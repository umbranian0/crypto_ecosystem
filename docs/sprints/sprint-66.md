## Independent verification (code read, not taken from the follow-up notes)

1. **Seeding delay is real, and the cause is a permission boundary, not just a schedule.** `dashboard-web/src/app/routers/demo.py` `POST /demo-run` calls `GET /ingestion/datasets` and shows "Sample data is not loaded for this tenant. Ask your operator to seed it." if `binance_price_btcusdt_1h` is absent. `list_datasets` reads three plain materialized views (`ingestion` migration `0007`) refreshed by a TimescaleDB `add_job` procedure every 5 minutes. Those views are created by the migration role `naive_first`; the runtime role `naive_first_app` only has `SELECT` (`0007` grants nothing else). `REFRESH MATERIALIZED VIEW` requires ownership, so refresh-on-seed would need a new migration (a SECURITY DEFINER wrapper or ownership change), a new call from `POST /internal/seed-platform-history`, and it would recompute the views for every tenant on every tenant creation (there are ~2,283 test-suite tenants; the suites create tenants constantly).
2. **Seed failure is silent on the ingestion side.** `ingestion-service/src/app/routers/internal.py` catches every exception and returns a fixed 503 with no log line at all. `_load_platform_csvs` raises `FileNotFoundError("no CSV files found under <dir>/(seed|incremental)")`, which that handler swallows. Gateway `provisioning.py` logs one warning ("tenant platform-history seed failed", `event_type=tenant_seed_degraded`) with no cause. `.gitignore` excludes `services/ingestion-service/data/raw/**/*.csv`, so on a fresh checkout `PROVENANCE.md` exists but no CSVs do. `infra/README.md` says only "A checkout without the host archive still seeds empty." The ONB-001 copy in `dashboard-web/.../setup_key_reveal.html` line 13 ("New tenants are loaded with sample data automatically") is therefore false on such a checkout, with no operator-visible reason.
3. **PDF stylesheet:** `reporting-service/src/app/renderers/pdf.py` `_PDF_CSS` has `@page` landscape, table, th/td rules and nothing about row breaking.
4. **Trend request:** `reporting-service/src/app/routers/report_generation.py` `GenerateReportRequest.horizon` is a bare `int | None`, with no lower bound. `RunRequest.horizon` in `libs/common` is `Field(ge=1)`. The gateway `GenerateReportRequest` is types-only and forwards downstream, and its docstring states the downstream 422 passes through `_raise_for_error`, so one change at reporting-service is enough.
5. **Scratch files:** `infra/docker-compose.yml` `reporting-service` has no `volumes:` or `tmpfs:` entry, so `/tmp` lives in the container's writable layer.
6. **Test-DB audit, static pass (done while planning, read-only).** Every Postgres-touching test module found defaults to `.../5432/naive_first_test` with an env override: `reporting-service` `test_postgres_repository.py`; `validation-service` `test_postgres_repository.py`, `test_chunk_interval_migration.py`, `test_index_migration.py`, `test_hypertable_migration.py`, `test_split_results_index_migration.py`; `ingestion-service` `test_crawl_runs_index_migration.py`, `test_hypertable_chunk_interval_migration.py`, `test_hypertable_tenant_source_fetched_at_index_migration.py`, `test_dataset_list_continuous_aggregates_migration.py`; `gateway-api` `test_postgres_repository.py`, `test_migrations.py`. No remaining default to `naive_first` was found by grep. `libs/common` and `libs/naive_first_engine` tests open no engine or connection (`test_db.py` uses a fake builder). `dashboard-web` has no DB access at all (its only DB-looking string is a fake secret in `test_settings_environment.py`). `economic-service` tests use a fake engine. Residual hazards for the Tech Lead to confirm (not asserted as bugs): (a) tests that run `alembic` or build apps with `**os.environ` but not an explicit `DATABASE_URL` (`validation-service/tests/test_models.py` overrides to sqlite; confirm the same for `gateway-api`/`economic-service` `test_models.py`) fall through to whatever `DATABASE_URL` the invoking shell exports, so a shell with the live URL exported is a hazard; (b) `dashboard-web/tests/e2e/conftest.py` spawns uvicorn with `**os.environ`, harmless only because dashboard-web has no DB. **The live row-count check could not be run by the planner (no shell/Docker access); it must be run by the Tech Lead/QA.**
7. **RPT-005 sizing inputs.** There is no list route in reporting-service (new repository method, RLS-covered query, route, pagination bound) or gateway (proxy); dashboard-web has no report page (three views, templates, tenant-session handling, tests). RPT-005 also depends on RPT-004's diff route, which exists API-only.

## Decisions made in this plan

- **Item 1: honest wording, not refresh-on-seed.** Why: wording is a string change in one file plus its test and README line; refresh-on-seed needs a migration for privileges, a new write path in the internal endpoint, and a full-view recompute per tenant creation, to remove a delay of at most about 5 minutes that also self-resolves. The new copy must cover both cases (delay and genuine seed failure) without claiming either: for example "Sample data for your tenant may still be loading (it can take up to about 5 minutes after tenant creation). Try again shortly; if it still does not appear, ask your operator." The existing ONB-001 sentence gets the same softening ("...loaded automatically; it can take a few minutes to appear"). Disclosed trade-off: the delay itself remains; only the false impression is removed.
- **Item 2: log at the point of failure plus documentation; no CSVs committed.** Why: the failure is detected in one place that currently discards it. In `routers/internal.py`, log a `FileNotFoundError` separately at ERROR with the missing directory path and a pointer to `data/raw/_platform/PROVENANCE.md` (the path is a repo path, not a credential; the HTTP body stays the fixed generic 503, preserving the no-leak test). Other exceptions get a log line with the exception class name only, no message (the existing test forbids connection strings reaching the body, and logs should not carry them either). README statement in `services/ingestion-service/README.md` and `infra/README.md` (replacing "still seeds empty"): the archive is untracked by design, what is missing (`data/raw/_platform/{price,onchain,sentiment}/.../{seed,incremental}/*.csv`, ~103 MB), that `PROVENANCE.md` documents sources and how it was produced, and that without it new tenants get no sample data and `/demo-run` shows the empty-data message. A separate startup warning is not added (YAGNI: one more code path for a condition the seed-time log already surfaces where it matters). If the Tech Lead finds the PROVENANCE.md does not say how to obtain the archive, add that one paragraph; do not invent a download source.
