# RAV-014 — Per-run compact error sparkline on the runs list

**Status: todo.**

**Module**: `services/dashboard-web` only.
**Story**: `RAV-014`, `docs/product/backlog-run-analysis-visualization.md` Epic D.
**Depends on**: `RAV-012` (needs its per-run split data). No dependency on `RAV-013`, but sequenced
after it per sprint-60.md's own file-overlap guidance (both edit `runs_list.html`'s row markup and
`runs_list`'s function region — landing as two back-to-back, non-overlapping-in-time edits rather than
parallel dispatch avoids a same-file collision).
**Sprint**: 60 (`docs/sprints/sprint-60.md`). Sequenced **fourth**, immediately after RAV-013.

## Analysis

Each row on `runs_list.html` should show a small sparkline of model-vs-Naive0 MAE across that run's
splits, so a tenant sees the shape/stability of a run's error at a glance — the same metric `RAV-002`'s
full-size `_error_chart.html` already shows on `run_detail.html`, at run-list scale. This is a compact
re-rendering of already-charted data, **not** a new chart type or new computed statistic (binding scope
limit, per the backlog's Epic D framing and CLAUDE.md).

## Design

**Design pattern**: none new — server-rendered SVG geometry, same as every other `charting.py` chart
function.

**Files touched** (scoped to `dashboard-web`):
- `services/dashboard-web/src/app/charting.py` — one small DRY refactor + one new function/dataclass.
- `services/dashboard-web/src/app/routers/runs.py` — `runs_list` computes the sparkline per run.
- `services/dashboard-web/src/app/templates/runs_list.html` — new column, new inline `<svg>` per row
  (or a new partial `_run_sparkline.html`, dev's call, matching this file's existing
  one-partial-per-chart convention if a partial is added).
- `services/dashboard-web/src/app/static/style.css` — reuse `--color-accent`/`--color-accent-2` only.

**DRY check note (mandatory, grepped `charting.py` before writing this design)**: `build_error_chart`
(line 253) is the only existing MAE-series computation. Its per-split value-gathering
(`getattr(split, model_attr)`/`getattr(split, naive0_attr)`) is currently inlined twice inside that
function (once for the `max_value` scan, once in the per-split loop) — **extract a small shared helper
both `build_error_chart` and the new sparkline function call, so the new function does not hand-roll a
third copy of "read model/naive0 values off a split for a metric key":**

```python
def _model_naive0_pairs(
    splits: list[SplitResultResponse], metric: str = DEFAULT_METRIC
) -> list[tuple[float, float]]:
    """Shared value-gathering step for build_error_chart and
    build_error_sparkline (RAV-014) -- returns (model_value, naive0_value)
    per split for the given metric key, resolved via METRIC_REGISTRY the
    same way both callers already do. Extracted here (implementation-plan.md
    section 9's "extract on second duplication" rule) so there is exactly
    one place a split's model/naive0 values for a metric are read off."""
    _, model_attr, naive0_attr = METRIC_REGISTRY.get(metric, METRIC_REGISTRY[DEFAULT_METRIC])
    return [(getattr(s, model_attr), getattr(s, naive0_attr)) for s in splits]
```

Refactor `build_error_chart` to call `_model_naive0_pairs(splits, metric)` for both its `values` scan and
its per-split loop (behavior must stay byte-identical — this is a pure refactor, prove it with the
existing `build_error_chart` tests still passing unmodified). Then add:

```python
_SPARKLINE_WIDTH = 96
_SPARKLINE_HEIGHT = 28
_SPARKLINE_BAR_GAP = 1
_SPARKLINE_GROUP_GAP = 2
_SPARKLINE_MIN_BAR_WIDTH = 0.5


@dataclass(frozen=True)
class SparklineChartData:
    """RAV-014: compact re-rendering of build_error_chart's own MAE pair,
    reusing the exact same Bar/SplitBars geometry dataclasses (no second
    bar-geometry shape) at table-cell scale. has_data=False for a run with
    fewer than 2 splits (insufficient to draw a meaningful shape) -- the
    caller must render an explicit placeholder, never a broken/misleadingly
    flat SVG."""

    width: int
    height: int
    has_data: bool
    splits: list[SplitBars] = ()


def build_error_sparkline(splits: list[SplitResultResponse]) -> SparklineChartData:
    """RAV-014: MAE-only (matching build_error_chart's own RAV-002 default),
    no metric selector at this scale (binding AC -- no interactivity/second
    metric at sparkline scale). Reuses _model_naive0_pairs (above) for the
    same value-gathering build_error_chart uses -- no second hand-rolled
    MAE-series computation."""
    if len(splits) < 2:
        return SparklineChartData(width=_SPARKLINE_WIDTH, height=_SPARKLINE_HEIGHT, has_data=False)

    pairs = _model_naive0_pairs(splits, metric="mae")
    max_value = max((v for pair in pairs for v in pair), default=0.0)
    if max_value <= 0:
        max_value = 1.0

    plot_width = _SPARKLINE_WIDTH
    plot_height = _SPARKLINE_HEIGHT
    group_width = plot_width / len(pairs)
    bar_width = max((group_width - _SPARKLINE_BAR_GAP) / 2, _SPARKLINE_MIN_BAR_WIDTH)

    split_bars: list[SplitBars] = []
    for i, (split, (model_value, naive0_value)) in enumerate(zip(splits, pairs)):
        group_x = i * group_width
        model_height = (model_value / max_value) * plot_height
        naive0_height = (naive0_value / max_value) * plot_height
        split_bars.append(
            SplitBars(
                split_index=split.split_index,
                model=Bar(x=group_x, y=plot_height - model_height, width=bar_width,
                          height=model_height, value=model_value),
                naive0=Bar(x=group_x + bar_width + _SPARKLINE_BAR_GAP,
                           y=plot_height - naive0_height, width=bar_width,
                           height=naive0_height, value=naive0_value),
                label_x=group_x + group_width / 2,
            )
        )

    return SparklineChartData(
        width=_SPARKLINE_WIDTH, height=_SPARKLINE_HEIGHT, has_data=True, splits=split_bars
    )
```

(Exact constant values/layout math above are a reference implementation, not gospel — the dev may adjust
padding/gap numbers for visual correctness, but must keep: table-cell-sized fixed dimensions distinct
from `_CHART_WIDTH`/`_CHART_HEIGHT` (RAV-002's full-size chart), reuse of `Bar`/`SplitBars`, reuse of
`_model_naive0_pairs`, and the `< 2` splits placeholder threshold.)

**Route wiring** (`runs_list`, `routers/runs.py`): parallel to `RAV-013`'s dict, e.g.
```python
run_sparklines = {
    run.id: build_error_sparkline(run_splits_summary.get(run.id, []))
    for run in runs
}
```
passed into the template context alongside `run_verdict_indicators` (both independent, per Design note
in `RAV-013`'s ticket).

**Template**: two-series palette only — `--color-accent` (model) / `--color-accent-2` (naive0), matching
`_error_chart.html`'s existing `.bar-model`/`.bar-naive0` classes (reuse those class names/CSS rules,
do not invent new color variables). A zero/one-split run (`has_data=False`) renders a plain placeholder
(e.g. `<span class="sparkline-placeholder">Not enough splits yet</span>`), never a broken/flat `<svg>`.
