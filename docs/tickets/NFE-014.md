Order is fixed and not reorderable by any parameter.

## Deviation note (not in original ticket scope, required to make it work)
While implementing, computing the full `MetricSet` for Naive0's own prediction (mandatory per solution-design.md section 1 principle 1) hit a pre-existing `ZeroDivisionError` in `metrics.f1_directional`: Naive0 forecasts exactly `0.0` for every point, so `pred_up` (`y_pred > 0`) is all-`False` on every call, making precision's denominator `0` unconditionally — not a fluke of test data, this reproduces on any real series. Fixed `f1_directional` (NFE-008/009/010 module, outside this ticket's nominal scope) to define precision/recall as `0.0` when their denominator is `0`, matching the standard "undefined precision/recall" convention (equivalent to sklearn's `zero_division=0`). Added a regression test (`test_f1_directional_is_zero_not_a_zero_division_error_when_pred_never_predicts_up`) to `tests/test_metrics.py`. This was necessary, not optional: without it, `run_validation_protocol` cannot compute Naive0's metrics on any input, which would make the mandatory-Naive0 acceptance criterion unsatisfiable.
