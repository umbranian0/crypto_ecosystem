## Analysis
Story: GW-007 (Must), depends on GW-006. ## Design
Pattern: **Dependency Injection**, reusing GW-006's `get_authenticated_tenant` dependency (already resolves once per request per FastAPI's own `Depends()` caching-within-a-request behavior — no new resolution step needed, this ticket's job is the *forwarding* half, not re-resolution). File: `src/app/dependencies/routing.py` (new) — a small helper, `build_downstream_headers(tenant: TenantContext) -> dict[str, str]`, returning `{"X-Tenant-Id": tenant.tenant_id}` and nothing else derived from the inbound request's own headers (the inbound request may carry its own `X-Tenant-Id` from a malicious/confused caller — that value is never read, never forwarded; the *only* source of the outbound header's value is GW-006's verified `tenant.tenant_id`).

This ticket does not yet issue any actual HTTP call (that's GW-008) — it defines the header-building seam GW-008 will call, and (per AC) states the interim-forwarding design note in the README. Keeping the header-building logic as its own named function (not inlined into GW-008's proxy code) is itself the DRY point: GW-009 later wraps GW-008's calls, and every one of them must build headers the same way — a single function makes "never read the inbound header" true by construction, not by convention repeated at every call site.

**Hard constraint, checked explicitly before this ticket is marked done**: `git diff`/file-scope check confirms this ticket's diff touches only files under `services/gateway-api/` — zero lines changed in `libs/common/src/naive_first_common/tenant_context.py` or any `services/validation-service/*` file.
