downstream-failure-to-status-code handling for each proxied `/health` call — no new transport-error

## Implementation acceptance criteria
- [ ] `GET /system/health` (no tenant auth required — health status is not tenant data) calls its own
  health check plus `validation-service`'s, `reporting-service`'s, and `ingestion-service`'s `/health`
  endpoints, returns `{"gateway-api": "ok", "validation-service": "ok"|"degraded"|"unreachable", ...}`
  one key per service.
- [ ] A downstream timeout/connection failure maps to `"unreachable"` for that service only — one
  unreachable service does not fail the whole aggregate call.

## Test acceptance criteria
