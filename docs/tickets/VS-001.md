## Environment note (applies to every ticket in this sprint, same as Sprint 01/02)
`uv sync` / plain `uv run pytest` intermittently fail to write new files (`uv.lock`, fresh `.venv` contents) in this sandboxed Windows environment (OneDrive file-creation race, not a code defect). Workaround, used throughout this sprint: `.venv` created via `python -m venv .venv`, dependencies installed via `.venv\Scripts\python.exe -m pip install -e . -e ..\..\libs\naive_first_engine pytest httpx`, tests run via `.venv\Scripts\python.exe -m pytest`. Every dev agent in this sprint is instructed to use this workaround and to actually run it, not assume it. `services/validation-service/.venv` already exists after this ticket — dev agents should reuse it (`pip install` any new deps into it) rather than recreating it, unless it's missing.
