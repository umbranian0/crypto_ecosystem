## Outcome

The dev agent's session ended before it updated this ticket file's Status/Outcome/checkboxes, but
the shipped code was already complete and correct on disk. The Tech Lead verified directly.

**Files created**: `scripts/check_doc_sync.py` (mirrors validation-service's VS-016 precedent --
imports the real, live `app.main.app` and introspects `app.routes`, not AST-parsing) and
`tests/test_doc_sync.py` (4 tests). One real, non-trivial implementation detail the dev agent
correctly handled, beyond VS-016's simpler precedent: this service's two routers
(`report_generation`/`report_retrieval`) are both mounted with `app.include_router(router,
prefix="/reports")`, and on the FastAPI/Starlette version installed here, an included sub-router
shows up on `app.routes` as an opaque placeholder object (exposing `original_router` +
`include_context.prefix`, not its own flattened `path`/`methods`) rather than each leaf route being
eagerly flattened with its full mounted path at include time. `check_doc_sync.py`'s
`_flatten_routes` recurses through this structure, accumulating the prefix, so the real
request-matched path (`/reports/{report_id}`, not just `/{report_id}`) is what gets compared against
the README -- verified this is correct by reading the function directly and by the drift-detection
demonstration below (the injected drift correctly identified the fully-prefixed path, not a
truncated one).

**README's `## Routes` section** (already present, confirmed matching the live app exactly):

