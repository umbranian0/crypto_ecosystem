# UAT-004 — Fixed-precision rounding for displayed metric values

**Module**: `services/dashboard-web`. **Depends on**: UAT-003 (file-ordering on `run_detail.html`/
`app/charting.py` only, no logical dependency).

## Analysis
Story: `docs/product/backlog-uat-findings.md` UAT-004. One shared Jinja2 filter/macro, not per-template
ad hoc formatting — extract-on-second-duplication (implementation-plan.md section 9). API response
values (`SplitResultResponse`/`RunDetailResponse`) stay full precision; display-only.

## Design
Pattern: none new.
Files touched:
- `app/main.py` (or wherever Jinja2 env/filters are registered) — new `round4` (or similarly named)
  Jinja2 filter, `round(value, 4)` guarding `None`.
- `run_detail.html`'s per-split table, `_error_chart.html`/`_dm_verdict_chart.html` (tooltips/labels if
  raw numbers rendered), `_forecast_horizon_summary_panel.html` — all route numeric values through the
  new filter.
- `app/charting.py`'s `build_shareable_summary_text` (FHS-004 export) — uses the same rounding (call the
  same underlying Python function the Jinja2 filter wraps, not a duplicate `round(x, 4)` literal).
**DRY check note**: grep `round(` and any ad hoc `"{:.4f}"`-style formatting across
`services/dashboard-web/src/app/templates/*.html` and `app/charting.py` before writing — if any template
already inline-formats, replace it with the new shared filter rather than leaving both.
