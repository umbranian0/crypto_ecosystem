## Analysis

Covers RAV-002's full acceptance criteria (backlog file, "Epic A" section): a chart comparing
`model_mae`/`naive0_mae` across a run's splits, using data `run_detail`'s handler
(`services/dashboard-web/src/app/routers/runs.py`) already fetches via `GET /runs/{id}/splits` — no
new backend call. Constrained by: CLAUDE.md's positioning rule (no forecast/prediction/signal/
recommendation language — `run_detail.html`'s existing docstring vocabulary is "validation results"/
"benchmark comparison"/"per-split metrics," reuse that, don't invent new words), `style.css`'s
documented no-green/red-bull/bear-pairing constraint, and the mandatory-naive-baseline rule (every
model metric shown must have Naive0 shown alongside it, matching `naive_first_engine`'s own rule).

## Design

**Pattern**: none of Strategy/Repository/Adapter/Factory/Observer from implementation-plan.md
section 7 applies to a read-only rendering addition — this is plain server-side templating, same as
every other `dashboard-web` route (Dependency Injection is already in place via
`DownstreamHeadersDep`/`GatewayApiUrlDep`, untouched by this ticket).

**Files touched** (scoped to `services/dashboard-web` only):
- `services/dashboard-web/src/app/charting.py` (new, per RAV-001's decision) — a pure function,
  e.g. `build_error_chart(splits: list[SplitResultResponse]) -> ErrorChartData`, that takes the
  already-parsed split list and returns a small dataclass/dict of pre-computed SVG geometry (bar
  x/y/width/height per split per series, axis tick positions/labels) — no I/O, no Jinja2 import, so
  it is unit-testable in isolation from the HTTP layer.
- `services/dashboard-web/src/app/templates/_error_chart.html` (new partial, `{% include %}`-ed
  from `run_detail.html`, mirroring the existing `_dataset_macros.html`/`_crawl_status_panel.html`
  shared-partial precedent already in this codebase) — renders the inline `<svg>` from
  `build_error_chart`'s output. MAE only for this ticket (the backlog's own RAV-004, out of scope
  this sprint, is what adds a metric selector for the other six pairs — do not build a toggle here).
- `services/dashboard-web/src/app/routers/runs.py` — `run_detail`'s existing handler passes the
  already-fetched `splits` through `build_error_chart` (or the template partial calls it directly
  via a Jinja2 global/filter — dev's call, whichever keeps `runs.py` from growing chart-specific
  logic beyond one function call) and hands the result to `run_detail.html`.
- `services/dashboard-web/src/app/templates/run_detail.html` — one new `{% include
  "_error_chart.html" %}` block, placed above the existing per-split table (which stays unchanged).
- `services/dashboard-web/src/app/static/style.css` — reuse `--color-accent` (model series) and
  `--color-accent-2` (naive0 series), the same pairing the backlog itself names as compliant; add
  only the minimal new CSS needed for the SVG container/legend, no new color variables.

**DRY check** (performed before writing code, restated here for the dev agent to verify against the
actual current file state, since these files may have shifted since this ticket was written): grep
`services/dashboard-web/src` for `<svg`, `chart`, `bar_chart` — expect zero hits before RAV-001's

parallel zero-splits check.

## Implementation acceptance criteria (carried over from the backlog story)

- `run_detail.html` renders one chart (per RAV-001's server-rendered-SVG decision) with split index
  on one axis and MAE on the other, plotting `model_mae` and `naive0_mae` as two visually distinct
  series over the same splits already fetched by `run_detail`'s existing `GET /runs/{id}/splits`
  call — no new backend call, no new field.
- The two series use `--color-accent`/`--color-accent-2` (or documented equivalents) — never a
  green/red or up/down color pairing.
- The existing per-split table remains on the page, unchanged, below the new chart.
- Chart title/axis labels/surrounding copy read as "model vs. Naive0 error by split" or equivalent
  audit language — reviewed against `run_detail.html`'s existing docstring vocabulary ("validation
  results"/"benchmark comparison"/"per-split metrics"); no word implying a forecast, a prediction
  the platform is making, or a trading recommendation.
- A run with zero splits renders the existing "No per-split validation results yet" message — no
  empty/broken chart shown (the new `{% include %}` must be inside the existing `{% if splits %}`
  branch, not before it).

  `model_mae`/`naive0_mae` values (e.g. relative bar heights match relative MAE values).
- Route-level test (same `httpx.MockTransport` convention as `tests/test_runs_detail.py`) asserting:
