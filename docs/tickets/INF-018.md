## Analysis
Story: INF-018 (Must, `docs/product/backlog-infra.md`), depends on INF-001 (postgres), INF-002 (redis), INF-014 (non-superuser app role pattern to replicate), `reporting-service`'s RS-001 (Dockerfile precedent, already exists — `services/reporting-service/Dockerfile` was read directly, see Design below) and RS-002 (schema/RLS, for the runtime-role AC to be meaningful — done per `docs/tickets/README.md`). Constraining acceptance criteria, read directly from the backlog entry:
- `services/reporting-service/Dockerfile` — **already exists** (confirmed by reading it directly, 2026-08-14 session): non-root (`appuser`), `uv sync --frozen --no-dev`, `EXPOSE 8002`, `additional_contexts: {libs: ...}` pattern already anticipated in its own comments. This ticket's job is Compose wiring around an existing Dockerfile, not authoring a new one — if the Dockerfile needs any correction to match INF-003/INF-004's precedent exactly, that's this ticket's scope, but the file itself is not greenfield.
- `infra/docker-compose.yml` gains a `reporting-service` entry (`build: ../services/reporting-service`), `depends_on: postgres: condition: service_healthy` AND `depends_on: redis: condition: service_healthy` (unlike `validation-service`, which does NOT depend_on redis since VS-014 wasn't live at INF-003's time — `reporting-service` DOES need redis at startup readiness for RS-006's future subscriber, per this ticket's own AC).
- `DATABASE_URL`, `REDIS_URL`, `VALIDATION_SERVICE_URL` env vars via internal Compose hostnames (`postgres:5432`, `redis:6379`, `http://validation-service:8000`), documented in `infra/.env.example` alongside existing entries, Compose-network vs. local-dev distinction preserved (same pattern INF-007 established).
- `DATABASE_URL` MUST use the existing non-superuser `naive_first_app` role (INF-014) — do not reintroduce the superuser-bypasses-RLS gap. Same `${POSTGRES_APP_USER:-naive_first_app}:${POSTGRES_APP_PASSWORD:-naive_first_app_dev_password}@postgres:5432/${POSTGRES_DB:-naive_first}` pattern `validation-service`/`gateway-api` already use in `docker-compose.yml`.
- `docker compose up reporting-service` starts successfully; `POST /reports/generate`/`GET /reports/{id}` respond over the container's exposed port — this story does NOT require RS-001–RS-006 to all be done first, only that the container builds/runs/is reachable once that code exists (it already does — RS-004/RS-005 are done).
- **No change to any file under `services/reporting-service/src/`** — packaging/wiring only. Any diff touching that path is out of scope and must be rejected in review.
- `infra/README.md` updated: remove `reporting-service` from the "still not wired into compose" list (INF-007's prior statement), state this was closed as `RS-GAP`'s infra half, cross-reference `GW-018` as the other half needed for actual reachability from outside the Docker network.

## Design
Pattern: none new — this is Compose/Dockerfile wiring, mirroring the existing `INF-003`/`INF-004` precedent exactly (same `additional_contexts: {libs: ...}` shape, same non-root/healthcheck/env-var-driven conventions). Files touched, all outside any service's `src/`:
- `services/reporting-service/Dockerfile` — verify against INF-003/INF-004's exact precedent (non-root `appuser`, `EXPOSE` matching the port this ticket assigns in Compose, `additional_contexts` shape) — confirmed already close to this shape by direct read; only correct if something doesn't match (e.g. if the existing `EXPOSE 8002` should instead map differently, document the choice in `infra/README.md`).
- `infra/docker-compose.yml` — add the `reporting-service` service block, following `validation-service`'s/`gateway-api`'s block structure and comment style exactly (same `restart: unless-stopped`, same `127.0.0.1:`-bound host port precedent per the "gateway-api is the only internet-facing service" boundary already documented above `validation-service`'s port binding).
- `infra/.env.example` — add `REPORTING_SERVICE_PORT`, `REPORTING_SERVICE_DATABASE_URL`, `REPORTING_SERVICE_REDIS_URL`, `REPORTING_SERVICE_VALIDATION_SERVICE_URL` (naming mirrors the existing `VALIDATION_SERVICE_*`/`GATEWAY_API_*` prefix convention), each with the Compose-network vs. local-dev distinction comment block already established for the other two services.
- `infra/README.md` — new `## reporting-service (INF-018)` section mirroring the `## validation-service (INF-003)`/`## gateway-api (INF-004)` sections' structure and depth (start command, env var table, verify curl, a smoke-test paragraph); remove `reporting-service` from the "Not yet wired into compose" paragraph at the top of the file; cross-reference `GW-018` as the reachability half.

DRY check (performed before writing this ticket): grepped `infra/docker-compose.yml` — `validation-service`/`gateway-api` blocks are the direct template to copy the shape of, not reinvent; grepped `services/reporting-service/` — `Dockerfile` already exists (read above), so this is not a greenfield Dockerfile-authoring ticket, it is a "wire the existing Dockerfile into Compose" ticket, same distinction INF-003's own AC drew for `validation-service`.
