## Analysis
Story: NFE-018 (Could), depends on NFE-014 (done, Sprint 01 — Template Method orchestration, the last module before the public surface was considered stable). Serves implementation-plan.md section 8's documentation-for-scaling convention: "for libs, the public function signatures in the README stay in sync with the code — CI should fail if they drift (add a doc-check step once the first lib ships)." The first lib (this one) has now shipped (Sprint 01), so this follow-up is due.

Scope per the backlog: compare public (non-underscore-prefixed) top-level functions/classes in `splitting.py`, `baselines.py`, `metrics.py`, `dm_test.py`, `report_schema.py` against a function-signature list maintained in the README. Note: the module list in the backlog's own acceptance criteria (written during Sprint 01 planning) predates `protocol.py` (NFE-014 added it as a sixth file, per the README's own file-layout table: "sixth file, added beyond implementation-plan.md section 3's original five-file list"). `protocol.py`'s `run_validation_protocol` is the library's actual public entry point and is unambiguously part of the public API — excluding it from a "does the README match the code" check would leave the single most important public function unchecked. The dev agent must include `protocol.py` in the check's module list alongside the five named in the backlog; this is a correction to keep the ticket internally consistent with what NFE-014 actually shipped, not scope creep.

## Design
No new pattern — a comparison/verification script, matching NFE-017's shape (a script, not library logic). New file: `libs/naive_first_engine/scripts/check_doc_sync.py` (Python, not shell — needs to introspect Python modules via `inspect`, so a `.py` script is the natural choice here, unlike NFE-017 where either was viable). This ticket must not touch `src/*.py`'s actual logic — only doc-string/signature-adjacent content if needed, and the README's own content.

The check:
1. For each of `splitting.py`, `baselines.py`, `metrics.py`, `dm_test.py`, `report_schema.py`, `protocol.py`: use `inspect`/`ast` to enumerate top-level functions and classes whose name does not start with `_`.
2. Maintain a corresponding list in `README.md` (extend the existing file-layout section, or add a new "Public API" section — dev agent's call, document which and why) with one line per public function/class and its signature (name + params, matching implementation-plan.md section 8's "plain function signature list for libs").
3. The script parses both sides and fails (non-zero exit, clear diff-style message: "in code but not README" / "in README but not code") on any divergence.

DRY check: grep `libs/naive_first_engine` for any existing introspection/doc-generation logic before writing (none is expected — `scripts/` doesn't exist yet, or if NFE-017 has landed first, `scripts/check_standalone.*` will exist as a sibling but does something unrelated) — do not duplicate NFE-017's venv-management logic; this script has nothing to do with environments, only with static code/README comparison, and should not import or shell out to NFE-017's script.

**Self-verification demonstration (the acceptance-critical part, explicit in the backlog's own acceptance criteria)**: after building the check and confirming it passes against the current, accurate README, the dev agent must:
1. Temporarily add one undocumented public function (or class) to one of the six modules.
2. Run the check, capture and report the failure output (proves the check actually detects drift, not just that the check "exists" and trivially passes).
3. Remove the temporary function.
4. Run the check again, capture and report the pass.
Neither the temporary function nor any leftover trace of it may remain in the final diff — this is a demonstration step, not a permanent addition to the codebase.
