## Analysis
RPT-002 requires exactly one implementation of the consistency rule; it currently lives only in `services/dashboard-web/src/app/charting.py` (`UNDEFINED_VERDICT_CATEGORY` ~line 534, `_verdict_category` ~591, `ConsistencyIndicator`/`_run_beats_naive0`/`compute_consistency_indicator` ~925-995). reporting-service cannot import another service, so the pure rule moves to the shared lib. ## Design
- New `libs/common/src/naive_first_common/consistency.py` with public `UNDEFINED_VERDICT_CATEGORY` (constant), `verdict_category(split)`, `run_beats_naive0(splits)`, `ConsistencyIndicator` (frozen dataclass: beat_count,total_count,has_data), `compute_consistency_indicator(runs)` -- bodies/docstrings moved verbatim (documented majority rule, undefined splits excluded, has_data False when nothing evaluable). Depends only on `naive_first_common.contracts.SplitResultResponse`.
- `charting.py`: delete the moved definitions and import them from the lib; keep the existing private names importable (`_verdict_category = verdict_category`, `_run_beats_naive0 = run_beats_naive0`) so every other charting.py use and test_charting.py stay UNCHANGED. `UNDEFINED_VERDICT_CATEGORY` stays importable from `app.charting`. `charting.py` still uses `_verdict_category` in many places (lines ~643-1041): do not rewrite those call sites.
- DRY check: grep dashboard-web for any other copy of the rule; there must be exactly one afterward.
- Pattern: none (pure-function extraction on second use, per DRY rule).
