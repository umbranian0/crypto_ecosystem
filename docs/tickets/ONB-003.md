# ONB-003 -- Fix GW-030 auto-seed on the local stack: mount the platform CSV archive into ingestion-service

**Status: done (QA GO 2026-10-02, live stack re-run).** Sprint 62. Module: `infra` (docker-compose only; README notes in ingestion-service).
(Id reused locally; the backlog's own ONB-003 is a Won't duplicate of RPT-003 -- this is an infra bug ticket, not that story.)

## Analysis
QA found that `POST /internal/seed-platform-history` returned 503 on the real stack: the ingestion-service
image workdir `/repo/services/ingestion-service` has no `data/raw/_platform` (CSVs are untracked, not baked in),
and `seed_platform_history.py` resolves `_PLATFORM_ROOT` there. So GW-030's auto-seed degraded for every new tenant.

## Design
One read-only bind mount on the `ingestion-service` compose service:
`../services/ingestion-service/data/raw/_platform:/repo/services/ingestion-service/data/raw/_platform:ro`.
No code change, no new service, no image change (DRY: reuses INGEST-030/GW-030 as-is).

## Implementation / Test
Done: `docker compose config -q` valid; container recreated; `ls` inside the container shows
`PROVENANCE.md onchain price sentiment`. Behavioral check (brand-new tenant ends up with sample data) is QA's re-run.

## Review
Single `:ro` mount only; no existing tenant data or audit rows touched.

## Documentation
`infra/README.md` and `services/ingestion-service/README.md` updated with the mount note. Known limitation:
requires the host archive to exist (untracked CSVs); a fresh clone without them still seeds empty (200, zero rows).
