# UAT-008 — Optional run label at submission time

**Module**: `libs/common`, `services/gateway-api`, `services/dashboard-web`. **Depends on**: UAT-007
(file-ordering on `RunRequest` — must land after UAT-007's typing change, not concurrently). Touches
`run_detail.html`, sequenced after Track B (UAT-003/004/013 finish editing that file).

## Analysis
Story: `docs/product/backlog-uat-findings.md` UAT-008. **Tech Lead design call**: ships as a new optional
`RunRequest.label: str | None` field (max length 200), not a `PATCH`-rename endpoint — simplest,
matches the story's own primary acceptance criterion literally ("attach an optional, freeform label to a
run when I submit it"), and a rename-after-creation endpoint would be new surface not asked for by any
UAT finding. `gateway-api`'s local `RunRequest` mirror and `validation-service`'s real model must be
updated together (README-documented version-sync convention) — this ticket spans `libs/common` (shared
contract) + `services/gateway-api` (its own copy + pass-through) + `services/dashboard-web` (form/render).
Kept as one ticket since it's one field threaded through one existing pass-through path, not independent
work per module.

## Design
Pattern: none new. Files touched:
- `libs/common/src/naive_first_common/contracts.py` — `RunRequest.label: str | None = Field(default=None, max_length=200)`;
  `RunSummaryResponse`/`RunDetailResponse` gain `label: str | None` too (persisted, returned).
- `services/validation-service` — persist `label` on run creation (repository interfaces + sqlite/postgres
  impls), return it on `GET /runs`, `GET /runs/{id}`.
- `services/gateway-api`'s local `RunRequest`/response mirrors updated identically; pass-through only, no
  new logic.
- `services/dashboard-web/src/app/templates/run_new.html` — new optional "Label (optional)" text input.
- `services/dashboard-web/src/app/routers/runs.py` — `run_new_submit` includes `label` (if non-blank) in
  `RunRequest` construction.
- `runs_list.html`, `run_detail.html` — render label when present, id always visible too (e.g. subtitle).
**DRY check note**: grep `RunRequest(` construction sites in `dashboard-web`/`gateway-api` before editing
— exactly one construction site per service already established by UAT-007's typing work; extend, don't
duplicate.

## Outcome

Implemented as designed -- `RunRequest.label: str | None = Field(default=None, max_length=200)` in
`libs/common/src/naive_first_common/contracts.py`, plus a matching `label: str | None = None` on
`RunDetailResponse`/`RunSummaryResponse`. `validation-service` persists it on `runs.label` (nullable
`String`, `migrations/versions/0010_add_runs_label_column.py`), threaded through
`RunRecord`/`ValidationRunRepository.create_run` (both SQLite and Postgres implementations) the same
optional-keyword-argument way `warnings`/`feature_lineage` already were, and returned on `GET /runs`/
`GET /runs/{id}`. `gateway-api` required **zero code change** -- confirmed it already imports `RunRequest`/
`RunDetailResponse`/`RunSummaryResponse` directly from `naive_first_common.contracts` (since ARCH-003/
UAT-007) and forwards/reconstructs generically (`request.model_dump()`, `RunDetailResponse(**response.json())`),
so the new field round-trips automatically; added dedicated forwarding tests anyway per the ticket's Test
acceptance criteria. `dashboard-web`'s `run_new.html` gained an optional "Label (optional)" input right
after `dataset_id`; `run_new_submit`'s single `RunRequest(...)` construction site (DASH-006) was extended,
not duplicated, sending `label=None` for a blank/whitespace-only submission. `runs_list.html`/
`run_detail.html` render the label when present (id always still visible, unconditionally); a run with no
label renders byte-identical to before this ticket (no unconditional new row/text).
