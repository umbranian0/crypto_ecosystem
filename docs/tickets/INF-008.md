# INF-008 — MinIO service in Docker Compose

**Module**: `infra`. **Priority**: Should. **Depends on**: none. **Round**: 1 (parallel).
**Source**: `docs/product/backlog-infra.md` INF-008, `docs/product/backlog-hardening-wave-review.md` Category 1, `docs/sprints/sprint-17.md`.

**Status: done (2026-08-24).** Implemented and verified against the real running Docker stack (not just a config review) -- see "Live verification" note below.

## Analysis

Story: stand up a `minio` Compose service matching solution-design.md section 5's service table, ahead
of `ingestion-service` (trigger #6, unfired) actually needing it. Acceptance criteria (from the
backlog entry verbatim):
- `infra/docker-compose.yml` defines a `minio` service (`minio/minio` image) with a persistent volume
  and credentials via env vars, same pattern as INF-001/INF-002.
- `docker compose up minio` starts successfully and the MinIO console/API is reachable on its
  documented port.
- `infra/README.md` states plainly that no service currently reads or writes to it.

**Non-negotiable care condition (hardening-wave review)**: apply the same `127.0.0.1`-only host port
binding already used for `postgres`/`redis`/`validation-service`/`reporting-service` in
`infra/docker-compose.yml` — do not reopen the port-exposure gap the platform already closed
elsewhere. State plainly in `infra/README.md` that no service currently reads or writes to it yet
(`ingestion-service`, trigger #6, is the first real consumer and hasn't been built).

## Design

No design pattern from implementation-plan.md section 7 applies here — this is pure infra
scaffolding (a Compose service definition), not application code.

**Files touched** (scoped to `infra/` only):
- `infra/docker-compose.yml` — add a `minio` service.
- `infra/.env.example` — document the new env vars.
- `infra/README.md` — new `## MinIO (INF-008)` section.

**DRY check**: `infra/docker-compose.yml`'s existing `postgres`/`redis`/`validation-service`/
`reporting-service` entries are the exact pattern to copy: named volume for persistence, credentials
via `${VAR:-default}` env-var substitution (never hardcoded), `127.0.0.1:<port>:<container-port>`
host binding with a comment citing the same rationale, `container_name: naive-first-<service>`,
`restart: unless-stopped`, a `healthcheck`. MinIO's official image supports `MINIO_ROOT_USER`/
`MINIO_ROOT_PASSWORD` env vars and a healthcheck via `mc ready local` or `curl -f
http://localhost:9000/minio/health/live` — use the same `CMD-SHELL` healthcheck shape already used
for `postgres`. Do not invent a second host-port-binding comment style — copy the existing one
verbatim, only naming this service.

## Implementation acceptance criteria

- [x] `infra/docker-compose.yml` gains a `minio` service: image `minio/minio` (the official image;
  `command: server /data --console-address ":9001"` to expose both the S3 API (9000) and web console
  (9001)), env vars `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD` sourced from `${MINIO_ROOT_USER:-...}`/
  `${MINIO_ROOT_PASSWORD:-...}` (pick dev defaults consistent in style with `naive_first_dev_password`),
  a named volume (`minio-data:/data`, added to the top-level `volumes:` block), `container_name:
  naive-first-minio`, `restart: unless-stopped`.
- [x] Both ports bound `127.0.0.1` only, mirroring the exact comment style of the existing
  `postgres`/`redis` entries: `"127.0.0.1:${MINIO_API_PORT:-9000}:9000"` and
  `"127.0.0.1:${MINIO_CONSOLE_PORT:-9001}:9001"`.
- [x] A `healthcheck` is declared (e.g. `CMD-SHELL`, `curl -f http://localhost:9000/minio/health/live
  || exit 1`, matching the `interval`/`timeout`/`retries` shape already used for `postgres`/`redis`).
- [x] No bucket is created and no bucket/prefix policy is invented — the container starts empty. Do
  not add a `mc mb` init step or any bucket-creation script; that belongs to `ingestion-service`
  (trigger #6) when it exists.
- [x] `infra/.env.example` gains a `# --- minio service (INF-008) ---` section documenting
  `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `MINIO_API_PORT`, `MINIO_CONSOLE_PORT`, following the
  same Compose-network-vs-local-dev comment convention every other section already uses (MinIO has no
  other service consuming it yet, so there is no "local, non-Compose dev equivalent" to document
  beyond reaching the console directly on the host-published port).
