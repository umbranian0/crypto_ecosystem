## Outcome

Added a `reporting-service` job to `.github/workflows/ci.yml`, inserted right before the
`ingestion-service` job (same position reporting-service occupies in the module list elsewhere in the
repo), mirroring `gateway-api`'s/`validation-service`'s job shape exactly -- `uv sync` +
`uv run pytest -q --cov=app --cov-report=term-missing`, no `--cov-fail-under`/hard gate:

```yaml
  reporting-service:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: services/reporting-service
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v3
      - run: uv sync
      - run: uv run pytest -q --cov=app --cov-report=term-missing
```

**Postgres/Redis provisioning finding (deviation from the ticket-issuing prompt's assumption, not
from the ticket itself)**: the prompt suggested checking how the existing `ci.yml` provisions
Postgres/Redis for `validation-service`/`gateway-api` via `services:` containers and mirroring that.
Read `.github/workflows/ci.yml` in full first, per the ticket's own DRY-check note -- neither
`validation-service` nor `gateway-api` (both of which also have real Postgres-backed repositories and
RLS tests) has any `services:` block in their CI job; there is no Postgres/Redis provisioning
anywhere in the existing file. Their Postgres-backed tests (e.g.
`test_rls_blocks_cross_tenant_reads_at_the_database_level`) self-skip via
`pytest.mark.skipif(not _postgres_reachable(), ...)` when `localhost:5432` isn't reachable, which is
`reporting-service`'s own `tests/test_postgres_repository.py`'s stated pattern too (confirmed by
reading that file). So the new `reporting-service` job mirrors the *actual* existing pattern (no
provisioning, tests self-skip in CI) rather than inventing new `services:` container provisioning
that no sibling job actually has -- adding one now would have made this job's shape diverge from
every other module's, which is exactly what the ticket's DRY-check note says not to do.

Added to `services/reporting-service/README.md`, immediately after the `GET /health` paragraph (same
position/order every other module's README uses -- CI, then Coverage, then Dependency upgrades):

```
**CI**: `.github/workflows/ci.yml` runs this module's test suite on every push/PR.

**Coverage**: run tests with coverage locally via `uv run pytest -q --cov=app --cov-report=term-missing` (no coverage threshold is enforced — CI prints the report, it never fails the build on a percentage).

**Dependency upgrades**: see [../../docs/dependency-upgrade-policy.md](../../docs/dependency-upgrade-policy.md) for this platform's cadence.
```
