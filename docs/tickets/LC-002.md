## Design
Pattern: none named in implementation-plan.md section 7 for this specific piece — this is a plain typed value object, matching the README's "plain typed Python, no framework lock-in beyond Pydantic" contract. Files: `libs/common/src/naive_first_common/tenant_context.py` (new — `TenantContext` definition), `libs/common/src/naive_first_common/__init__.py` (edit — export `TenantContext`), `libs/common/tests/test_tenant_context.py` (new).
DRY check: grep `libs/common/src/naive_first_common/` (only `__init__.py` exists after LC-001, empty) — nothing to deduplicate.

**Type choice**: a Pydantic `BaseModel` (not a frozen dataclass) — the lib's own dependency is already Pydantic (LC-001), and Pydantic's validators give "fails closed at construction time" for free (a `field_validator` that rejects empty/whitespace-only `tenant_id`, raising `pydantic.ValidationError` on construction) without hand-rolling `__post_init__` checks a dataclass would need. Set `model_config = ConfigDict(frozen=True)` so instances are immutable, matching "value object" semantics.

**Field**: `tenant_id: str`, non-empty and non-whitespace-only after `.strip()` (a `field_validator("tenant_id")` that strips and rejects if the result is empty — mirrors LC-004's later test for whitespace-only rejection, so define the rule here, not duplicated in LC-003/LC-004). No other fields — no `dataset_id`, no service-specific concept, per the story's explicit "shared-boundary-only" scope.
