## Analysis

Story: DBOPT-002 (`docs/product/backlog-db-optimization.md`). `PostgresValidationRunRepository.list_runs`
(`SELECT * FROM runs WHERE tenant_id = :tenant_id ORDER BY created_at DESC LIMIT :limit OFFSET
:offset`) and `.count_runs` (`SELECT count(*) FROM runs WHERE tenant_id = :tenant_id`) back `GET /runs`
(VS-022). `runs`' only index today is the PK on `id`; the RLS policy's `USING (tenant_id =
current_setting('app.tenant_id'))` clause and both of these `.where(Run.tenant_id == tenant_id)` calls
have no index to use.

Live-verified by the DBA: `EXPLAIN (ANALYZE, BUFFERS)` on the real 1,928-row table, scoped to a tenant
with 1 row, shows `Seq Scan on runs ... Filter: (tenant_id = ...) Rows Removed by Filter: 1927` for
both `list_runs` and `count_runs` — the textbook unindexed-RLS-filter-becomes-full-scan trap.

## Design

No design pattern from implementation-plan.md section 7 applies — pure schema/index change. The
Repository pattern (VS-003/VS-013/VS-022) is unaffected: `list_runs`/`count_runs`'s signatures, SQL
text, and ordering responsibility are unchanged; the index only changes the query plan.

## Implementation acceptance criteria

- New Alembic migration adds
  `CREATE INDEX ix_runs_tenant_id_created_at ON validation.runs (tenant_id, created_at DESC);` — the
  DBA's exact migration shape: composite, `tenant_id` leading (serves the RLS filter and `count_runs`
  alone), `created_at DESC` trailing (serves `list_runs`'s `ORDER BY ... DESC` for free, no separate
  sort step).
- Postgres-only-guarded (`op.get_bind().dialect.name != "postgresql"` early-return), matching
  `0002_add_row_level_security.py`/`0004_convert_split_results_to_hypertable.py`'s existing idiom, so
  this service's own sqlite-backed `tests/test_models.py::test_alembic_upgrade_head_creates_matching_schema`
  still no-ops cleanly.
- `downgrade()` drops the index (`DROP INDEX IF EXISTS ix_runs_tenant_id_created_at`), Postgres-guarded.
- Zero changes to `src/app/repositories/postgres_repository.py`, `src/app/routers/runs.py`, or any
  route/business-logic file.
