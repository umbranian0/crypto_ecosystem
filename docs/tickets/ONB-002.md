## Analysis
Tech Lead validated against the real stack: stored price `close` is a raw level and is rejected by
validation-service's MR-001 price-level guardrail (422). No returns field is stored. `volume` on
`binance_price_btcusdt_1h` passes the guardrail. A probe run with
`dataset_reference={"source":"binance_price_btcusdt_1h","field":"volume","start":"2024-01-01T00:00:00","end":"2024-03-01T00:00:00"}`,
`horizon=1, purge_gap_hours=24, train_window=500, test_window=100, step=100` completed with 9 splits.
Therefore the demo target is hourly traded volume (disclosed on the page), not a return series. The demo
illustrates the protocol mechanics only; copy must say so and must not frame numbers as a finding.

## Design
New router `src/app/routers/demo.py` (include in `main.py`), reusing from `app.routers.runs`:
`_fetch_ingestion_datasets`, `_call_downstream`, `_render_error_for_status`, `DownstreamHeadersDep`,
`GatewayApiUrlDep`, `DOWNSTREAM_HTTP_TIMEOUT_SECONDS`, and `RunRequest`/`RunResponse` from
`naive_first_common.contracts` (grep `runs.py` first; do not copy submit logic beyond the minimal call).
Demo config is a module-level constant in `demo.py` (never form defaults; `run_new.html` must not change).
Disclosure mechanism: `RunRequest.label` (max 200) set to
`"Demo run: demo configuration -- not a recommended default for your own data"`; run_detail already renders
`run.label`. No validation-service/gateway change.
Templates: new `demo_run.html` (and `demo_run_unavailable` handled inside the same template via a flag).
- `GET /demo-run` (session-gated via `DownstreamHeadersDep`): explains what it will do: sample data,
  fixed illustrative config (list all values), target = hourly traded volume of the sample BTCUSDT 1h
  dataset because stored price levels are rejected by the platform's returns guardrail, the literal
  sentence "demo configuration -- not a recommended default for your own data", and that the result is
  the usual naive-first comparison, not a finding; a POST button "Run demo validation".
- `POST /demo-run`: fetch datasets; if source `binance_price_btcusdt_1h` absent -> render same page
  (status 200) with message "Sample data is not loaded for this tenant. Ask your operator to seed it." and
  no button; else POST `/runs` with the fixed RunRequest; on transport failure/502/504/other non-2xx use
  `_render_error_for_status`; on success 303 redirect to `/runs/{id}`. Repeat clicks just submit another run.
- Add a nav link "Demo run" in `base.html` (tenant nav) so the entry is reachable post-login; fix any
  nav test expectations.
