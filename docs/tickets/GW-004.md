# GW-004 — SQLite-backed repository implementation (interim)

**Status: done**

## Analysis
Story: GW-004 (Must), depends on GW-003. Constraining docs: backlog decision 2 (interim SQLite, mirrors VS-004), backlog AC (`GATEWAY_API_DB_PATH` env var-driven path, default `./gateway.db`, mirroring `VALIDATION_SERVICE_DB_PATH`'s precedent named explicitly in the backlog), backlog AC4 (revoked key's hash still resolves via `get_by_hash` with `revoked_at` set — revocation is a flag, not a delete). Direct precedent: `services/validation-service/src/app/repositories/sqlite_repository.py` (VS-004) and its DI wiring in `dependencies/repositories.py`.

## Design
Pattern: **Repository** (concrete SQLite implementation of GW-003's interfaces) behind the **DI** seam GW-003 declared. Files: `src/app/repositories/sqlite_repository.py` (new — `SQLiteTenantRepository`, `SQLiteUserRepository`, `SQLiteApiKeyRepository`), `src/app/dependencies/repositories.py` (edit — wire concrete providers, `_db_path()` reading `GATEWAY_API_DB_PATH` env var defaulting to `./gateway.db`, same shape as validation-service's `_db_path()`).

DRY check: grep `src/app/repositories/` (only `interfaces.py` from GW-003) before writing. Conversion between GW-002's SQLAlchemy models and GW-003's dataclasses happens once here (`_tenant_to_record`, `_user_to_record`, `_api_key_to_record`), same "convert once" rule VS-004 documents.

Tenant isolation (binding, same stance as VS-004's Design section): every query that has a `tenant_id` to filter by does so in the SQL `WHERE` clause itself, never "fetch, then check tenant_id in Python." `get_by_hash`/`get_user_by_email` (GW-003's two documented exceptions) correctly have no `tenant_id` filter — they resolve identity, they don't yet know the tenant.

`key_hash` uniqueness: `ApiKey.key_hash` should be looked up via an indexed/unique query — not a design requirement to add a DB-level unique constraint this ticket (GW-002 didn't specify one), but `get_by_hash` must do an exact-match `WHERE key_hash == ...` lookup, never a scan-and-compare-in-Python (that would reopen a timing-side-channel discussion GW-006 doesn't need to have, since SHA-256 lookup is already a deterministic index hit, not a secret comparison).

Only `src/app/dependencies/repositories.py` imports `sqlite_repository` directly (AC2) — route/business-logic code (none exists yet at this ticket, first appears at GW-005/006) depends on interfaces only.
