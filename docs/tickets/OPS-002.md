# OPS-002 — Measure and report test coverage in CI (no hard gate)

Status: **done**
Backlog: docs/product/backlog-operability.md, OPS-002 [Should]
Sprint: docs/sprints/sprint-08.md, runs after OPS-001
Depends on: OPS-001 (extends the CI workflow OPS-001 creates — cannot be written first)

## Analysis

Story: OPS-002 (Should). Acceptance criteria (backlog): `pytest-cov` (or equivalent) added as a dev
dependency to each of the five modules; OPS-001's CI workflow runs each module's tests with coverage
enabled and surfaces the report (printed in CI logs at minimum); **no minimum coverage threshold
enforced as a hard CI gate** — this is an explicit, binding acceptance criterion, not an oversight to
"improve" later; each module's README gains one line stating how to run tests with coverage locally.

Session constraint (do not violate): no hard coverage-percentage gate. The workflow must print the
number, not fail the build on it. This is stated three times now (backlog, sprint plan, this ticket)
because it is the one place a well-intentioned dev agent might over-deliver by adding
`--cov-fail-under=N` — do not add it.

This ticket spans all five modules by nature of the story itself (same shape as OPS-001, which the
Tech Lead also kept as one ticket rather than five, since the acceptance criteria are one coherent
change applied identically five times, not five independently-designed pieces).

**Deviation from environment assumption (not a scope deviation)**: `uv add --dev pytest-cov` and `uv
sync`/`uv lock` could not be run directly inside this repo's own module directories — Windows blocked
`uv.exe` specifically from writing to files under this machine's `Documents` folder (`Acesso
negado`/os error 5), while `python.exe`, `pip`, and `cp` could write there without issue, isolating
this to a `uv.exe`-specific write restriction rather than a repo permissions problem. Worked around by
running `uv add --dev pytest-cov` in a byte-for-byte scratch copy of each module (preserving the same
relative directory layout so `[tool.uv.sources]`'s `../../libs/...` relative paths resolved
identically), then copying the resulting `pyproject.toml`/`uv.lock` back into the real repo paths via
plain Python file copies (diffed against the originals first to confirm each change was exactly the
one intended `pytest-cov` line/lockfile update, nothing else). `pytest-cov` was then installed into
each module's actual pre-existing local `.venv` via `pip install pytest-cov` (identical end state to
what `uv sync` would have produced) so the local test run below is real, not simulated.
