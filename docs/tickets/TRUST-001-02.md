## Analysis

Covers TRUST-001's reporting-service AC plus its shared-constant AC (this ticket's copy must be
byte-identical to `TRUST-001-01`'s `METHODOLOGY_FACTS`, verified by a same-text test in this
service).

Verified directly (do not re-derive): `validation_audit.html.jinja`'s section 2 ("Leakage-protocol
parameters," lines 32–40) states the run's own parameter *values* but never names Diebold-Mariano
or the Harvey correction. Section 2.5 ("Reproducibility statement," `TRUST-004`, lines 42–55) sits
immediately after section 2. Sections 2 through 4 (lines 30–154) are entirely inside
`{% if run.status != "completed" %}...{% else %}...{% endif %}` (lines 24–157) — a non-`"completed"`
run today renders only the "Status" paragraph, nothing else, until section 5's disclaimer
paragraph (which, by an existing quirk, renders unconditionally because it sits after the
`{% endif %}` on line 157 even though its own `<h2>` heading is inside the `else` — pre-existing
behavior, out of scope for this ticket, not to be "fixed" here).

**Design call resolved** (the open question the sprint plan explicitly left for the Tech Lead): the
backlog's own AC text says the new subsection must be **"always-visible"** — that phrase settles
the question the sprint plan raised. The four methodology facts are static protocol facts, not
run-computed metrics, so they do not share the "no fabricated placeholder metrics" rationale that
justifies withholding sections 2–4 for a non-completed run. **Resolution: the new Methodology
subsection renders unconditionally, before the `{% if run.status != "completed" %}` gate** — not
inside either branch. This also matches dashboard-web's `TRUST-001-01` panel exactly (outside any
status/split gate) and satisfies this sprint's own Definition of Done line requiring a test that
proves the subsection "render[s] for a zero-split and/or non-completed run."

**Section-numbering consequence, decided to minimize blast radius** (per the sprint's own note not
to leave numbering ambiguous for whatever touches this template next): insert the new subsection as
**"2. Methodology"**, unconditional, directly after section 1 (Scope) and before the status gate.
The existing gated "2. Leakage-protocol parameters" (this run's own parameter *values*) is renamed
to **"2.1 This run's leakage-protocol parameter values"** — a sub-number under the new section 2,
requiring no renumbering of sections 2.5/3/4/5/6/7 (they keep their existing numbers unchanged).
This keeps the diff small: one new always-visible block, one heading-text rename, zero changes to
any other section's number or content.

## Design

**Pattern**: none of Strategy/Repository/Adapter/Factory/Observer applies — Jinja2 templating plus
one new Python constant passed into the existing render context, same shape as `narrative_html`'s
existing pass-through in `ValidationAuditRenderer.render`.

**Files touched** (scoped to `services/reporting-service` only):
- `services/reporting-service/src/app/renderers/validation_audit.py` — add a module-level constant,
  `METHODOLOGY_FACTS: tuple[str, str, str, str]`, **textually identical (byte-for-byte) to
  `TRUST-001-01`'s dashboard-web constant** — copy exactly:

  ```python
  METHODOLOGY_FACTS: tuple[str, str, str, str] = (
      "Rolling-origin walk-forward validation: each split trains on data up to a point in "
      "time and tests only on the period immediately after it -- never on rows the model "
      "could not yet have seen.",
      "A configurable purge gap separates every split's training window from its test "
      "window, closing the boundary-leakage channel a plain train/test split allows.",
      "Every run is benchmarked against the mandatory Naive0 and NaiveLast baselines -- a "
      "model's result is never reported in isolation.",
      "Model-vs-baseline comparisons use the Diebold-Mariano test with the Harvey et al. "
      "(1997) long-run variance correction for overlapping horizons, not a raw metric "
      "difference.",
  )
  ```

  `ValidationAuditRenderer.render` passes `methodology_facts=METHODOLOGY_FACTS` into
  `template.render(...)` alongside `run`/`splits`/`narrative_html` — pure addition, no existing
  call site changed in shape.
- `services/reporting-service/src/app/templates/validation_audit.html.jinja` — insert a new,
  unconditional block directly after section 1's closing `</table>` (line 22) and before
  `{% if run.status != "completed" %}` (line 24):

  ```jinja
  <h2>2. Methodology</h2>
  <p>Every validation run on this platform follows the same leakage-aware protocol, regardless
  of this run's own status or outcome:</p>
  <ul>
      {% for fact in methodology_facts %}
      <li>{{ fact }}</li>
      {% endfor %}
  </ul>
  ```

  Then rename the existing `<h2>2. Leakage-protocol parameters</h2>` (line 32) to
  `<h2>2.1 This run's leakage-protocol parameter values</h2>` — no other change to that block's
  content (still inside the completed-only `else` branch, still states horizon/purge
  gap/splits-evaluated verbatim). Sections 2.5/3/4/5/6/7 keep their existing numbers unchanged.

**DRY check** (performed before writing this ticket): grepped
`services/reporting-service/src/app` for `Harvey`/`Diebold-Mariano` — no existing occurrence
anywhere (the report today never names either by name, only computes/passes through `dm_*`
fields). No existing "static methodology text" constant exists to reuse; this ticket creates the
one constant this service needs, textually matching `TRUST-001-01`'s independently-authored copy
by convention plus a same-text test, per implementation-plan.md section 2's module-boundary rule
(no cross-service import).
