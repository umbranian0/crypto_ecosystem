# GW-008 — Request routing to `validation-service`'s real endpoints

**Status: done**

## Analysis
Story: GW-008 (Must), depends on GW-007. Constraining docs: backlog AC (request/response shapes match `validation-service`'s real `RunRequest`/`RunResponse`/`RunDetailResponse`/`SplitResultResponse` exactly — read from `src/app/routers/runs.py`/`splits.py`, not guessed; no business logic reimplemented; cross-tenant access proven impossible via the same 404 validation-service already returns, no new tenant-isolation logic added here; `VALIDATION_SERVICE_URL` env var, not hardcoded). Real shapes confirmed by reading `services/validation-service/src/app/routers/runs.py`/`splits.py` directly (not re-derived):
- `POST /runs` request (`RunRequest`): `dataset_id: str`, `dataset_reference: dict`, `horizon: int (ge=1)`, `purge_gap_hours: int (ge=0)`, `train_window: int (gt=0)`, `test_window: int (gt=0)`, `step: int (gt=0)`. Response (`RunResponse`, `201`): `{id: str, status: str}`.
- `GET /runs/{id}` response (`RunDetailResponse`, `200`): `{id, tenant_id, dataset_id, horizon, purge_gap_hours, split_config, status, created_at, completed_at, failure_reason}`. `404` if the run doesn't exist or belongs to a different tenant (validation-service's own `get_run` already collapses both cases).
- `GET /runs/{id}/splits` response (`list[SplitResultResponse]`, `200`): each entry `{split_index, train_start, train_end, purge_start, purge_end, test_start, test_end, model_mae, model_rmse, model_smape, model_mase, model_da, model_f1, model_oos_r2, naive0_mae, naive0_rmse, naive0_smape, naive0_mase, naive0_da, naive0_f1, naive0_oos_r2, dm_statistic, dm_pvalue, dm_verdict}`. `404` under the same run-ownership rule.
- Tenant header contract: `validation-service` resolves tenant via `Depends(get_tenant_context)` reading `X-Tenant-Id` — this is exactly what GW-007's `build_downstream_headers` produces.

## Design
Pattern: none new beyond **DI** (GW-006/GW-007's dependencies injected into these handlers) — this router is a pure proxy, no Strategy/Factory/etc. applies. File: `src/app/routers/runs.py` (new — mirrors validation-service's `RunRequest`/`RunResponse`/`RunDetailResponse` Pydantic models field-for-field, since this is the public contract clients build against per README.md's own "Contract" note, and `SplitResultResponse` too, kept in the same file per "no line overlap" not being a concern here — this is a fresh file, unlike VS-007/008/009's parallel-file split rationale). `src/app/dependencies/http_client.py` (new — a thin `httpx.Client`/`AsyncClient` provider reading `VALIDATION_SERVICE_URL` env var, default `http://localhost:8000` for local dev without `infra/docker-compose.yml` existing yet).

Handler flow (fixed, must match exactly, mirrors GW-007's Design intent): resolve `tenant: TenantContext = Depends(get_authenticated_tenant)` (GW-006) -> `headers = build_downstream_headers(tenant)` (GW-007) -> forward request body/path params via `httpx` to `VALIDATION_SERVICE_URL` + the matching validation-service path -> return validation-service's response body/status unmodified (structural pass-through: parse validation-service's JSON into this router's own Pydantic response models — which are exact field-for-field copies of validation-service's — rather than proxying raw bytes, so FastAPI's own response validation/OpenAPI contract stays accurate; this is not "reimplementing business logic," it's shape-preserving pass-through, same distinction VS-008's own docstring draws between "repository's job" vs "caller's job").

No tenant-isolation branching is added in this router — the `404` a cross-tenant request receives is entirely `validation-service`'s own `get_run`-returns-`None`-for-both-cases behavior (VS-007/VS-008), forwarded as-is (GW-009 will formalize "pass failure responses through unmodified" as its own concern, but the *absence* of new isolation logic here is this ticket's own AC).

DRY check: grep `src/app/routers/` (empty except GW-001's package init) before writing — no existing routing code to reuse; `src/app/dependencies/repositories.py` (GW-003/004/005/006) is where `TenantContext`/auth dependencies already live, imported not reimplemented.

Note on the mock-transport choice: production code (`app.dependencies.http_client`) uses a sync `httpx.Client`. `httpx.ASGITransport` only implements the async transport interface (`handle_async_request`), so it cannot back a sync client — confirmed directly against the installed `httpx==0.28.1` (`hasattr(httpx.ASGITransport, "handle_request")` is `False`). `tests/test_runs_routing.py` therefore uses `httpx.MockTransport` (the ticket's explicitly offered alternative) with a handler that mimics validation-service's real `runs.py`/`splits.py` response shapes and its 404-collapses-both-cases tenant-ownership rule.
