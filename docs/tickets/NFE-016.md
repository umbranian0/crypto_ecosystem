## Design
No new pattern. Two new files only: `libs/naive_first_engine/tests/test_regression_6h.py` and `tests/test_regression_24h.py`. This ticket must not touch `src/`. DRY check: reuse `tests/fixtures.py`'s calibration primitives (`_calibrated_magnitudes`, `_signed`, `_build_directional_scenario`) and `test_regression_1h.py`'s helper patterns (`_with_preamble`, `_single_split_config`, `_SyntheticForecast`/`_build_model_mae_rmse_scenario`-style construction) rather than re-deriving them — read `test_regression_1h.py` in full first as the template; it is closely mirrored, not reinvented. If a helper is generic enough to be reused verbatim across 1h/6h/24h (e.g. `_with_preamble`'s preamble-padding logic), prefer importing/parametrizing over copy-paste — but do not refactor `test_regression_1h.py` itself as part of this ticket (out of scope; NFE-015 is done and its file is not in this ticket's stated scope). Minor unavoidable duplication of the preamble/config helpers across three regression test files is acceptable and matches the existing repo convention of one self-contained regression file per horizon; do not force a shared cross-file module purely to satisfy DRY if it would require touching `test_regression_1h.py`.

Each file's MAE (and DA/F1, and DM) scenarios follow the same "calibrate a synthetic series to hit a published number, run it through the real `run_validation_protocol`" approach as NFE-015, with `ValidationConfig(horizon=6, ...)` / `horizon=24` respectively (the orchestrator already threads `config.horizon` into `dm_test`, confirmed in `protocol.py`).

**Harvey-correction demonstration (the acceptance-critical part of this ticket)**: for at least one fixture per file, in addition to asserting the published DM verdict/counts via `run_validation_protocol`, add a direct comparison: call `dm_test.dm_test(errors_model, errors_naive0, horizon=6)` (or 24) and `dm_test.dm_test(errors_model, errors_naive0, horizon=1)` on the *same* per-split error arrays, and assert the two `.statistic` values differ (not just p-value/verdict — the raw statistic, which is the actual quantity the correction changes). This requires the fixture's per-split loss differential to have real (non-zero) autocorrelation — a fixture with i.i.d. errors will make gamma_k ≈ 0 for all k>0 and the correction will be a near no-op even at horizon=6/24, defeating the point. Construct (or reuse if `fixtures.py` already has something suitable — grep first) a per-split error series with deliberately induced positive autocorrelation in the squared-error loss differential (e.g. an AR(1)-style construction on the residual, or overlapping-window construction that naturally induces it) so the two statistics are demonstrably, not just theoretically, different. Document in a comment why the fixture has autocorrelation (don't just assert the numbers differ with no explanation of why the construction guarantees it).

Same disclosure-block requirement as NFE-015: a docstring/comment block at the top of each new test file stating (1) original dataset/scripts absent from repo, (2) synthetic/seeded/deterministic fixture used, calibrated to reproduce published numbers, (3) exactly which published numbers are reproduced end-to-end vs not reproduced at all (mirror NFE-015's per-horizon disclosure precisely — if RF/OLS DM B/W counts can't all be fully reconstructed from the published aggregate rows alone, same scope call as NFE-015's RF/ARIMA applies and must be stated plainly, not silently dropped), (4) stated as a visible, disclosed downgrade, not buried.
