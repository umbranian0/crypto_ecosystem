## Design
No new design pattern -- this ticket is documentation plus a doc-sync verification script, mirroring
NFE-018's shape exactly (a script using `ast`, not `inspect`/import, comparing a README "Public API"
section against real public top-level defs/classes). File(s) touched: `libs/common/README.md`
(status line, owns/not-yet-owned distinction, Public API section) and, if the dev agent chooses to
build the check now (acceptance criteria allow either that or an explicit follow-up), a new
`libs/common/scripts/check_doc_sync.py` + `libs/common/tests/test_doc_sync.py`.

DRY check: grep `libs/common/scripts/` and `libs/common/tests/` first -- neither exists yet (no
`scripts/` directory in this lib at all). If building the check, do not duplicate NFE-018's logic by
copy-paste; the module list, README section format, and AST-parsing approach are lib-specific
(different modules: `tenant_context.py`, `db.py`, `contracts.py`, `testing.py`, not
`naive_first_engine`'s six), so a fresh, small script mirroring NFE-018's *structure* (not its
literal code) is the correct amount of reuse -- there is no shared cross-lib doc-sync utility today,
and building one now (e.g. moving the logic into `libs/common` itself so `naive_first_engine` could
import it) would be scope creep beyond this ticket's Should-priority hygiene goal; note the
observation for a future ticket if genuinely tempting, don't act on it here.
