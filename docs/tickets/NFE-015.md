# NFE-015 — Regression suite: reproduce the thesis's published 1h results table

**Status: done (with one disclosed, unmet acceptance criterion — see below)**

## Analysis
Story: NFE-015 (Must), depends on NFE-014 — the hard completion gate for the whole module (implementation-plan.md section 9: "must pass a regression test against the thesis's own numbers before any service is allowed to depend on it"). Constraining docs: da-tese-ao-produto.md section 1.3 (full 1h table), backlog NFE-015's own acceptance criteria (explicitly allows a documented synthetic/fixture-based reconstruction if the original dataset isn't available).

**Confirmed before writing this ticket**: the thesis's original dataset/scripts (`run_arima_returns.py`, `run_rf_noleak.py`, `run_sarima_only.py`, referenced in the README's "source material to extract from") are **not present anywhere in this repo** (checked: no matches repo-wide). `jupyter_notebooks/data/` contains real BTC market data (`btc1h_usdt_part1/2.csv`, sentiment, hash-rate CSVs) but not a ready-made reconstruction of the thesis's exact OLS/RF/ARIMA train/test scenario, model fits, or per-split errors — using it would require re-deriving the thesis's entire modeling pipeline (feature engineering, OLS/RF/ARIMA fitting, exact split windows), which is out of scope for this library (the library validates, it does not fit models) and out of scope for this ticket. Per the backlog's explicit allowance, this ticket uses a **documented synthetic fixture**, not the real dataset.

## Design
No new pattern. File touched: `libs/naive_first_engine/tests/test_regression_1h.py` (new file) only — this ticket must not touch `src/`. DRY check: reuse the shared 1h fixture already built across NFE-005/007/009/011 (grep `tests/` for it) as the base; extend with synthetic OLS/RF/ARIMA-shaped forecast series calibrated to reproduce the four rows' MAE/RMSE/DA/F1/DM numbers.

**Explicit disclosure required in the test file header** (this is the acceptance-critical part of the ticket, not optional prose): a docstring/comment block stating, in plain language:
1. The original thesis dataset and model-fitting scripts are not in this repo.
2. This suite uses a checked-in **synthetic fixture** (deterministic, seeded) constructed so that Naive0's MAE/RMSE against it equal the published 1h Naive0 numbers exactly (0.003627/0.005321), and OLS/RF/ARIMA are represented as synthetic forecast series *calibrated* (not fit from real features) to reproduce the published MAE/RMSE/DA/F1 numbers within tolerance.
3. Which specific numbers are fully reproduced by this end-to-end suite vs. which are only unit-tested at the function level in NFE-005-012 (e.g. DM B/W counts for all three of OLS/RF/ARIMA may not all be exactly reconstructable from summary tables alone — state plainly which ones are and aren't, per the backlog's explicit "not done silently" requirement).
4. This is a **downgrade from full reproduction to fixture-based reconstruction**, and it is visible here, not hidden.
