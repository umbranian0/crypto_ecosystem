# VS-016 — OpenAPI contract / README sync check

**Status: done**

## Analysis
Story: VS-016 (Should, `docs/product/backlog-validation-service.md`), depends on VS-006/007/008
(all done, Sprint 03). Deferred since Sprint 03 (7 sprints), re-confirmed with no cost/dependency
objection through Sprint 09, pulled into Sprint 10 on zero-cost/zero-risk grounds per sprint-10.md.
Constraining doc: implementation-plan.md section 8 ("for services, FastAPI's generated OpenAPI
schema is the source of truth -- don't hand-maintain a duplicate"). Backlog acceptance criteria:
(1) the README links to how to view/regenerate the OpenAPI schema (`/openapi.json` or a docs page)
instead of hand-listing endpoint request/response shapes; (2) a check (script or test) fails if the
README's "Contract" section lists endpoints that don't match the live route set, mirroring
`naive_first_engine`'s `check_doc_sync.py` (NFE-018) approach applied to routes instead of
functions. **Read `libs/naive_first_engine/scripts/check_doc_sync.py` directly before implementing**
-- it uses `ast` (not `inspect`/import) to avoid needing the package importable; a route-set check
can and should use FastAPI's own `app.routes` via a real import instead (the service is already a
running FastAPI app with fully wired routers, unlike a standalone lib script avoiding import
side-effects), so mirror NFE-018's *goal and rigor* (a real drift-detecting check, demonstrated to
actually fail on injected drift) rather than its literal AST-parsing mechanism, which solved a
different constraint (lib avoiding import) that doesn't apply here.

Note: `services/validation-service/README.md` currently hand-lists each endpoint's full
request/response field set in prose (the "POST /runs", "GET /runs/{id}", "GET /runs/{id}/splits"
sections) -- this is exactly the "hand-maintained duplicate" implementation-plan.md section 8 warns
against, and it is long, detailed prose that took real effort to write. This ticket does **not**
require deleting all of that detail -- the design-notes narrative (tenant resolution, failure
handling, persistence behavior) is genuinely valuable context beyond a bare route list and stays.
What must change is the framing: the README should point at `/openapi.json` (or `/docs`) as the
authoritative, always-current source for exact request/response *shapes*, with the prose narrative
kept for behavior/design context that OpenAPI can't express (tenant isolation semantics, failure
handling, synchronous-execution caveat, etc.) -- dev agent's call on exact wording/restructuring,
but the "Contract" framing must change from "here is the full shape" to "here is what it does and
why; see /openapi.json for the exact wire shape."

## Design
No new design pattern -- a comparison/verification script, matching NFE-018's shape (a script,
possibly wired into `pytest`, not library/business logic). New file(s):
`services/validation-service/scripts/check_doc_sync.py` (or `tests/test_doc_sync.py`-only if the
dev agent judges a standalone script unnecessary for a service, unlike a redistributable lib --
dev agent's call, document the choice). Must not touch `src/app/routers/*.py`'s actual route
logic -- only the README's content and the new check.

The check should confirm the README's documented route list (`POST /runs`, `GET /runs/{id}`,
`GET /runs/{id}/splits`) matches the real, live `app.routes` (path + method) from
`src/app/main.py`'s FastAPI instance -- catching the case where a route is added/removed/renamed in
code but the README's route references (however they end up phrased after this ticket's
restructuring) go stale.

DRY check: grep `services/validation-service/scripts/` and `services/validation-service/tests/`
first -- no `scripts/` directory exists yet in this service; no existing route-introspection/doc-
sync logic to duplicate. Do not import or shell out to `naive_first_engine`'s `check_doc_sync.py`
directly (different module, different comparison target -- functions vs. HTTP routes); write this
service's own small check, matching the precedent's *pattern*, not code-sharing it cross-module
(per implementation-plan.md section 9 -- this is exactly the kind of module-local tooling that stays
local unless a second service needs the identical logic, which none does yet).

it does a real `from app.main import app` import and introspects the live `app.routes`, recursively
flattening FastAPI's lazy `_IncludedRouter` wrapper (a structural, not isinstance-based, detection
that keeps working across FastAPI versions that flatten eagerly instead) to compare against the
README's `## Routes` entries. `tests/test_doc_sync.py` wraps `check()` as a pytest case plus three
additional unit tests for the parsing/diff helpers.
