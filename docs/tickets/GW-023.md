# GW-023 — Proxy: forward `since` override on `POST /ingestion/connectors/{source}/run`

**Module**: `services/gateway-api`
**Story source**: direct requester ask (2026-09-01), same follow-up as `INGEST-013`.
**Depends on**: `INGEST-013` (this sprint, must land and be Tech-Lead-verified first — same-file-
sequencing is not the concern here, correctness of the downstream contract is: this ticket forwards a
parameter whose semantics `INGEST-013` defines).
**Status**: done

## Analysis

`GW-019`'s existing `run_connector` (`src/app/routers/ingestion.py`) proxies `POST /ingestion/
connectors/{source}/run` to `ingestion-service`'s real endpoint with zero query parameters forwarded.
`INGEST-013` adds an optional `since` query parameter to that real endpoint (tenant-specified
first-crawl backfill depth). Per this router's own established precedent (`read_series` already
forwards `start`/`end`/`field` query params unmodified, dropping `None` entries, with zero
re-validation at this layer — `ingestion-service` owns all validation), `since` should be forwarded the
same way: this is a pass-through proxy, not a second place to reimplement `INGEST-013`'s `422`
validation rules.

## Design

**Pattern**: none of implementation-plan.md section 7's named patterns is newly invoked here — this is
a one-line extension of an existing pass-through proxy handler, the same shape `GW-019`/`GW-020`
already established.

**DRY check (grepped first)**: `read_series` in this exact file already has the "build a `params` dict
from optional query args, drop `None` entries, forward via `_call_downstream`" pattern
(`params = {key: value for key, value in {...}.items() if value is not None}`). Reuse this exact
pattern for `run_connector`'s new `since` parameter rather than inventing a second param-building
idiom in the same file.

**File touched** (one file, `services/gateway-api`, disjoint from every other in-flight ticket this
sprint): `src/app/routers/ingestion.py`'s `run_connector` handler only:
- Add `since: str | None = Query(default=None)` parameter, mirroring `read_series`'s existing
  `start`/`end`/`field` parameters exactly (same type, same default, same docstring style).
- Build `params = {"since": since} if since is not None else {}` and pass it to
  `_call_downstream(client.post, f"/connectors/{source}/run", params=params, headers=headers)`.
- Zero new validation logic in this router — a downstream `422` (malformed/future/`INGEST-013`'s
  earliest-available-date rejection) is forwarded unmodified via the existing `_raise_for_error`, same
  as every other proxied error in this file.
- No response-shape change — `ConnectorRunResponse`'s `since` field already flows through unmodified
  (this router returns the forwarded JSON body as-is, per its own existing `-> dict` pass-through
  shape).

## Implementation acceptance criteria

- `POST /ingestion/connectors/{source}/run` accepts an optional `since` query parameter.
- When supplied, `since` is forwarded to `ingestion-service` as a query parameter on the downstream
  call, unmodified (same string value, no reformatting/reparsing).
- When omitted, the downstream call carries no `since` parameter at all (not an empty string) —
  matching `read_series`'s existing "only include params that were actually supplied" behavior.
- A downstream `422` (any of `INGEST-013`'s three rejection reasons) is forwarded unmodified: same
  status code, same `detail` text.
- No change to any other route in this file (`list_datasets`, `read_series`, `connector_status`).
