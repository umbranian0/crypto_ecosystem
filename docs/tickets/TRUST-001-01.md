## Analysis

(this ticket originates the shared wording; `TRUST-001-02` reuses the same literal text
independently in reporting-service).

Verified directly (do not re-derive): `run_detail.html`'s status table (lines 9–22) and
`headline_verdict_summary` paragraph (lines 32–34) render unconditionally. Everything from
"Per-split validation results" onward (line 36+), including `_dm_verdict_chart.html`'s caption

## Design

**Pattern**: none of Strategy/Repository/Adapter/Factory/Observer applies — static server-side
templating plus one new pure-text constant, same shape as `CAVEAT_SENTENCE` (FHS-004 precedent).

**Files touched** (scoped to `services/dashboard-web` only):
- `services/dashboard-web/src/app/routers/runs.py` — add a new module-level constant,
  `METHODOLOGY_FACTS: tuple[str, str, str, str]`, placed near the existing `CAVEAT_SENTENCE`
  constant (same file, same "static disclosure text" concern). **Exact text, authored once here
  and reused verbatim (byte-for-byte) by `TRUST-001-02` in reporting-service — do not paraphrase**:

  ```python
  METHODOLOGY_FACTS: tuple[str, str, str, str] = (
      "Rolling-origin walk-forward validation: each split trains on data up to a point in "
      "time and tests only on the period immediately after it -- never on rows the model "
      "could not yet have seen.",
      "A configurable purge gap separates every split's training window from its test "
      "window, closing the boundary-leakage channel a plain train/test split allows.",
      "Every run is benchmarked against the mandatory Naive0 and NaiveLast baselines -- a "
      "model's result is never reported in isolation.",
      "Model-vs-baseline comparisons use the Diebold-Mariano test with the Harvey et al. "
      "(1997) long-run variance correction for overlapping horizons, not a raw metric "
      "difference.",
  )
  ```

  `run_detail`'s existing handler passes `methodology_facts=METHODOLOGY_FACTS` in the template
  context alongside its existing values — no new downstream call, no new field, pure addition to
  an already-built context dict.
- `services/dashboard-web/src/app/templates/_methodology_panel.html` (new partial, same
  `{% include %}` pattern as `_error_chart.html`/`_dm_verdict_chart.html`) — renders a `<h3>
  Methodology</h3>`, one intro sentence ("Every validation run on this platform follows the same
  leakage-aware protocol, regardless of this run's own status or outcome:"), and a `<ul>` of the
  four `methodology_facts` items. Also includes one link: `<a href="/help/leakage-demo">See this
  protocol applied to the thesis's own real numbers</a>` (the link `TRUST-002` needs — add the
  `<a>` now since the panel is being authored anyway; `TRUST-002` will make `/help/leakage-demo`
  resolve, this ticket does not need that route to exist yet for its own tests to pass, but must
  not 404-link-check itself — do not add an automated link-check test here, `TRUST-002`'s own
  ticket covers that).
- `services/dashboard-web/src/app/templates/run_detail.html` — `{% include
  "_methodology_panel.html" %}` inserted right after the status `</table>` (line 22) and before the
  `{% if run.warnings %}` block (line 24) — unconditional, outside `{% if splits %}`, matching the
  Analysis section's verified gap exactly.

**DRY check** (performed before writing this ticket): grepped `services/dashboard-web/src` for
`Harvey`/`Diebold-Mariano` outside `_dm_verdict_chart.html` — no other occurrence. No existing
"static methodology text" constant exists to reuse; this ticket creates the one constant used by
this panel (and, independently authored but textually identical, by reporting-service in
`TRUST-001-02`).
