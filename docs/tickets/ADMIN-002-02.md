## Design

**Pattern**: none of Strategy/Repository/Adapter/Factory applies — a read-only proxied list view, same
shape as `settings_connectors.html`'s read path. Dependency Injection only (`OperatorTokenHeaderDep`/
`GatewayApiUrlDep`), same as every other Settings route.

**Files touched** (scoped to `services/dashboard-web` only):
- `services/dashboard-web/src/app/routers/settings_audit_log.py` (**new module**, mirroring
  `settings_connectors.py`'s/`settings_tenants.py`'s own "one new disjoint file per Settings concern"
  precedent — do not add this route to `settings.py`, `settings_tenants.py`, or `settings_connectors.py`):
  ```python
  @router.get("/settings/audit-log")
  def settings_audit_log(
      request: Request,
      headers: OperatorTokenHeaderDep,
      base_url: GatewayApiUrlDep,
      limit: int = 20,
      offset: int = 0,
  ):
      with httpx.Client(base_url=base_url, timeout=DOWNSTREAM_HTTP_TIMEOUT_SECONDS) as client:
          response, transport_status = _call_downstream(
              client.get, "/operator-audit-log", headers=headers, params={"limit": limit, "offset": offset}
          )
          if transport_status is not None:
              return _render_error_for_status(request, transport_status)
          if response.status_code != 200:
              return _render_error_for_status(request, response.status_code)
          body = response.json()

      return templates.TemplateResponse(
          request,
          "settings_audit_log.html",
          {"items": body["items"], "limit": body["limit"], "offset": body["offset"], "total": body["total"]},
      )
  ```
  No `@router.post` anywhere in this file — this is a read-only surface by design (AC's own "read-only"
  wording); no mutating control of any kind is ever rendered here.
- `services/dashboard-web/src/app/templates/settings_audit_log.html` (new template, same structural shape
  as `settings_tenants.html`'s table): one `<table>` with columns Action / Target tenant / At /
  Correlation id, one `<tr>` per `items` entry (`target_tenant_id` rendered as `—` when `None`, matching
  this codebase's existing "honest absence" convention, e.g. `_format_progress`'s own precedent in
  `operator.py`), plus a "See also" cross-link paragraph to `/settings/tenants` (matching
  `settings_tenants.html`'s/`settings_connectors.html`'s own existing cross-link convention). No `<form>`,
  no `<button type="submit">`, no `hx-post`/`hx-delete` anywhere in this file (Test acceptance criteria
  below proves this mechanically).
- `services/dashboard-web/src/app/templates/base.html` — one new nav `<a href="/settings/audit-log">Audit
  log</a>` inside the existing operator-nav block (lines 33-42), alongside `Tenants`/`Environment`/
  `Monitoring`, same active-class ternary convention as the other three links.
- `services/dashboard-web/src/app/main.py` (or wherever this service's routers are registered — confirm
  the exact registration call site before editing, mirroring how `settings_tenants.router`/
  `settings_connectors.router` are already registered) — register the new router.

**DRY check note** (grepped before writing this ticket): `_call_downstream`/`_render_error_for_status`
(`routers/runs.py`) are the one existing transport-failure/non-2xx handling mechanism every Settings route
already reuses (`settings_tenants.py`, `settings_connectors.py`) — reused here too, not a fourth
near-identical try/except. No existing "render a paginated table" partial/macro exists to reuse; this is
the first paginated (not just listed) table in this service's Settings area, so a new template is
correct, not a DRY violation.
