## Analysis
Building blocks for self-serve rotation. Constraints: one minting implementation; operator `revoke_key` behavior unchanged; auth behavior/401 paths/logging unchanged; no migration.

## Design
- DRY check: grep `token_urlsafe` / `sha256` in gateway-api; the only minting code is in `provisioning.py::provision()`. Extract `mint_api_key(tenant_id, api_key_repo) -> tuple[ApiKeyRecord, str]` (record + raw key; creates the hashed row via `create_key`) in `provisioning.py`; `provision()` calls it; the `api_key_issued` log line behavior stays. `provision()` externally unchanged (still returns `(tenant, raw_key)`).
- `app/dependencies/auth.py`: add `get_authenticated_key(...) -> ApiKeyRecord` holding the current body of `get_authenticated_tenant` (same 401 paths/logging); `get_authenticated_tenant` becomes a thin wrapper returning `TenantContext(tenant_id=record.tenant_id)` (via `Depends(get_authenticated_key)`; existing tests that `dependency_overrides` `get_authenticated_tenant` must keep working).
- Repository: add to `ApiKeyRepository` protocol + Postgres + SQLite: `revoke_key_if_not_last_active(tenant_id, key_id) -> str` returning one of `"revoked"`, `"already_revoked"`, `"not_found"`, `"last_active"` (module constants / Literal). Atomic: Postgres -- one transaction, `_set_tenant_scope`, `SELECT ... FOR UPDATE` over the tenant's api_keys rows, then evaluate: target missing -> not_found; target already revoked -> already_revoked; count of active keys excluding target == 0 -> last_active (no update); else set revoked_at. SQLite: single write transaction (`BEGIN IMMEDIATE`-equivalent) with the same rule. Update interfaces.py docstrings. Update any test fakes implementing the protocol (grep tests for `revoke_key`).
- Pattern: Repository (existing). No other pattern.
