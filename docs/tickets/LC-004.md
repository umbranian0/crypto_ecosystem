## Analysis
Story: LC-004 (Must), depends on LC-003 (resolver must exist). Binding sprint note: assert 401, not 400, matching LC-003.

## Design
Pattern: none new — this ticket is entirely test code proving LC-003's DI-based fail-closed guarantee (implementation-plan.md section 7's Dependency Injection pattern) standalone. Files: `libs/common/tests/test_get_tenant_context_app.py` (new — the dedicated minimal FastAPI test app + its tests, kept separate from `test_tenant_context.py`'s function-level unit tests per LC-003's own ticket, so this file's job — full app-level proof — isn't mixed with LC-002/003's narrower unit tests).
DRY check: grep `libs/common/tests/` — only `test_tenant_context.py` (LC-002/003) exists; no existing FastAPI test-app fixture to reuse, this is the first one in this lib.

**Test app**: a minimal `FastAPI()` instance built inline in the test module (or a fixture), with one dummy route `GET /probe` whose handler takes `tenant: TenantContext = Depends(get_tenant_context)` and, if called, returns `{"tenant_id": tenant.tenant_id}`. For the "never invoked" proof (AC2), the handler body itself must be provably unreached on rejection — asserting the response status is `401` already proves this mechanically (FastAPI raises the `HTTPException` from within dependency resolution, before the endpoint function is invoked at all), but per the story's explicit "a dummy handler that would raise if called proves it was never invoked" wording, add a second dummy route whose handler body raises `AssertionError("handler body was invoked")` unconditionally, and assert that route also returns `401` (not a `500` from the `AssertionError` bubbling up) — this is the stronger, non-tautological proof the story asks for.
