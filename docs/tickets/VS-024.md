## Analysis
Story: backlog `VS-024`, unchanged design, restated against the new reference shape. Without this,
`VS-023`'s new source path is a real, live cross-tenant data leak: same-named sources
(`"binance_price_btcusdt_1h"`) exist per-tenant, and a `dataset_id`-free but `source`-keyed reference
must not let tenant A load tenant B's series just because the strings match.

## Design
File: `services/validation-service/src/app/dependencies/repositories.py`'s `get_dataset_source()`
provider â€” inject the current request's `TenantContext` into the constructed
`IngestionServiceDatasetSource` call so `load()` sends `X-Tenant-Id` on its own outbound call.

## Implementation acceptance criteria
- [x] `get_dataset_source()` threads the resolved tenant id through to `IngestionServiceDatasetSource`,
  not left for `POST /runs`'s handler to pass manually a second time. (`get_dataset_source` now depends
  on `get_tenant_context` and constructs a fresh, per-request `IngestionServiceDatasetSource` carrying
  `tenant.tenant_id`; `IngestionServiceDatasetSource` gained a required `tenant_id` constructor argument
  and sends it as `X-Tenant-Id` on every outbound call. `POST /runs`'s handler code is unchanged.)
