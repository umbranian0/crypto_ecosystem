# MDF-005-01 — Positioning/copy discipline for multimodal validation run results

**Module**: `services/dashboard-web` (primary — run detail template render), with a read-only check of
`services/gateway-api`/`services/validation-service` API field descriptions (no code change expected there
unless a banned word is literally found in a docstring/response description).
**Sprint**: 38 (`docs/sprints/sprint-38.md`). **Story**: MDF-005 [Must].
**Status**: done — Tech Lead independently re-ran `services/dashboard-web` suite (307 passed, 7 deselected,
zero regressions), confirmed no new CSS/visual treatment invented, confirmed all seven banned words
covered.

## Analysis

Covers MDF-005's full acceptance criteria (`docs/product/backlog-multimodal-dataset-fusion.md` lines 213-233).
MDF-003 (Sprint 36) persisted `feature_lineage`/`has_multimodal_features` on `Run`
(`services/validation-service/src/app/models.py`, migration `0009_add_runs_feature_lineage_column.py`) and
forwards both through `RunDetailResponse` (confirmed present in `services/gateway-api`'s contract and test
`test_get_run_forwards_and_returns_full_detail_shape`), but **`run_detail.html` does not render either field
yet** — confirmed by grep, zero matches for `feature_lineage`/`has_multimodal_features` in
`services/dashboard-web/src/app/templates/` or `routers/runs.py`. That gap is this ticket's scope: render the
lineage, with copy discipline, not build the lineage data (already done).

Constraints:
- CLAUDE.md: "statistical accuracy != economic value", never imply prediction/trading-signal capability.
- Existing precedent (`docs/tickets/README.md` Sprint 27 notes on FHS-003/FHS-004): every run-detail partial
  gets its own banned-word grep test scanning the rendered template's static HTML (not live data) for
  `"prediction"`, `"forecast"`, `"signal"`, `"target"`, `"recommendation"` — see
  `services/dashboard-web/tests/test_runs_detail.py::test_run_detail_template_has_no_banned_positioning_words`
  (and the `_dm_verdict_chart.html`/`_forecast_horizon_summary_panel.html`/`_shareable_summary.html` variants
  in the same file) as the exact pattern to copy. This ticket's own word list must additionally include
  `"alpha"` and `"edge"` per MDF-005's AC (the FHS precedent's list didn't need those; this feature does,
  because "alpha"/"edge" are the words most likely to leak into multi-source-data marketing copy).
- DRY check: reuse the existing verdict-category CSS variables and `UNDEFINED_VERDICT_CATEGORY` sentinel
  (RAV-003, still in `app.charting`) for any multimodal-run rendering — do not invent a second color/visual
  system for "multimodal mode." Reuse the existing `run_detail.html` `{% if splits %}`/DM-verdict block
  structure; feature-set composition is an additional inline fact alongside it, not a parallel template.

## Design

- Files touched (single module, `services/dashboard-web`):
  - `services/dashboard-web/src/app/templates/run_detail.html` (or a new included partial,
    `_feature_lineage.html`, if the dev agent judges that cleaner — matches this repo's existing
    partial-per-concern convention, e.g. `_dm_verdict_chart.html`).
  - `services/dashboard-web/src/app/routers/runs.py` only if `feature_lineage`/`has_multimodal_features` need
    any presentation-shaping before the template renders them (e.g. grouping by source) — no new backend
    call, both fields already arrive on the existing `RunDetailResponse` gateway-api call.
  - `services/dashboard-web/tests/test_runs_detail.py` — new tests, following the existing file's structure.
- No new "multimodal mode" visual treatment: same card/section styling as the rest of `run_detail.html`, same
  neutrality for beat/not-beat-naive verdicts regardless of source count.
- Read-only check (no expected code change): grep `services/gateway-api` and
  `services/validation-service`'s `RunDetailResponse`/OpenAPI field descriptions for
  `feature_lineage`/`has_multimodal_features` and confirm the docstrings already read as validation/composition
  language, not prediction-improvement language. If a banned word is found there, it is in scope to fix
  (still `services/gateway-api` or `services/validation-service`'s own module boundary — a one-line docstring
  fix, not a cross-module rewrite) and must be called out explicitly in the Outcome note.
