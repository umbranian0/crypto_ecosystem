# NFE-010 — Out-of-sample R²

**Status: done**

## Analysis
Story: NFE-010 (Must), depends on NFE-001, sequenced last in the `metrics.py` group. Constraining docs: da-tese-ao-produto.md section 1.5 — **critical**: R² here is naive-relative (measures whether the model's squared error beats Naive0's), explicitly NOT scikit-learn's mean-relative default. Getting this definition wrong would misrepresent the thesis's single most important interpretive claim (section 1.5 warns against exactly this misreading).

## Design
No new pattern. File touched: `metrics.py` (extend, final metrics addition this sprint), `tests/test_metrics.py` (extend). DRY check: grep `metrics.py` for the validation helper and reuse it.

`oos_r2(y_true, y_pred, y_naive) -> float` computed as `1 - (SSE(y_pred) / SSE(y_naive))` (naive-relative), not `1 - SSE(y_pred)/SSE(mean(y_true))`.

- [x] `oos_r2(y_true, y_pred, y_naive) -> float` exists, typed, computed relative to the naive benchmark's squared error, not the training-set or mean-relative definition.
- [x] Docstring explicitly states which R² definition is used (naive-relative, not mean-relative) and why (cross-reference da-tese-ao-produto.md section 1.5).

## Test acceptance criteria

- [x] Run via `.venv\Scripts\python.exe -m pytest tests/test_metrics.py -q`, confirm pass, paste output.

## Review acceptance criteria
- [x] Tech Lead personally re-derives the formula used in the diff by hand against `1 - SSE(pred)/SSE(naive)` before accepting — this is the single highest-risk definitional bug in the whole sprint (an sklearn-style mean-relative R² would silently pass a shallow test but misrepresent the thesis). Re-derivation: implementation computes `sse_pred = sum((y_true - y_pred)**2)`, `sse_naive = sum((y_true - y_naive)**2)`, returns `1 - sse_pred / sse_naive` — matches exactly, no reference to `mean(y_true)` anywhere.
