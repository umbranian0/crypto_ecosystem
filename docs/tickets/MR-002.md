## Design

**Pattern**: none of implementation-plan.md section 7's patterns are newly introduced — these are plain,
stateless pure functions (`Series -> Series`/`DataFrame`), not a Strategy/Adapter/Factory. This matches
MR-002's own backlog framing ("a documented, leakage-safe feature-engineering function," not a class
hierarchy) and keeps `research/` code trivially reusable as plain input to a future `Baseline.predict`
implementation without inventing structure the story doesn't call for.

**Files touched** (scoped to `research/` only, all new — this is the first real code in the directory):
- `research/features.py` (new) — the four feature functions.
- `research/tests/test_features.py` (new) — leakage-boundary unit tests.
- `research/tests/__init__.py`, `research/pyproject.toml` (or equivalent minimal test-runner config, per
  this repo's existing per-module `pytest` convention — see `libs/naive_first_engine/pyproject.toml` for
  the pattern to mirror) — a new `research/` test runner did not exist before this ticket; this ticket
  creates the minimal one, matching `libs/naive_first_engine`'s own scaffolding shape (NFE-001 precedent),
  not a heavier framework.
- `research/README.md` (documentation, not code) — status update per Definition of Done.

**DRY check (grep first)**: `grep -rn "rolling\|def.*volatility\|def.*lagged" libs/naive_first_engine/src
research/` — expected empty (confirmed before implementation; no existing rolling-window/feature-engineering
code anywhere in the repo to reuse or duplicate). `libs/naive_first_engine` owns the split/baseline/metric
machinery only (per its own README's "Owns/Does not own" section) — it has no feature-engineering surface,
so there is nothing there to import from; this is genuinely new ground, not a DRY violation of an existing
implementation.

**Function shapes** (research question stays open — MR-004/MR-005 decide if these help):
- `rolling_volatility(train_returns: pd.Series, window: int) -> pd.Series` — rolling standard deviation of
  `train_returns`, computed with `pandas.Series.rolling(window).std()`, no `min_periods` override that
  would let a value creep from outside the passed-in `Series` — output index is a strict subset of the
  input index (the first `window - 1` rows are `NaN`/dropped, never backfilled from data the caller didn't
  pass in).
- `rolling_mean_return(train_returns: pd.Series, window: int) -> pd.Series` — rolling mean, same window
  discipline as above.
- `rolling_std_return(train_returns: pd.Series, window: int) -> pd.Series` — rolling std of returns
  themselves (distinct from `rolling_volatility`'s naming only for backlog-literal traceability — both use
  the same `.rolling(window).std()` primitive; kept as two named functions since the backlog names both
  "rolling volatility" and "rolling ... std of returns" as separate deliverables, not to be silently
  collapsed into one function under two names).
- `lagged_returns(train_returns: pd.Series, lags: list[int]) -> pd.DataFrame` — one column per lag
  (`shift(lag)`), each column's first `lag` rows are `NaN` (never filled from data outside the passed-in
  `Series`), columns named `f"lag_{lag}"`.

**The one structural leakage-safety property every function must have, verified by AST/inspection (not
just tests)**: each function's body contains no reference to any name other than its own parameters and
`pandas`/`numpy` module-level calls — no closure over a module-level "full series" object, no default
argument bound to mutable/external state. This is the same "no `.fit()`/aggregation reaching outside the
current split" property `VS-030`'s `FeatureFoldScaler` already had to prove structurally, restated here for
this ticket's own functions per `/ml-feature-planning`'s design-phase requirement.

## Test acceptance criteria

- [x] One leakage-boundary unit test per function (4 total minimum): construct a synthetic `Series` with a
  distinctive, known "future" value appended past the fold boundary the function is given; call the
  function with only the pre-boundary slice; assert the function's output for every in-boundary index
  position is bit-identical to the output computed from a Series that never included the future value at
  all (i.e. appending/removing unseen future rows cannot change any already-computed output value) — the
  concrete mechanism the backlog's own AC2 asks for ("output length/window alignment against a synthetic
  series with a known future value that must not leak in").
- [x] A structural check (AST scan or direct source-inspection assertion, mirroring NFE-018/VS-030's own
  precedent for this kind of hard gate) proving no function in `research/features.py` references a
  module-level mutable object or a second Series-shaped parameter — both required, a passing behavioral
  test alone does not satisfy this per the sprint's own instruction (mirrors VS-030's Test AC precedent).
- [x] `research/` gains a runnable test suite (`pytest` from `research/`, or repo-root pointed at
  `research/tests`) — confirmed actually runnable, not just written.
