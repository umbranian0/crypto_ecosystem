## Analysis

`SplitResultResponse.client_baseline` (VS-017, `libs/common/src/naive_first_common/contracts.py`)
is an optional `ClientBaselineResult` present only when a run was submitted with a
`client_prediction_reference`. It carries the same metric fields as `model_*`/`naive0_*` plus a
mandatory `disclaimer` string, and (documented single-point-split case) may have
`dm_statistic`/`dm_pvalue` both `None`, which must render the same "undefined for this split"
treatment RAV-003 already established for the platform's own baseline — never a different,
inconsistent treatment for a third series.

## Design

**Pattern**: none from implementation-plan.md section 7 applies — read-only rendering addition.

**Files touched** (scoped to `services/dashboard-web` only):
- `services/dashboard-web/src/app/charting.py` — extend `build_error_chart` to append a third
  series (`client` bars, using the same registry-driven metric lookup RAV-004 added, read off
  `split.client_baseline.model_<metric>` when `split.client_baseline is not None`) only when at
  least one split in the run carries a `client_baseline`; extend `build_dm_verdict_chart` to bucket
  `client_baseline`'s own verdict into the same four categories, as a second, distinguishable
  series/count set, reusing `_verdict_category`'s None/None rule against `client_baseline.dm_statistic`/
  `client_baseline.dm_pvalue` rather than a second, inconsistent None-check. When no split has a
  `client_baseline`, both functions must return exactly the same shape as before this ticket (no
  layout change for the common case) — a regression here breaks every existing RAV-002/003 test's
  assumption.
- `services/dashboard-web/src/app/templates/_error_chart.html` / `_dm_verdict_chart.html` — render
  the third series only when present in the chart data; render `client_baseline.disclaimer` as
  visible copy adjacent to the chart whenever the series is shown (pull the disclaimer text off the
  first split that has a non-null `client_baseline` — it is documented as constant per run, VS-017).
- `services/dashboard-web/src/app/static/style.css` — one additional, distinct, status-neutral
  color token for the third (client-baseline) series in the error chart (e.g.
  `--color-accent-3` or reuse an existing unused status-neutral variable — dev's call, must not be a
  green/red pairing with the existing two/four). The DM-verdict chart's client-baseline series reuses
  the same four category colors RAV-003 already defined (a second set of four bars, not a fifth
  color) since the categories themselves are identical, just counted separately.

**DRY check**: reuses `_verdict_category`/`UNDEFINED_VERDICT_CATEGORY`/`_CATEGORY_CSS_SLUGS`
(RAV-003) for the client-baseline verdict bucketing rather than a second None-check; reuses
RAV-004's metric registry for the client-baseline value lookup rather than a third hardcoded
attribute-name formatter.

## Implementation acceptance criteria (carried over from the backlog story)

- When `SplitResultResponse.client_baseline` is present for a run's splits, the error chart and
  verdict chart each gain a third, visually distinct series; when absent (the common case), both
  charts render exactly as before this ticket — no layout change for runs without a client baseline.
- `client_baseline.disclaimer` is rendered as visible copy adjacent to the chart whenever that
  series is shown — never omitted just because the information is also in a chart.
- A `client_baseline` split with `dm_statistic`/`dm_pvalue` both `None` renders the same "undefined
  for this split" treatment RAV-003 already defines for the platform's own baseline.

## Test acceptance criteria

- Unit test(s) for `build_error_chart`/`build_dm_verdict_chart` against a fixture split set with
  `client_baseline` present on some/all splits, asserting a third series/category set appears with
  correct values; a fixture set with `client_baseline` absent on every split asserts the return shape
  is byte-for-byte identical to what RAV-002/003's own pre-existing tests already assert (no
  regression).
- A dedicated fixture with `client_baseline.dm_statistic=None, dm_pvalue=None` asserts it maps to
  `UNDEFINED_VERDICT_CATEGORY`, not merged into "no significant difference".
- Route-level test asserting `client_baseline.disclaimer` text renders adjacent to the chart when
  present, and is absent when no split carries a `client_baseline`.
- Color-safety assertion extended to include the new third-series color value.
