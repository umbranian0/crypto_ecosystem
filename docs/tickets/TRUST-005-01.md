**Story**: `docs/product/backlog-trust-and-admin-ops.md` TRUST-005 (Should).

## Analysis

Covers TRUST-005's dashboard-web AC. **Real finding, confirmed directly against
`services/dashboard-web/src/app/charting.py` (read in full, `build_headline_verdict_summary`, lines
421–455)**: there is no `better_count`/`worse_count` Jinja conditional anywhere in `run_detail.html`.
The closest existing "verdict" surface is `headline_verdict_summary`, a pre-built string returned by
this Python function. It computes `better_count` via the same `_verdict_category` helper
`build_dm_verdict_chart` uses, then returns one of two fixed-shape sentences:

```python
if run.has_client_model:
    return f"Beat Naive0 on {better_count}/{total} splits."
return (
    f"Beat NaiveLast placeholder on {better_count}/{total} splits -- "
    "no client model submitted."
)
```

It returns `None` outright for a zero-split run and has **no branch today for the "better_count is
zero across existing splits" case** — this story's condition is a Python-side change inside/beside
this function, not a template-side `{% if better_count == 0 %}` block (unlike reporting-service's
`TRUST-005-02`, which is a pure template addition inside an already-existing conditional).

**Design call made (stated explicitly, not assumed)**: the added sentence must apply only when
`run.has_client_model` is `True` *and* `better_count == 0`. Reasoning: when `has_client_model` is
`False`, the "Model" column is actually NaiveLast's own placeholder output being compared to
Naive0 — there is no real client model that "did not beat naive" in that case, only a platform
placeholder being benchmarked against another platform baseline. Appending a "most models,
including sophisticated ones, do not beat naive" sentence to that placeholder case would
misleadingly imply a real model was evaluated. The existing "no client model submitted" wording
already covers that case honestly; this ticket does not touch it.

## Design

**Pattern**: none of Strategy/Repository/Adapter/Factory/Observer applies — a pure-function
extension, same shape `build_headline_verdict_summary` already has.

**Files touched** (scoped to `services/dashboard-web` only):
- `services/dashboard-web/src/app/routers/runs.py` — add a new constant next to `TRUST-001-01`'s
  `METHODOLOGY_FACTS` (same file, same "static disclosure text" concern), **textually identical
  (byte-for-byte) to `TRUST-005-02`'s reporting-service sentence**:

  ```python
  NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE = (
      "Under rigorous, leakage-free validation, most models -- including sophisticated ones -- "
      "do not beat a strong naive baseline in a stable way; this platform's own published "
      "research found the same pattern, so this outcome is common and not evidence of a broken "
      "evaluation."
  )
  ```
- `services/dashboard-web/src/app/charting.py`'s `build_headline_verdict_summary` — extend the
  `run.has_client_model` branch only: when `better_count == 0` (and `has_client_model` is `True`),
  append `NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE` (space-separated) to the returned string, e.g.
  `f"Beat Naive0 on 0/{total} splits. {NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE}"`. The
  `has_client_model=False` branch is untouched. Import `NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE`
  from `app.routers.runs` into `charting.py`, or move the constant to `charting.py` instead if that
  avoids a circular import — dev's call at implementation time, but the constant's *text* and the
  *condition* it's gated on must match this ticket exactly either way.
- `run_detail.html` requires **no change** — `headline_verdict_summary` already renders
  unconditionally inside the existing `{% if headline_verdict_summary %}` block (lines 32–34); the
  longer string is rendered exactly the same way the shorter one is today.

**DRY check** (performed before writing this ticket): `build_headline_verdict_summary` is the only
function that computes `better_count` for this page (reused from `_verdict_category`, per its own
docstring) — no second "is this a zero-better-count run" check exists anywhere else in
`dashboard-web` to duplicate or diverge from.

## Implementation acceptance criteria

- A run with `has_client_model=True` and `better_count == 0` across its splits renders the
  existing "Beat Naive0 on 0/N splits." sentence **unchanged**, immediately followed by
  `NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE` verbatim.
- A run with `has_client_model=True` and `better_count > 0` renders **byte-identical** output to
  today (no regression) — confirmed against the existing
  `test_build_headline_verdict_summary_matches_dm_verdict_chart_better_count` test, which must
  still pass unmodified.
- A run with `has_client_model=False` renders **byte-identical** output to today regardless of
  `better_count` (the placeholder-wording branch is untouched) — confirmed against the existing
  `test_build_headline_verdict_summary_placeholder_when_no_client_model` test, which must still
  pass unmodified.
- A zero-split run still returns `None` (unchanged) — confirmed against the existing
  `test_build_headline_verdict_summary_none_for_zero_splits` test, which must still pass unmodified.
- Positioning check: the added sentence never implies any model *should* beat naive, only that not
  beating it is expected and valid — read literally, it states a fact about what "most models" do,
  not a normative claim.

## Test acceptance criteria

- New unit test, e.g. `test_build_headline_verdict_summary_appends_expected_finding_note_when_better_count_zero`:
  `run.has_client_model=True`, all splits `"worse"`/`"no significant difference"` (better_count=0),
  asserts the return value starts with `"Beat Naive0 on 0/N splits."` and ends with
  `NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE` verbatim (exact string check on the constant, not a
  substring/keyword check).
- New unit test confirming `has_client_model=False` with `better_count == 0` does **not** append
  the new sentence (returns exactly the existing placeholder-wording string) — proves the design
  call above is actually enforced in code, not just documented.
- Same-text test: `test_not_beating_naive_sentence_matches_shared_wording` asserts
  `NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE == (<the literal string above, hardcoded in this test
  file>)` — exact match, mirrors `TRUST-001-01`'s same-text-test mechanism exactly (same file
  location convention, same assertion shape). QA will independently verify this fails if this
  service's copy drifts from reporting-service's.
- The three pre-existing `build_headline_verdict_summary` tests listed in Implementation ACs above
  are re-run and confirmed to still pass unmodified (proves "does not soften or hide the actual
  verdict" — the existing sentence is untouched, not rewritten).
