# OPS-005-01 — Deepen validation-service's `/health` to check real DB connectivity

Status: **done**
Backlog: docs/product/backlog-operability.md, OPS-005 [Should]
Sprint: docs/sprints/sprint-08.md, runs in parallel with OPS-001 and OPS-005-02
Depends on: none

## Analysis

Story: OPS-005 (Should), scoped here to `validation-service`'s half of the story (`OPS-005-02`
covers `gateway-api`'s half — same story, split into two tickets because each touches exactly one
service's own file, per the Tech Lead's "a ticket spanning two modules should be two tickets" rule).

Evidence: `services/validation-service/src/app/main.py:26-28` is:
```python
@app.get("/health")
def health() -> dict[str, str]:
    return {"status": "ok"}
```
This returns `{"status": "ok"}` unconditionally — it never touches the database, so a container whose
Postgres connection is completely dead still reports healthy.

Constraining docs: this is distinct from `INF-009` (Compose-level startup ordering, deferred,
Sprint-07-owned) — INF-009 is about *when* the container is allowed to start; this story is about
what the app's own `/health` endpoint checks *after* it's running. Not duplicated.

Acceptance criteria (backlog, this service's half): `/health` performs a lightweight real check
against the active repository backend (e.g. `SELECT 1` via the already-memoized engine); returns a
non-`200`/distinguishable-failure body when the check fails; the check stays cheap (no full query);
existing `200 {"status":"ok"}` shape is preserved in the healthy case (additive, not breaking); a
test proves the failure case using the service's existing dependency-override/fake pattern.

## Design

No new `implementation-plan.md` section 7 pattern — this reuses the existing Dependency Injection
seam (`app.dependencies.repositories`) already in place for the repository providers.

File touched: `services/validation-service/src/app/main.py` (the `/health` handler) and
`services/validation-service/src/app/dependencies/repositories.py` (a new, small DI provider for a
health-check engine — see DRY check below). New test file:
`services/validation-service/tests/test_health.py`.

DRY check: grepped `services/validation-service/src/app/dependencies/repositories.py` — it already
has `_get_engine(url: str) -> Engine`, memoized by URL (ARCH-002), and both `get_validation_run_repository`/
`get_split_result_repository` already resolve the correct URL (SQLite path or `DATABASE_URL`) before
calling it. Do **not** duplicate that URL-resolution logic in `main.py` — add one new small provider,
e.g. `get_health_check_engine() -> Engine`, in `dependencies/repositories.py` that reuses the exact
same `_database_url()`/`_db_path()`/`_is_postgres_url()`/`_postgres_engine_url()`/`_get_engine()`
helpers already defined there (call the same private functions the two existing providers call, don't
re-derive the URL a third way), and expose it via a `Depends()`-injectable alias
(`HealthCheckEngineDep`) alongside the existing `ValidationRunRepositoryDep`/`SplitResultRepositoryDep`
aliases, so `main.py`'s `/health` handler takes the engine via `Depends()` like every other handler in
this service, and tests can override it with `app.dependency_overrides` exactly like the rest of the
suite already does.

Check design: `SELECT 1` via `engine.connect()` inside a `try`/`except`, nothing more — no ORM query,
no session/transaction beyond what the connection open+one trivial statement requires. On success,
return the existing `{"status": "ok"}` (status code `200`, unchanged shape). On failure (any
exception from `connect()`/`execute()`), return `{"status": "unhealthy", "detail": ...}` — no raw
exception message included in `detail` (avoid leaking connection strings/credentials in a public
response body); use a fixed generic string like `"database unreachable"`. Status code: `503 Service
Unavailable` (the standard HTTP semantic for "temporarily can't serve," matching the story's own
"non-200/distinguishable-failure body" requirement).

## Implementation acceptance criteria

- [x] `dependencies/repositories.py` gains a `get_health_check_engine() -> Engine` provider that
      reuses the existing URL-resolution helpers (no re-derivation of the DB URL) and a
      `HealthCheckEngineDep` `Annotated[Engine, Depends(...)]` alias, matching the existing alias
      convention in this module.
- [x] `main.py`'s `/health` handler takes `engine: HealthCheckEngineDep`, runs a cheap connectivity
      probe (`SELECT 1` via `engine.connect()`), and returns `{"status": "ok"}` (`200`) on success or
      `{"status": "unhealthy", "detail": "database unreachable"}` (`503`) on any connection/execution
      exception — no raw exception text, connection string, or credential ever appears in the
      response body.
- [x] The healthy-case response shape (`200 {"status": "ok"}`) is byte-identical to today's — additive
      change only, confirmed by re-running any existing test that already asserts on `/health`'s
      current shape (if one exists) unmodified.

## Test acceptance criteria

## Outcome

Implemented as designed. `dependencies/repositories.py` gained `get_health_check_engine()` (reuses
`_database_url`/`_is_postgres_url`/`_postgres_engine_url`/`_db_path`/`_get_engine`, no third URL
derivation) and `HealthCheckEngineDep`. `main.py`'s `/health` handler now takes the engine via
`Depends()`, runs `SELECT 1` inside `engine.connect()`, and returns `200 {"status": "ok"}` on success
or `503 {"status": "unhealthy", "detail": "database unreachable"}` on any exception (fixed generic
string, no raw exception text/connection string/credential ever included). Note: `response_model=None`
was added to the `@app.get("/health", ...)` decorator — not called out in the ticket's Design, but
required because the handler's return type widened to `dict[str, str] | JSONResponse`, and FastAPI's
default response-model inference cannot build a Pydantic schema for a `JSONResponse`-including union.
`tests/test_health.py` added (healthy case + non-tautological failure-path override case). Full suite:
65 passed (63 pre-ticket baseline + 2 new). README updated with a `/health` contract note.
