# AI-003 — Natural-language Q&A over a tenant's own stored run data (`services/dashboard-web`)

**Sprint**: 50. **Module**: `services/dashboard-web`. **Status**: done. **Priority**: Should.
**Depends on**: AI-001 (done), AI-002 (done, establishes the fact-grounding/validation pattern reused
here), AI-003-REFACTOR (done, `libs/ai_assist` now exists — this ticket consumes it, does not build a
second hosted-API client).

## Analysis

Covers backlog story AI-003 in full: `docs/product/backlog-ai-integration-ux.md` lines 153-193. Binding
constraints this ticket must satisfy, restated from the backlog/ADR-0011/this sprint's own instructions:
- Retrieval only through `gateway-api`'s existing public endpoints (`GET /runs`, `GET /runs/{id}`,
  `GET /runs/{id}/splits`) — `gateway-api` exposes no `GET /runs/trend` today (confirmed by reading
  `services/gateway-api/README.md`'s full route list before scoping this ticket — no gap found, no new
  endpoint needed).
- A fixed, small, non-looping number of retrieval calls per question (never an open-ended agent loop).
- The model call sits behind a new, dedicated route (`POST /assistant/ask`), never an existing hot-path
  route (ADR-0011's unsafe-extension-point list).
- Retrieval scoped to the authenticated tenant's own session via `DownstreamHeadersDep` (DASH-003's
  existing seam every other route uses) — a real cross-tenant-leak-guard test required (VS-024
  precedent: assert on actual retrieved values, not just "a response came back").
- Every answer carries an explicit citation to specific run id(s)/split(s).
- Banned-term test on both the generated answer and the assistant's static UI copy; a fixed refusal for
  out-of-scope questions (proven by a concrete test case, e.g. "will Bitcoin go up next week").
- Graceful degradation on model-call failure/timeout — no crash, no hang, a disclosed "unavailable"
  response.

## Design

**Pattern**: reuses the Adapter (`AssistClient`, from `libs/ai_assist`, AI-003-REFACTOR) and the
Dependency Injection seam (`DownstreamHeadersDep`/`GatewayApiUrlDep`, DASH-003) already established in
this module — no new pattern introduced for this ticket alone.

**DRY check (grepped before writing)**:
- `src/app/routers/runs.py`'s `_call_downstream`/`_render_error_for_status` helpers are reused for the
  retrieval calls to `gateway-api` — no fourth near-identical transport-failure try/except.
- `src/app/dependencies/downstream.py`'s `DownstreamHeadersDep`/`GatewayApiUrlDep` are reused unchanged.
- `libs/ai_assist`'s `get_assist_client()`/`AssistClient`/`AssistClientError` are imported, not
  reimplemented (this is the exact reason AI-003-REFACTOR ran first).
- A new, small `src/app/assistant/` package (mirrors `reporting-service`'s `app/narrative/` layout, the
  closest precedent for "prompt-building + fact-check + generation glue" in this codebase) holds:
  - `prompt_template.py` — `build_prompt(question: str, runs: list[RunSummaryResponse], detail:
    RunDetailResponse | None, splits: list[SplitResultResponse]) -> str`, a versioned, checked-in
    template (`PROMPT_TEMPLATE_VERSION = "v1"`), same "no new data source, only already-fetched fields"
    discipline as `reporting-service`'s `prompt_template.py`.
  - `fact_check.py` — `contains_banned_term(text: str) -> str | None` (own six-word `BANNED_TERMS` tuple,
    identical wordlist to AI-002's, deliberately not imported cross-service — see AI-003-REFACTOR's Design
    section for why this one stays module-local) and `is_out_of_scope(question: str) -> bool`, a small,
    deterministic keyword heuristic (mirrors "guardrail, not full NLU" precedent from AI-002's
    `fact_check.py` docstring) flagging questions about future prices/predictions (e.g. containing
    "will"+"go up"/"go down"/"price" combined with a future-tense cue, "predict", "forecast") — checked
    **before** any model call, so an out-of-scope question never reaches the hosted API at all (cheaper,
    and removes any chance the model improvises an answer).
  - `retrieval.py` — `fetch_context(client, headers, base_url) -> AssistantContext` making exactly three
    bounded calls: `GET /runs?limit=10` (tenant's recent run history), then, only for the single most
    recent run in that list (if any), `GET /runs/{id}` and `GET /runs/{id}/splits` — three calls max, zero
    calls if the tenant has no runs yet (in which case the assistant answers only from "you have no
    recorded validation runs yet," never fabricated). This is the fixed, reviewable retrieval pattern the
    backlog requires — no branching that could grow the call count based on the question's content.
  - `generation.py` — `answer_question(question, context, client) -> AssistantAnswer` (dataclass:
    `text: str`, `citations: list[str]`, `degraded: bool`). Builds the prompt, calls
    `client.generate(prompt)` inside a `try/except AssistClientError` (mirrors
    `reporting-service`'s `generate_narrative_html` `_MAX_ATTEMPTS` retry-then-fallback shape, one retry),
    runs `contains_banned_term` post-generation (regenerate once, then fall back to a fixed "unavailable"
    answer on a second banned-term hit — never ships a rejected answer), and **always appends a
    deterministic citation footer built from the real retrieved run/split ids** (not trusted to the
    model's own text) — e.g. `"Sources: run <id>"` / `"Sources: run <id>, split <n>"` / `"Sources: none
    (you have no recorded validation runs yet)"` — so the citation acceptance criterion holds by
    construction, not by hoping the model includes it.
- `src/app/routers/assistant.py` (new router module, following the `operator.py`/`settings.py`
  "one fresh module per distinct concern" convention): `GET /assistant` (renders `assistant.html`, the
  question form plus static intro/placeholder copy) and `POST /assistant/ask` (`headers:
  DownstreamHeadersDep`, `base_url: GatewayApiUrlDep`) — the sole route making the model call, never
  retrofitted onto `runs.py`'s existing routes.
- `src/app/templates/assistant.html` (new) + `src/app/templates/_assistant_answer.html` (new, HTMX-swapped
  fragment for the answer, same pattern `_crawl_trigger_result.html`/`_report_trigger_result.html`
  established in DASH-110) — intro copy states plainly: "This assistant explains your own validation
  history — it does not predict prices or markets."
- `base.html` gains a nav link to `/assistant` (tenant-session-gated block, same convention as every other
  authenticated route's nav entry).

**File(s) touched**: all under `services/dashboard-web/src/app/` (new `assistant/` package, new
`routers/assistant.py`, new templates, one-line `base.html` nav addition) plus
`services/dashboard-web/pyproject.toml` (add `naive_first_ai_assist` dependency, mirroring
`naive_first_common`'s existing `[tool.uv.sources]` entry) — one module only, per this repo's "a ticket
spanning two modules should be two tickets" rule (the `libs/ai_assist` half is AI-003-REFACTOR).

## Implementation acceptance criteria

- [x] `POST /assistant/ask` is a new, dedicated route; `runs.py`/`GET /runs/{id}` and its sibling routes
  are byte-unchanged by this ticket (confirmed via `git diff`).
- [x] Retrieval calls only `gateway-api`'s existing `GET /runs`, `GET /runs/{id}`, `GET /runs/{id}/splits`
  — no new `gateway-api` endpoint, no direct DB access, `DownstreamHeadersDep` used for every call.
- [x] Retrieval is exactly the fixed 0-3-call pattern described above — no loop, no per-question-content
  branching that changes the call count.
- [x] Every non-degraded answer includes a citation to a real run id (and split index when applicable);
  the zero-runs case states plainly there is no data to cite.
- [x] Out-of-scope questions are refused with a fixed message before any model call.
- [x] Model-call failure/timeout degrades to a fixed "assistant unavailable" response — no exception
  escapes `POST /assistant/ask`, no hang (bounded by the same `NARRATIVE_API_TIMEOUT_SECONDS`-driven
  `httpx` timeout `libs/ai_assist`'s client already enforces).
- [x] `assistant.html`'s intro/placeholder copy states plainly it explains the tenant's own validation
  history and does not predict markets.

## Test acceptance criteria

- [x] Cross-tenant-leak-guard test (VS-024 precedent): two distinct tenant sessions, distinct mocked
  `gateway-api` responses per tenant; asserts tenant A's citation/answer content only ever reflects tenant
  A's actual mocked run ids/values, never tenant B's — asserted on real values, not just "a response came
  back."
- [x] Citation test: a mocked successful run/splits fetch produces an answer whose citation footer names
  the real mocked run id (and split index for a splits-referencing question).
- [x] Banned-term test on generated answers (fixed `BANNED_TERMS` list) and a separate banned-term test on
  `assistant.html`'s static copy (mirrors DASH-004/005's precedent test shape).
- [x] Out-of-scope refusal test: at least one concrete case ("will Bitcoin go up next week") asserts the
  fixed refusal string is returned and the mocked `AssistClient.generate` is never called.
- [x] Graceful-degradation test: `AssistClient.generate` raising `AssistClientError` (and, separately,
  timing out) is asserted to return the fixed "unavailable" response, not raise/hang the request.
- [x] Zero-runs tenant test: no retrieval calls beyond `GET /runs` happen, and the answer states there is
  no data.
