## Design
No new production code — this is a test-only ticket. Files: `tests/test_regression_api.py` (new). DRY check: **reuse `naive_first_engine`'s existing fixture-construction helpers rather than re-deriving the calibration math** — `naive_first_engine.tests.fixtures` (e.g. `build_1h_reference_scenario`, `NAIVE0_MAE_1H`, `NAIVE0_RMSE_1H`, `TOLERANCE`) is importable since `naive_first_engine` is an installed path dependency of this service; import it directly (`from naive_first_engine.tests import fixtures` — check it's actually importable as installed, since `tests/` may not be part of the installed wheel; if not importable, note that as a deviation and either vendor the minimal calibration helper needed or construct an equivalent scenario using only `naive_first_engine`'s public API, documenting which approach was taken and why).

**What this test does and does not check (mirror the disclosure-block convention)**: write a module-level docstring disclosure block, same spirit as `test_regression_1h.py`'s, stating: (1) this test drives the full `POST /runs` → `GET /runs/{id}/splits` HTTP round trip, not a direct `run_validation_protocol` call; (2) it reuses the same seeded synthetic 1h fixture the engine's own regression suite is checked against (or documents the deviation if direct reuse wasn't possible); (3) it is a wiring/integration check confirming values survive the engine call → persistence → API response path unaltered — **it is explicitly not a re-derivation of the algorithm's correctness**, that remains `naive_first_engine`'s own regression suite's job.

**What must be asserted**: the persisted/returned Naive0 MAE (`naive0_mae` column, via `GET /runs/{id}/splits`) matches `NAIVE0_MAE_1H` (0.003627) within the same tolerance the engine's own suite uses. For the DM verdict count, reuse `build_ols_dm_splits_1h`-style construction (or the simplest available equivalent) to produce a multi-split run whose `naive_last` DM verdicts (per VS-002's `model_*`/`dm_*` = naive_last mapping) have a known better/worse count, and assert the returned `dm_verdict` values match — this doesn't have to be the exact OLS scenario (this service never sees an OLS baseline; VS-017 is deferred), but it must be a real, checkable-against-something-published-or-derived assertion, not an arbitrary tautology.
