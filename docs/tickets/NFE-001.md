## Environment note (applies to every ticket in this sprint)
In this sandboxed Windows environment, `uv sync` / plain `uv run pytest` intermittently fail to write new files (`uv.lock`, files inside a freshly-created `.venv`) with a Windows "file not found" error — reproducible even with the sandbox disabled, consistent with a cloud-sync (OneDrive) file-creation race, not a code defect. Workaround used throughout this sprint: `.venv` created via `python -m venv .venv`, dependencies installed via `.venv\Scripts\python.exe -m pip install -e . pytest`, and tests run via either `.venv\Scripts\python.exe -m pytest` or `uv run --no-sync pytest` (both bypass the lock-file write). Every dev agent in this sprint was instructed to use this workaround and to actually run it, not assume it.
