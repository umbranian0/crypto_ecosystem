## Analysis
Story: VS-010 (Must), depends on `libs/common`'s tenant-context module (LC-001–004, all complete before this ticket starts, per sprint-04.md's execution order). Constraining docs: docs/product/backlog-validation-service.md VS-010 acceptance criteria — route handlers resolve `tenant_id` via `Depends()` from `naive_first_common`, no hand-rolled tenant-resolution logic inside `validation-service`, a test confirms unresolvable-tenant requests are rejected before reaching repository code, this story previously blocked (not implemented against a placeholder). Binding sprint note: **this ticket, not LC-001, is the one that adds `naive_first_common` to `services/validation-service/pyproject.toml`** and performs the actual swap in the route handlers.

**Current state read directly from Sprint 03 code** (`src/app/routers/runs.py`, `src/app/routers/splits.py`, both read in full before writing this ticket):
- `POST /runs` (`runs.py`): `RunRequest.tenant_id: str` is a required body field; every downstream call (`run_repository.create_run`, `split_repository.add_splits`, `run_repository.update_run_status`, `event_publisher.publish`'s payload) uses `request.tenant_id`.
- `GET /runs/{id}` (`runs.py`, `get_run` handler): `tenant_id: str` is a required query parameter, passed straight to `run_repository.get_run(tenant_id, run_id)`.
- `GET /runs/{id}/splits` (`splits.py`, `get_splits` handler): same pattern — `tenant_id: str` query parameter, passed to `run_repository.get_run(tenant_id, run_id)` then `split_repository.get_splits(tenant_id, run_id)`.
- All three handlers' tenant-isolation behavior (404-collapses-both-cases for `GET` endpoints) is independent of *how* `tenant_id` is obtained — only the source changes, not the isolation logic itself, which is Repository-layer (VS-004) and out of this ticket's scope.

## Design
Pattern: Dependency Injection (implementation-plan.md section 7), consistent with the DI seam `src/app/dependencies/repositories.py` already established for repositories/`DatasetSource`/`EventPublisher` in Sprint 03. Files: `services/validation-service/pyproject.toml` (edit — add `naive_first_common` as a path/workspace dependency, mirroring the existing `naive_first_engine` entry), `src/app/routers/runs.py` (edit — remove `tenant_id` from `RunRequest`, remove the `tenant_id` query param from `get_run`, add `tenant: TenantContext = Depends(get_tenant_context)` to both handlers, replace every `request.tenant_id`/`tenant_id` reference with `tenant.tenant_id`), `src/app/routers/splits.py` (edit — same swap in `get_splits`), `services/validation-service/tests/test_runs_endpoint.py` and `tests/test_splits_endpoint.py` (edit — replace the `tenant_id` body field / `params={"tenant_id": ...}` query param with an `X-Tenant-Id` request header on every call, add a new fail-closed test), `services/validation-service/tests/test_failure_handling.py` and `tests/test_regression_api.py` (edit only if they construct requests with the old `tenant_id` field/param — grep first, update only what's broken by the swap, no unrelated changes).
DRY check: grep `src/app/` for any hand-rolled tenant-extraction logic before writing — none exists yet (Sprint 03 used the interim explicit-field pattern deliberately, per backlog decision 1); this ticket removes that pattern, it does not need to deduplicate an existing one.

**Swap mechanics (must match exactly, mirrors LC-003's resolver shape)**:
1. `RunRequest` (runs.py) drops its `tenant_id: str` field entirely — it is no longer part of the request body.
2. `create_run(request: RunRequest, ..., tenant: TenantContext = Depends(get_tenant_context))` — new parameter, added alongside the existing `Depends()` params (repositories, dataset source, event publisher), same pattern already used for those.
3. Every `request.tenant_id` reference inside `create_run`'s body becomes `tenant.tenant_id`.
4. `get_run(run_id: str, tenant: TenantContext = Depends(get_tenant_context), run_repository: ValidationRunRepositoryDep)` — the `tenant_id: str` query parameter is removed, replaced by the `Depends()` parameter; body uses `tenant.tenant_id`.
5. `get_splits` in `splits.py` — identical swap: query param removed, `Depends(get_tenant_context)` added, `tenant.tenant_id` used in both the `get_run` ownership check and `get_splits` call.
6. Callers now authenticate via the `X-Tenant-Id` HTTP header (LC-003's interim extraction source) instead of a body/query field — this is a caller-facing contract change, documented in the Documentation acceptance criteria below.
7. No tenant-resolution logic (header parsing, validation, `TenantContext` construction) is written inside `validation-service` — `Depends(get_tenant_context)` is imported as-is from `naive_first_common`, matching AC2's explicit prohibition.

**Fail-closed proof placement (AC3)**: the required test confirming rejection happens "before reaching repository code" is written using the same technique LC-004 used standalone (a repository call that would raise/record-a-call if reached, proving it wasn't) — except here it proves the guarantee at the real consumer, with a real (SQLite-backed) repository, closing the loop from LC-004's standalone proof to this service's actual wiring, per sprint-04.md's stated sequencing rationale.
