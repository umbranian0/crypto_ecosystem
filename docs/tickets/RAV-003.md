## Analysis

Covers RAV-003's full acceptance criteria: visualize each split's existing `dm_verdict` field
(verbatim, no recomputation — the Harvey-corrected DM test already ran upstream in
`naive_first_engine`/`validation-service`) across a run's splits. `dm_verdict`'s actual values,
confirmed by reading `libs/naive_first_engine/src/naive_first_engine/dm_test.py`, are exactly
`"better"`, `"worse"`, `"no significant difference"` (`Verdict` type there) — plus the documented
`dm_statistic`/`dm_pvalue` both `None` case (`SplitResultResponse`'s own docstring in
`libs/common/src/naive_first_common/contracts.py`: a single-test-point split has zero variance,
making the statistic genuinely undefined). That `None` case must render as its own category, never
silently dropped or coerced into "no significant difference."

## Implementation acceptance criteria (carried over from the backlog story)

- Renders a chart using each split's existing `dm_verdict` field verbatim — no recomputation of the
  verdict client-side.
- A split whose `dm_statistic`/`dm_pvalue` are both `None` is shown as its own distinguishable
  category ("undefined for this split" or equivalent) — never silently dropped from the chart or
  coerced into "no significant difference."
- The four verdict categories use distinct, status-neutral colors — no green="better"/red="worse"
  pairing (verify explicitly, don't assume the chosen `style.css` variables are safe by inspection
  alone — list the actual hex values used and confirm none pairs a pure green with a pure red).
- Copy accompanying the chart states plainly that "better"/"worse" describes this split's own
  out-of-sample error relative to Naive0, under the Harvey et al. (1997)-corrected DM test already
  applied upstream — never phrased as "the model recommends" or "predicts."
