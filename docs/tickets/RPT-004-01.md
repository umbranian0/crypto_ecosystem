# RPT-004-01 -- reporting-service `GET /reports/{id}/diff/{other_id}` (field-level diff of two validation-audit reports)

**Status: done.** Module: `services/reporting-service` only. Story: RPT-004 (narrow API-only slice). Sprint: docs/sprints/sprint-65.md (see "RPT-004" YAGNI section). Read services/reporting-service/README.md and src/app/generation.py first.

## Analysis
Reports store rendered HTML only, so a field-level diff cannot read stored content: for each report, take its stored `run_id` (reports of kind `validation_audit` only), re-fetch run + splits from validation-service (`X-Tenant-Id`, same as generation.py) and diff per-split metric fields. This is disclosed as a run-data diff keyed by two reports. AC3 (dashboard "compare with a previous report" action) is NOT built: it depends on a report viewer that does not exist.
Positioning: neutral deltas only. NO "improved", "better model", "regression", scoring or ranking language anywhere (code, keys, docs, README). A smaller error is not an economic or predictive claim. The only summary permitted is the number of splits whose Naive0 comparison verdict category changed.

## Design
- New module `src/app/diff.py` (pure function, no I/O) + route `GET /{report_id}/diff/{other_id}` in a NEW router module `routers/report_diff.py` mounted under `/reports` in main.py (do not grow report_retrieval.py). Add a `fetch_run_and_splits(tenant_id, run_id, client)` helper in `generation.py` by extracting the existing fetch from `generate_validation_audit_report` (and reusing `_fetch_bounded_splits` / count for the 500-split cap) -- do not copy-paste the fetch; `generate_validation_audit_report` behavior must stay byte-identical (its tests unmodified).
- Lookup: `report_repository.get_report(tenant, id)` for both ids; either None -> 404 "report not found" (same body as GET /reports/{id}; no distinction between unknown and cross-tenant). Tenant only from `get_tenant_context`.
- Comparability rule (state it in README and the 422 `detail`, one plain reason string per failure), checked in this order: (1) both reports `report_kind == "validation_audit"`; (2) both runs have same `dataset_id`; (3) same `horizon`; (4) same `purge_gap_hours` and equal `split_config`; (5) either run's split count > 500 -> reject ("too many splits to diff"); (6) the two runs have identical `split_index` sets and identical `test_start`/`test_end` per split_index (alignment). Diffing a report with itself is allowed (all deltas 0).
- Output (pydantic response model): `report_id`, `other_report_id`, `run_id`, `other_run_id`, `dataset_id`, `horizon`, `split_count`, `verdict_changed_split_count`, `splits: [ {split_index, metrics: {<field>: {base, other, delta}}, dm_verdict: {base, other, changed}} ]` where fields are exactly the `model_*` (mae,rmse,smape,mase,da,f1,oos_r2), `naive0_*` (same seven) and `dm_statistic`, `dm_pvalue`; `delta = other - base`, or null when either side is null (undefined DM split); `dm_verdict.changed` compares the category via `naive_first_common.consistency.verdict_category` (so undefined splits are not conflated with "no significant difference"). Nothing recomputed; DM values are the existing Harvey-adjusted ones, verbatim. Splits ordered by split_index.
- Errors from downstream map as in the generate router (404 run not found, 502/504). Run no longer exists -> 404 "run not found".
- Pattern: none new (pure function + existing repository/DI). DRY: reuse generation.py fetch, `_call_downstream`, `verdict_category`.
