# GW-021 — Minimal operator-token authentication dependency (slice of `SETUP-010`)

**Sprint**: 18. **Module**: `services/gateway-api`. **Status**: done. **Priority**: Must.
**Depends on**: none. **Blocks**: `DASH-113` (uses this to gate `/settings`), `DASH-112`.
**Can run in parallel with**: `GW-022` (disjoint files).

## Analysis
Per the requester's explicit resolution (no more blocking on the sibling backlog): pull only the
minimal slice of `backlog-first-run-setup-and-ops.md`'s `SETUP-010` needed to unblock this sprint's
`DASH-112` (and `DASH-113`'s `/settings` gate) — a single shared `OPERATOR_TOKEN` env var, not a
multi-admin user table, not `SETUP-011`'s full `/tenants` CRUD (out of scope, not needed by anything in
this sprint). This ticket is deliberately narrower than `SETUP-010`'s own full scope.

## Design
Pattern: DI (FastAPI `Depends()`), mirroring `get_authenticated_tenant`'s existing shape in
`dependencies/auth.py` structurally (per `ARCH-008`'s documented `Security()`/`APIKeyHeader`
convention) but structurally distinct — never the same dependency function as tenant auth. File: new
`services/gateway-api/src/app/dependencies/operator_auth.py`. **DRY check**: reuses the same
`hashlib.sha256`-comparison discipline `GW-006` already established for tenant API keys (compare a
hash of the presented token to a hash of `OPERATOR_TOKEN`, never compare/log the raw value) — no new
comparison mechanism invented.

## Implementation acceptance criteria
- [x] `get_authenticated_operator` dependency reads a presented token (`X-Operator-Token` header, via
  `Security()` + `APIKeyHeader`, per `ARCH-008`), compares its SHA-256 hash to `OPERATOR_TOKEN`'s
  (loaded from env at dependency-call time, not memoized at import), raises `401` on mismatch/missing.
- [x] Structurally separate from `get_authenticated_tenant` — no code path where a tenant's own API key
  satisfies this dependency, and vice versa.
- [x] `INGEST-004`'s existing credential-status data is exposed via a new operator-gated proxy route
  (`GET /ingestion/connectors/credentials-status`) using this dependency — the concrete, real consumer
  this ticket exists to unblock (`DASH-112`). Note: `ingestion-service` does not implement the real
  downstream endpoint yet (lands later this sprint, `INGEST-004`/`INGEST-009` territory) — the route is
  wired and gated correctly today, and will 502/504 via GW-009's existing transport-failure handling
  until that downstream endpoint exists. This is expected, not a defect of this ticket.

## Test acceptance criteria
- [x] Valid `OPERATOR_TOKEN` → `200`. Missing/wrong token → `401`.
- [x] A real tenant's own valid API key, presented to the operator-gated route, is rejected (`401`/`403`)
  — the cross-boundary case this ticket exists to close.
- [x] Raw token value never appears in any log line (same discipline as `GW-006`/`GW-014`).

## Review acceptance criteria (Tech Lead verifies personally)
- Confirms zero raw-value comparison (`==` on the plaintext token) — hash-to-hash only.
- Confirms this dependency is never satisfied by a tenant API key.
- Re-runs `gateway-api`'s full suite, confirms zero regressions.

## Documentation acceptance criteria
- [x] `services/gateway-api/README.md` documents this as a narrow, deliberate stopgap (one shared
  operator secret, not multi-admin), same disclosed-interim convention `SETUP-010`'s own text uses,
  and states plainly this sprint pulled only this minimal slice of `SETUP-010` — the full
  `/tenants` list/create/revoke surface (`SETUP-011`) remains that sibling backlog's own scope, not
  duplicated here.
