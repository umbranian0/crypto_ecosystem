## Test acceptance criteria
- [x] Regression test reproduces da-tese-ao-produto.md OLS 6h (DA 52.51, F1 0.526) and OLS 1h (DA 51.33, F1 0.528). The MAE/RMSE `build_1h_reference_scenario` fixture could not be reused as-is: its residual signs are independent seeded coin flips (calibrated on magnitude only), so it doesn't carry a DA/F1 signal. Added a new, separately-documented `build_directional_reference_scenario_1h`/`_6h` fixture pair in `fixtures.py` (same disclosure/determinism discipline as the existing fixture), constructed by solving the DA/F1 equations for the two free confusion-matrix counts (TP, TN) under a balanced actual up/down assumption at n=10000, then assigning each point's sign by its solved quadrant (TP/TN/FP/FN) and drawing magnitudes from a seeded uniform distribution (magnitude is irrelevant to DA/F1). n=10000 makes both target DA percentages land on an exact integer count, so DA reproduces exactly; F1 only needs quadrant-count rounding to the nearest whole point, which empirically produces <= 2.03e-5 error for 1h and <= 6e-7 for 6h — both comfortably inside the documented tolerance `DIRECTIONAL_TOLERANCE_F1 = 2.5e-4` (and `DIRECTIONAL_TOLERANCE_DA = 1e-6` for the exact DA case).
- [x] Unit test: `directional_accuracy` returns exactly 50.0 on a synthetic series where predicted direction is uncorrelated with actual direction — built from two orthogonal periodic sign patterns (true: period 2, pred: period 4) that are mathematically guaranteed to agree on exactly half of every 4-point block, not a cherry-picked random draw.

## Post-close amendment (during NFE-014)
`f1_directional` originally raised `ZeroDivisionError` whenever a baseline predicts zero "up" moves — which Naive0 (flat zero forecast) does unconditionally, not only in an edge-case input. This wasn't caught by this ticket's own tests because its fixtures always contain a mix of predicted up/down signs. NFE-014's orchestrator surfaced it immediately, since it must score Naive0 on the full metric set (including F1) on every split. Fixed in `metrics.py` by the NFE-014 dev agent: precision/recall default to 0.0 when their denominator is 0 (sklearn's `zero_division=0` convention), documented inline at the fix site. Verified: NFE-009's own regression tests (OLS 1h/6h DA/F1 reproduction) still pass unchanged after the fix (`37`-plus tests green, no target numbers moved) — the fix only changes behavior for the previously-crashing zero-up-moves case, not the already-passing balanced case. Tech Lead sign-off: retroactively patching a closed ticket's file to fix a bug surfaced by downstream integration is acceptable and expected practice — the alternative (blocking NFE-014 or forking a near-duplicate metric) would be worse. Recorded here per the "no silent downgrade" documentation norm used throughout this sprint.
