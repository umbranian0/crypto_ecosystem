## Analysis

Covers the backlog's GW-028 story — verification-only unless a real gap is found, per the same
"confirm, don't assume" framing `GW-024` already established for this exact router/endpoint pair.
`connector_status` in `services/gateway-api/src/app/routers/ingestion.py` already returns
`response.json()` as a plain `dict` with no local Pydantic model to go stale — the working hypothesis
(to be proven, not assumed) is that `INGEST-021`'s new status values (`running`/`cancelling`/`cancelled`)
and `INGEST-024`'s new `rows_fetched_so_far`/`updated_at` fields pass through this proxy with zero code
change, the same way `GW-024` already proved for `INGEST-015`'s `queued`/`202`/`409` contract change on
the sibling `run_connector` route.

## Design

**File touched, if the test passes as expected**: only a new/extended test in
`services/gateway-api/tests/` — zero production code change.

**If (and only if) the confirmation test fails**: the minimal fix is scoped and added as part of this
same ticket, not a separate one (per the backlog's own "extend the same handler flow" precedent) — most
likely location, if a fix is needed at all, is `connector_status`'s own handler in `ingestion.py`, kept
to the smallest change that makes the new fields pass through, no re-architecture.
