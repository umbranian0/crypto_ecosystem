# FHS-001 — Resolve horizon-unit and cross-run-selection design questions

**Module**: `services/dashboard-web` (decision/documentation only, no chart/route/backend code
shipped by this ticket).
**Depends on**: none. **Blocks**: FHS-002, FHS-003, FHS-004.
**Story**: `docs/product/backlog-forecast-horizon-summary.md` FHS-001 (Must, blocking).
**Status**: done. `docs/adr/0007-forecast-horizon-summary-unit-and-scope.md` records the decision;
`services/dashboard-web/README.md`'s top status block links to it.

## Analysis

`RunRequest.horizon` (`libs/common/src/naive_first_common/contracts.py`) is a plain `int, ge=1`
with no documented unit. `naive_first_engine`'s regression suites
(`test_regression_1h.py`/`6h.py`/`24h.py`) confirm `horizon` is a step count over whatever
frequency the input series carries, not a fixed hour/day constant — the file names' "1h/6h/24h"
labels are the *fixture's own hourly index* multiplied by the step count, not something the engine
itself enforces. The one real ingestion connector today,
`services/ingestion-service/src/app/routers/connectors.py`'s `BINANCE_SOURCE_NAME =
"binance_price_btcusdt_1h"`, samples hourly — so for every run built from it, `horizon` is hours.
This is a fact about that connector, not a platform guarantee, and must be named as such rather
than hardcoded as if it always holds.

## Design

**Decision (written up in the ADR, not re-litigated here)**: `horizon` is
dataset-sampling-interval-relative; "7/15/30 days" converts to `horizon` 168/360/720 for the one
real (hourly) source today via a named, disclosed constant
(`ASSUMED_SAMPLING_INTERVAL_HOURS = 1`), not a hardcoded platform-wide day-to-`horizon` mapping.
This feature is scoped **Epic-A-style — select among a tenant's existing completed runs, no
backend change** — `GET /runs` (already proxied, `RunSummaryResponse` already carries `horizon`)
is filtered client-side (dashboard-web) by the converted `horizon` value; no new
gateway-api/validation-service endpoint, no `naive_first_engine`/`libs/common` change. A horizon
with zero matching completed runs renders an explicit empty state linking to `/runs/new` — no
silent fallback to a different horizon's data.
