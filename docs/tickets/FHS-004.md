# FHS-004 — Exportable/shareable summary text with the honesty caveat

**Module**: `services/dashboard-web`.
**Depends on**: FHS-003 (must be `done` — this ticket renders the same data shape the panel does;
sequenced strictly after it, not in parallel).
**Story**: `docs/product/backlog-forecast-horizon-summary.md` FHS-004 (Must).
**Status**: done.

Write the caveat-verbatim test **before** the rendering code (test-first), per this repo's own
emphasis on regression-proofing the honesty requirement, not just the happy path — this is the
highest-scrutiny part of this sprint (same standing this repo gave RAV-003's null-DM handling and
ECON-005's precedent). Presentation-only work — no `libs/naive_first_engine`/`libs/common`/
service-boundary change; if something here seems to need one, stop and report back.

## Analysis

A "copy summary" affordance on `run_detail.html` (near FHS-003's panel) renders a fixed-format
plain-text block via a `<textarea>` + copy-to-clipboard HTMX partial — no new JS framework
dependency (matches RAV-001's zero-new-dependency precedent, ADR-0006). The text block uses the
same already-fetched `run`/`splits` data FHS-003's panel renders — no new backend call, no
server-side persistence of the exported text (pure render-and-copy, per the backlog's own explicit
scope limit).

## Design

**Pattern**: none of Strategy/Repository/Adapter/Factory/Observer applies — plain server-side
templating, same DI seam as every other route.

**Files touched** (scoped to `services/dashboard-web` only):
- `services/dashboard-web/src/app/routers/runs.py` — a pure function, e.g.
  `build_shareable_summary_text(run: RunDetailResponse, splits: list[SplitResultResponse]) -> str`
  (no I/O, unit-testable standalone), producing a fixed-format text block containing: dataset/run
  identifier, horizon in the user-facing day unit (reverse of ADR-0007's conversion — `horizon`
  168/360/720 → "7/15/30 days", falling back to showing the raw `horizon` value with its unit
  undetermined if it doesn't match one of the three known conversions, never guessing), naive-first
  baseline metric(s), candidate-model metric(s), DM verdict and p-value (per split, or the same
  aggregation FHS-003 chose — must match FHS-003's actual shipped granularity, not invent a second
  one), and the fixed caveat sentence below verbatim. `run_detail`'s existing handler calls this
  function and passes the result to the template as `shareable_summary_text`.
- `services/dashboard-web/src/app/templates/_shareable_summary.html` (new partial, `{% include %}`-ed
  from `run_detail.html` near FHS-003's panel) — a `<textarea readonly>` pre-filled with
  `shareable_summary_text` plus a "Copy" button. No new JS framework: either a minimal inline
  `<script>` calling `navigator.clipboard.writeText` (same "small inline `<script>`" precedent
  `run_new.html`'s RSS-001/002 already established) or an HTMX-only affordance if the dev finds a
  no-JS way to trigger a browser copy that actually works — inline-`<script>` fallback is
  acceptable and matches existing precedent.
- The `<textarea>` is `readonly` and the caveat sentence is generated by the same server-side
  function as the rest of the text — no client-editable field, no UI path (including via the
  textarea itself, since it is `readonly`) can strip or alter the caveat before copying.

**The exact caveat sentence** (verbatim, from the backlog — wording may only be adjusted if
meaning is fully preserved, and any adjustment must be justified in this ticket's Review notes):

> This is a backtested validation result, not a forecast of future performance. Under this
> platform's own published research, no machine learning model has beaten a naive statistical
> baseline in a stable, significant way at any tested horizon — treat any deviation shown here as
> unproven until independently reconfirmed.

**DRY check**: grep `services/dashboard-web/src` for `clipboard`/`readonly` — expect no existing
copy-to-clipboard affordance (confirmed: this is the first one). No existing "build shareable text"
function exists to reuse; this ticket creates the one function, imported wherever else this need
might arise in the future rather than duplicated.

## Implementation acceptance criteria (carried over from the backlog story)

- A "copy summary" affordance renders a fixed-format text block containing: dataset/run identifier,
  horizon in the user-facing day unit, naive-first baseline metric(s), candidate-model metric(s),
  DM verdict and p-value, and the fixed caveat sentence verbatim (or a documented, meaning-preserving
  equivalent).
- The caveat sentence is not editable/removable from the copied text through any UI path in this
  story (the `<textarea>` is `readonly`; no form submits a modified version of it back).
- No server-side persistence of the exported text is introduced (pure render-and-copy) — confirmed
  by reading the diff for any new storage/DB/session write.
- Copy vocabulary matches FHS-003's constraint — no "prediction"/"forecast"/"signal"/"target"/
  "recommendation" anywhere except inside the caveat sentence's own required wording ("not a
  forecast of future performance" — the word "forecast" appearing *inside the caveat itself,
  negating it*, is the one permitted exception; the test below must distinguish this from a banned
  affirmative usage).

## Test acceptance criteria (test-first, per this ticket's own instruction above)

- Unit test for `build_shareable_summary_text` (pure function, no HTTP) against a fixture
  `RunDetailResponse`/`splits` list — asserts the returned text contains: the real dataset/run
  identifier, the real naive and model metric values, the real DM verdict/p-value, and the caveat
  sentence verbatim (exact string match, not a substring/keyword check — this is the regression-proof
  test the ticket's own instruction calls for).
- A second fixture case using `horizon=168` asserts the text shows "7 days" (or the exact documented
  day-label wording chosen); a fixture with a `horizon` not matching 168/360/720 asserts the raw
  `horizon` value is shown without a fabricated day label (per ADR-0007's own "no silent
  generalization" note).
- Route-level test asserting `GET /runs/{run_id}` includes the `<textarea>` with the summary text
  when splits exist, and that the banned-positioning-words scan (extended, not new) permits only the
  caveat's own negated "forecast" usage and flags any other occurrence.
- A test asserting the caveat sentence cannot be found rendered with any word altered/dropped
  compared to the fixed string constant — protects against a future edit silently weakening it.
