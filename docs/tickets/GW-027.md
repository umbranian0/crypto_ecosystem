# GW-027 — Proxy: `POST /ingestion/connectors/{source}/cancel`

Sprint: docs/sprints/sprint-23.md. Backlog: docs/product/backlog-crawl-lifecycle-control.md.
Status: **done**
Depends on: INGEST-024 (the real downstream endpoint this proxies).

## Analysis

Covers the backlog's GW-027 story. `services/gateway-api/src/app/routers/ingestion.py` already proxies
`POST /ingestion/connectors/{source}/run`, `GET /ingestion/datasets`,
`GET /ingestion/datasets/{source}/series`, `GET /ingestion/connectors/{source}/status` — all tenant-
authenticated, all via the same `get_authenticated_tenant` → `build_downstream_headers` →
`_call_downstream`/`_raise_for_error` flow (`GW-019`/`GW-020`/`DASH-109`/`GW-023`/`GW-024`). This is a
thin, single-file, low-risk addition following that exact precedent — `dashboard-web`'s stop button
(Sprint 24, `DASH-116`) has nothing to call without it.

## Design

**File touched**: `services/gateway-api/src/app/routers/ingestion.py` only — no new module (this router
already exists and every sibling route lives here; a new cancel route is one more function in the same
file, not a new file, matching `GW-020`/`DASH-109`/`GW-023`'s own precedent of extending this file
rather than creating a second one for the same downstream service).

**DRY check**: reuses `get_authenticated_tenant`, `build_downstream_headers`, `_call_downstream`,
`_raise_for_error` (the last two imported from `app.routers.runs`, already imported at the top of this
file) exactly as every other route here does — no new auth mechanism, no new transport-error pattern, no
local Pydantic response model (the downstream `202`/`404`/`409` body is forwarded unmodified as a plain
`dict`, matching `run_connector`'s own pass-through shape in this same file).
