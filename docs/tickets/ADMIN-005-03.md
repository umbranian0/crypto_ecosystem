## Analysis
Tenant-session-gated page. Uses `DownstreamHeadersDep` (tenant session; redirects to /login on 401), NOT `OperatorTokenHeaderDep`. Raw key never stored in SessionStore, logs, URLs or redirects.

## Design
- New router `routers/api_keys.py` (mounted in main.py): `GET /api-keys` (list page), `POST /api-keys` (mint; render the existing `_one_time_reveal.html` partial directly from the POST response, `label="API key"`, name = created time/short id, `continue_url="/api-keys"`, continue text "Back to My API Keys"; no redirect-with-key; response `Cache-Control: no-store`), `POST /api-keys/{key_id}/revoke` (HTMX row fragment, follow `_tenant_row.html` precedent; 404/409 render an inline message fragment, never a stack trace).
- Templates: `api_keys.html` (extends base) and `_api_key_row.html`. Revoked rows greyed with revoked timestamp; current key's revoke button disabled, labelled "key in use by this session". Nav link "API Keys" in base.html in the tenant-session nav only. Copy: validation-run credentials only; explains the flow (mint new, copy it, log out, log in with the new key, revoke the old one). No prediction/signal wording.
- DRY check: grep users of `_one_time_reveal.html` and `settings_tenants.py`'s revoke fragment; reuse the partial and the row-fragment pattern; no second reveal template.
