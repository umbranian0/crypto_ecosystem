# UAT-013 — Real heading elements for chart section titles

**Module**: `services/dashboard-web`. **Depends on**: UAT-004 (file-ordering on the same three chart
partials only).

## Analysis
Story: `docs/product/backlog-uat-findings.md` UAT-013. `_error_chart.html`, `_dm_verdict_chart.html`,
`_forecast_horizon_summary_panel.html`'s `<p class="chart-title">` become real `<h2>`/`<h3>` elements
consistent with `run_detail.html`'s existing heading hierarchy, styled via the existing `chart-title`
class unchanged (no visual regression).

## Design
Pattern: none new. Files touched: the three named partials only. Check `run_detail.html`'s existing
`<h1>`/`<h2>` structure first to pick the correct level (partials nested under a section likely already
headed by an `<h2>` — partials should be `<h3>` in that case, not `<h2>`, to avoid a level skip).
**DRY check note**: all three partials currently duplicate the same `<p class="chart-title">{{ title }}</p>`
pattern — since this is the third occurrence, consider extracting a small `_chart_title.html` macro/
include if it doesn't complicate diffs unnecessarily; otherwise three consistent inline edits are
acceptable since the class/behavior stays identical (Tech Lead's call at review time).

## Implementation acceptance criteria
- [x] All three partials' titles render as real heading tags (h2/h3, whichever is consistent with the
      surrounding hierarchy), same CSS class, no visual change. Implemented as `<h4>`, not `<h2>`/`<h3>`:
      the three partials are `{% include %}`-ed inside `run_detail.html`'s existing `<h3>Per-split
      validation results</h3>` section, so `<h4>` is the level that avoids a heading skip (the ticket's
      own Design section anticipated this exact reasoning for a "likely already `<h2>`" surrounding
      section, adjusted here for the real `<h3>` surrounding section).
