# UAT-009 — Pagination controls on runs list page

**Module**: `services/dashboard-web`. **Depends on**: UAT-008 (file-ordering on `runs_list.html` only).

## Analysis
Story: `docs/product/backlog-uat-findings.md` UAT-009. **Verified at ticket-breakdown time**: DASH-122
(`docs/tickets/DASH-122.md`, done) already fixed the *silent-truncation* bug for `runs_horizon_summary`/
`runs_trend` via a `_fetch_all_runs` paging helper — it deliberately left `runs_list` (`DASH-005-01`)
untouched, since that route already forwards caller-supplied `limit`/`offset` unmodified by design. That
means the backend contract UAT-009 needs (server-side `limit`/`offset`/`total`) already exists on
`GET /runs` via `gateway-api`'s `GW-016` proxy of `validation-service`'s `VS-022` — this story is UI only,
confirmed, no backend change needed. `runs_list` (`services/dashboard-web/src/app/routers/runs.py`) today
parses `body["items"]` but does not pass `limit`/`offset`/`total` to the template — that's the actual gap
to close.

## Design
Pattern: none new. Files touched:
- `services/dashboard-web/src/app/routers/runs.py` — `runs_list` passes `limit`, `offset`, `total` (from
  the response envelope) to the template alongside `runs`.
- `services/dashboard-web/src/app/templates/runs_list.html` — "Previous"/"Next" links computed from
  those values, linking to `/runs?limit=<L>&offset=<prev/next>`.
**DRY check note**: `runs_list`'s existing caller-supplied `limit`/`offset` forwarding (DASH-005-01) is
reused unmodified — no new pagination backend logic, only reading the same envelope's `total` field this
route already receives but currently discards.

## Implementation acceptance criteria
- [x] `runs_list.html` renders Previous/Next links computed from the response envelope's
      `limit`/`offset`/`total`. Closed by `runs_list` (`services/dashboard-web/src/app/routers/runs.py`)
      passing `page_limit`/`page_offset`/`page_total` (read from `body["limit"]`/`["offset"]`/`["total"]`)
      to `runs_list.html`, which renders a `<nav class="runs-pagination">` with the two links.
- [x] "Previous" absent/disabled on first page (`offset == 0`); "Next" absent/disabled when
      `offset + limit >= total`. Verified by `test_runs_list_pagination_next_link_present_when_more_pages_exist`
      / `test_runs_list_pagination_next_absent_on_last_page`.
- [x] No client-side re-sort/re-filter introduced.
- [x] No backend change (confirmed — DASH-122 already covers the underlying data-completeness concern
      for the other two routes; `runs_list` already had correct server-side pagination support, only
      lacked UI).
