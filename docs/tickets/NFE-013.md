## Design
No new pattern (pure data contract). File touched: `libs/naive_first_engine/src/naive_first_engine/report_schema.py` only, plus `tests/test_report_schema.py` (new file). DRY check: grep `report_schema.py` first — docstring only. Also grep `dm_test.py` for NFE-011's interim `DMResult` — this ticket re-homes/imports that shape rather than redefining it from scratch (DRY across files within the module).

Plain dataclasses (no Pydantic needed — avoids adding a dependency not already justified elsewhere, keeps "zero framework dependency" simple): `SplitBoundaries` (train/purge/test start-end, from NFE-002/003's `Split`), `MetricSet` (mae, rmse, smape, mase, da, f1, oos_r2), `DMResult` (statistic, p_value, verdict — matching or importing NFE-011/012's shape), composite `SplitResult` bundling all three.

## Implementation acceptance criteria
- [x] `SplitBoundaries`, `MetricSet`, `DMResult`, `SplitResult` all defined and typed in `report_schema.py`.
- [x] `SplitResult`'s fields are a superset-or-equal shape of solution-design.md section 4's `split_results` columns (no field silently dropped). Mapping: `run_id`/`split_index` are direct fields; `train_start/end`/`purge_start/end`/`test_start/end` live in `SplitResult.boundaries` (`SplitBoundaries`); `model_mae/rmse/da/f1`/`naive0_mae/rmse/...` live per-baseline in `SplitResult.baseline_results[name].metrics` (`MetricSet`, which is a superset of the four columns literally named — it also carries `smape`/`mase`/`oos_r2` per the ticket's required metric set); `dm_statistic/pvalue/verdict` live in `SplitResult.baseline_results[name].dm_result` (`DMResult`). The DB's `id` surrogate primary key is intentionally not modeled (assigned at persistence time, not a domain property) — documented in the module docstring.
- [x] `report_schema.py` has zero dependency on `splitting.py`/`baselines.py`/`metrics.py`/`dm_test.py` internals beyond the types they return (pure output contract). Only import from those four modules is `from naive_first_engine.dm_test import DMResult` (a type, re-exported, not redefined). `SplitBoundaries` mirrors `splitting.Split`'s shape but is defined independently (frozen, no import of `splitting.py` at all) — rationale documented in its docstring.
