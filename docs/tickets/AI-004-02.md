# AI-004-02: `run_new.html` conversational widget — suggested values, visibly distinct, additive only

Depends on AI-004-01 (`POST /assistant/configure-run`, `ConfigureRunResult`/`RunFieldSuggestion`,
`_configure_run_suggestions.html` plumbing). Reuses AI-004-01's route/response shape unchanged; this
ticket is template/frontend-only.

## Analysis

Covers AI-004's remaining acceptance criteria:
- Client-side/form-assist layer only — pre-fills/suggests values for `run_new.html`'s existing fields, no
  second submission path, no second `RunRequest` construction site.
- Suggestions rendered as "suggested value based on your answer, please confirm," never silently populated
  as if a standard default (preserves DASH-006's "no pre-filled defaults" rule).
- The user always sees and can edit final values before submitting — no auto-submission from the
  conversational flow.
- Degrades to the existing plain form (unchanged) if the model call fails.

## Design

**DRY check**: read `run_new.html` in full (already read for this sprint's planning) and
`services/dashboard-web/src/app/templates/assistant.html`/`_assistant_answer.html` (AI-003's HTMX-swap
fragment precedent, `DASH-110`'s `_crawl_trigger_result.html`/`_report_trigger_result.html` pattern). The
existing form has no conversational widget today; nothing to extend, only to add additively.

**Files touched (scoped to `services/dashboard-web` only)**:
- `services/dashboard-web/src/app/templates/run_new.html` — add an optional, collapsed-by-default
  "Get help filling this out" section above the form: a single free-text `<textarea>` ("Describe what
  you're trying to validate, in plain language") plus a "Get suggestions" button that HTMX-posts to
  `/assistant/configure-run` and swaps in `_configure_run_suggestions.html` into a dedicated `<div
  id="configure-run-suggestions">` — the same HTMX-fragment-swap convention `assistant.html`/DASH-110
  already established, not a new mechanism. This section is visually and structurally separate from the
  `<form id="run-form">` element (its own `<div>`, not inside the form's submit path) — HTMX-posting to
  `/assistant/configure-run` is not a form `submit` event and never triggers `run-form`'s own `submit`
  listener or `action="/runs/new"`.
- `services/dashboard-web/src/app/templates/_configure_run_suggestions.html` (finished here, plumbing-only
  version from AI-004-01) — for each returned `RunFieldSuggestion`, renders: the field's plain-language
  label, the suggested value, and an "Apply suggestion — please confirm" button (not a checkbox
  auto-applied) that, on click, copies the value into the matching `run_new.html` input via a small inline
  script and adds a visible `.suggested-value-applied` badge/label next to that field reading "Suggested
  value applied — please review before submitting" (a text label styled distinctly from the plain
  `placeholder`/typed-value state, e.g. a `<span class="suggestion-badge">` — never a value that renders
  indistinguishably from a normal filled-in field). The field's `value` attribute is set by this explicit
  user click only — never by the page load, never by `_configure_run_suggestions.html`'s own render.
  When `degraded` is true (or the response returns no suggestions), renders a fixed "Suggestions are
  currently unavailable — you can still fill out the form below yourself." message, no error, no
  broken layout.
- `services/dashboard-web/src/app/routers/assistant.py` (if not already complete from AI-004-01) — confirm
  the fragment render path matches the finished `_configure_run_suggestions.html` contract.

**Design pattern**: none newly introduced (server-rendered HTML + HTMX swap is the existing convention,
implementation-plan.md section 7 does not call for a new pattern here).

  widget shows the same "Suggestions are currently unavailable" message and the plain `run-form` below it
  remains fully interactive and submittable — proven by `test_configure_run_route_returns_200_when_model_call_fails`
  plus this ticket's new degraded-fragment tests. Note: no client-side HTMX `hx-on::response-error`
