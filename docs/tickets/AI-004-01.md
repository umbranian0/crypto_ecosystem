# AI-004-01: Conversational configure-run backend — dedicated route + suggestion generation

**Status: done** — implemented, tested (18 new tests, 378 passed / 0 failed for the full
`services/dashboard-web` suite), self-reviewed. Documentation criterion for `README.md`'s AI-assist
section is explicitly deferred to AI-005 per this ticket's own Documentation section.

## Analysis

Covers AI-004's acceptance criteria (`docs/product/backlog-ai-integration-ux.md`, search "AI-004") for
the model-calling half of the story:
- A new, dedicated model-call route, never fused into `POST /runs/new` (ADR-0011, Decision 2 of
  `docs/sprints/sprint-51.md`).
- The helper never suggests/implies disabling the purge gap or the naive baselines.
- A fixed test asserts the helper's own generated copy never contains a banned term
  (`signal`/`buy`/`sell`/`profit`/`trade`/`recommendation`) and never claims a specific value is
  "optimal"/"best"/"correct".
- Graceful degradation: an unconfigured/failed model call must return a response the frontend (AI-004-02)
  can render as "suggestions unavailable," never a 5xx or a hang.

Constrained by ADR-0011's binding recommendation: hosted open-weights API via `libs/ai_assist`'s
`AssistClient`/`get_assist_client()` — reused verbatim, no second client, no local Ollama.

## Design

**DRY check (performed before writing code)**: read `services/dashboard-web/src/app/assistant/{generation.py,
fact_check.py, prompt_template.py}` and `routers/assistant.py` in full (AI-003's shipped code). Findings:
- `naive_first_ai_assist.client.get_assist_client()`/`AssistClient`/`AssistClientError` already exist —
  reuse unchanged, do not build a second client.
- `app.assistant.fact_check.contains_banned_term` already exists in this same service — reuse it directly
  (this is same-service reuse, not the cross-service-copy precedent AI-003's own docstring discusses; that
  precedent only justifies a *fresh* list when duplicating across services, it does not justify duplicating
  within one service). AI-004 additionally needs an "no optimal/best/correct claim" check that
  `fact_check.py` does not have — add `contains_overstated_certainty_claim` to `fact_check.py` (extending
  that existing module, not a new banned-term module) since it is the same "guardrail check on generated
  copy" concern `contains_banned_term` already owns.
- `generation.py`'s one-retry-then-fallback shape (`_MAX_ATTEMPTS = 2`, catch `AssistClientError`, run a
  guard on the result, fall back to a fixed unavailable message) is the established pattern for a hosted
  model call in this service — reused structurally for the new `generate_run_suggestions`, not
  reinvented.
- `prompt_template.py`'s "versioned, checked-in template, only fields already available to this route"
  convention is reused for the new prompt.

**Files touched (scoped to `services/dashboard-web` only)**:
- `services/dashboard-web/src/app/assistant/fact_check.py` — add `contains_overstated_certainty_claim`
  (checks for `optimal`/`best`/`correct` used to describe a suggested configuration value; module-level
  constant `OVERSTATED_CERTAINTY_TERMS`).
- `services/dashboard-web/src/app/assistant/configure_run_prompt.py` (new) — `build_configure_run_prompt
  (answer: str) -> str`, versioned instructions forbidding banned terms, forbidding any claim that a
  specific purge gap/window/horizon value is "optimal"/"best"/"correct", forbidding any suggestion to
  omit/shorten the purge gap or omit the naive baselines, and instructing the model to respond in a fixed
  `field: value` line format for exactly the fields this story is scoped to suggest:
  `horizon`, `purge_gap_hours`, `train_window`, `test_window`, `step`, `label`. (`dataset_id` and
  `dataset_reference_*` are explicitly NOT suggested — the model has no knowledge of the tenant's actual
  ingested datasets, so suggesting a `dataset_id`/source would be a fabricated claim; this is a real scope
  narrowing from the sprint's own "Recommended shape," disclosed here, not silently reduced.)
- `services/dashboard-web/src/app/assistant/configure_run.py` (new) — `RunFieldSuggestion` dataclass
  (`field: str`, `value: str`, `explanation: str`); `parse_suggestion_lines(text) -> list[RunFieldSuggestion]`
  (parses the fixed `field: value` format, silently skips any line for a field outside the fixed allowed
  set of 6 above — never lets the model introduce an unexpected field name into the response); `generate_
  run_suggestions(answer: str, client: AssistClient | None) -> ConfigureRunResult` (dataclass:
  `suggestions: list[RunFieldSuggestion]`, `degraded: bool`) — mirrors `generation.py`'s retry-then-
  fallback shape, runs both `contains_banned_term` and the new `contains_overstated_certainty_claim` guard
  on the raw model text before parsing (reject-and-retry-once, then degrade, same as AI-003).
- `services/dashboard-web/src/app/routers/assistant.py` — add `POST /assistant/configure-run` (`answer:
  str = Form(...)`), calling `generate_run_suggestions(answer, get_assist_client())`, rendering a new
  `_configure_run_suggestions.html` fragment (built in AI-004-02, this ticket returns the dataclass/
  fragment plumbing only — a minimal fragment with just the raw suggestion list is acceptable here, refined
  visually in AI-004-02). Extends the existing `assistant.py` module (this is the same "AI-assist surface"
  concern the module docstring already claims, not a second router file) — update that module's docstring
  to disclose the new route, per this repo's per-file docstring convention.

**Design pattern**: none of implementation-plan.md section 7's named patterns (Strategy/Repository/
Adapter/Factory/Observer/DI/Template Method) is newly introduced here — `AssistClient` is already the
Adapter (`libs/ai_assist`), reused unchanged; this ticket is glue code (prompt building + parsing + a thin
route), same shape as AI-003's own ticket.

## Implementation acceptance criteria

- [x] `POST /assistant/configure-run` never constructs a `RunRequest` and never calls `POST /runs` — grep
  confirms no `RunRequest(` in this ticket's diff.
- [x] The route is reachable only via its own path; `routers/runs.py` has zero diff (`git status
  --porcelain` empty for that file).
- [x] `generate_run_suggestions` returns `degraded=True` (never raises) when `get_assist_client()` returns
  `None`, when the model call raises `AssistClientError` on both attempts, or when both attempts fail the
  banned-term/overstated-certainty guard.
- [x] `parse_suggestion_lines` never emits a suggestion for a field outside `{horizon, purge_gap_hours,
  train_window, test_window, step, label}` — in particular, never `dataset_id` or any `dataset_reference_*`
  key.
- [x] The prompt template's instructions explicitly forbid suggesting disabling/omitting/shortening the
  purge gap or omitting the naive baselines (checked by a fixed-string test reading the actual template
  content, not just trusting the model to comply at runtime — see Test section).

## Test acceptance criteria

- [x] Unit tests for `parse_suggestion_lines` (well-formed input, unexpected field name dropped, malformed
  line dropped, empty input).
- [x] Unit test proving `contains_overstated_certainty_claim` flags "optimal"/"best"/"correct" used
  adjectivally about a value, and does not false-positive on unrelated uses of those words is not required
  (simple substring match, matching `contains_banned_term`'s own precedent) — a plain substring check is
  sufficient and consistent with the existing guard's own simplicity.
- [x] A test proving a model response containing a banned term never reaches the caller as a suggestion
  (mocked `AssistClient` returning banned text, asserting the fallback/degraded path is taken).
- [x] A test proving a model response claiming a value is "optimal" never reaches the caller as a
  suggestion (same shape as above, for the new guard).
- [x] A fixed test asserting `configure_run_prompt.py`'s own instructions text contains the phrases
  forbidding disabling/omitting the purge gap and omitting the naive baselines (a static content check,
  same "audit exactly what was asked of the model" precedent AI-002's prompt template test established).
- [x] A test proving `generate_run_suggestions(..., client=None)` returns `degraded=True` with no
  exception.
- [x] A test proving the route returns `200` (not `5xx`) even when the model call fails.
