# VS-030 — `validation-service` dataset assembly for a multi-source feature set (MDF-003)

**Status: implemented (dev agent), pending Tech Lead review/QA sign-off.**

**Module**: `services/validation-service` (+ shared shape additions in `libs/common/src/naive_first_common/contracts.py`, same precedent as VS-029/VS-022). No `libs/naive_first_engine` changes.
**Depends on**: none within this sprint (MDF-001/MDF-002 closed Sprint 31 — ADR-0008/ADR-0009, both `status: accepted`). MDF-004/MDF-005 explicitly deferred, not touched here.

## Analysis

Covers `docs/product/backlog-multimodal-dataset-fusion.md` MDF-003's acceptance criteria in full (search
"### MDF-003"). Binding constraints, not re-derived here:
- ADR-0008: the join lives inside `validation-service`, as a new `feature_dataset.py` sibling to
  `dataset_source.py`, calling `CompositeDatasetSource.load()` once per `{source, field}` reference
  (reuse, not reimplementation of the four existing dispatch branches). No new service.
- ADR-0008(b): per-connector lag table — price-onto-price zero additional lag; on-chain 24h conservative
  floor keyed off `fetched_at`; sentiment zero additional buffer beyond substituting `fetched_at` for
  `created_utc`.
- ADR-0009: alignment is forward-fill per source-pair, keyed off `fetched_at` (never nominal timestamp),
  `missing_timestamp_policy` is a required request field (`drop_row` / `forward_fill_exhausted_as_null_then_drop`
  / `exclude_source`), no default, `422` if omitted. Target series' own `DatetimeIndex` stays authoritative
  and is what `generate_splits` receives, unchanged in *meaning* (still the target's own index, possibly a
  subset if rows were dropped by policy), strictly after alignment, before any split boundary is chosen.

**Real, disclosed gap found during ticket-breakdown research, binding on this ticket's scope**:
`services/ingestion-service`'s `GET /datasets/{source}/series` (`src/app/routers/datasets.py`) returns only
`timestamps`/`values` — it does **not** expose each row's `fetched_at`, even though `fetched_at` is stored
per-row in that service's own tables (`ConnectorRecordRepository`'s `add_*_records` methods all require it,
per `postgres_repository.py`). Extending that endpoint's response shape is a change to `services/ingestion-service`,
a different module — out of this ticket's file scope per this repo's own "a ticket spanning two modules
should be two tickets" rule, and not authorized by this sprint (sprint-36.md assigns VS-030 only). Per
ADR-0009 ("never use a value's nominal timestamp as a stand-in for when it became knowable") and CLAUDE.md's
no-silent-inference rule, this ticket must **fail closed** for any feature reference that resolves to
`IngestionServiceDatasetSource` (a `{"source": ...}` reference): it cannot honestly align that source without
a real `fetched_at`, so it raises a clear, disclosed error naming the gap rather than approximating with the
nominal timestamp. Real per-row `fetched_at` alignment is fully implemented and tested for the two dataset
shapes that can carry it today — inline payloads and object-storage CSVs — both extended with an optional
third `fetched_at` column/key (opt-in, backward compatible: absent for a plain 2-column payload). A follow-up
ticket to extend `ingestion-service`'s series endpoint with `fetched_at` is flagged in Documentation below,
not silently left for a future session to rediscover.

## Design

**Pattern**: Adapter (existing `DatasetSource`, reused unmodified) + a new thin assembly layer above it —
no new pattern from implementation-plan.md section 7 is introduced; `feature_dataset.py` is a plain
composition step, matching ADR-0008's own framing ("sits one layer above `CompositeDatasetSource`, not
inside it").

**DRY check**: grepped `services/validation-service/src/app/dataset_source.py` and `routers/runs.py`.
Reused, not duplicated: `CompositeDatasetSource.load()` (called once per feature reference, exactly as
ADR-0008 specifies), `InlineOrLocalFileDatasetSource._build_series`/`_read_csv`/`_parse_inline` (extended
in place for the optional third `fetched_at` column, not re-implemented), `DatasetSourceError`'s hard-fail
convention (new `FeatureDatasetError` subclasses it, same catch-and-fail-closed shape `runs.py`'s existing
`try/except Exception` already uses — no second error-handling path). `IngestionServiceDatasetSource`'s
existing `httpx.Client`/`base_url`/`tenant_id` constructor pattern is reused for the new connector-status
fail-closed check (same client, same header convention), not a second HTTP client.

**Files touched** (all within `services/validation-service`, one new + four edited, plus the shared
contracts file):

1. **`src/app/dataset_source.py`** (edit): extend `InlineOrLocalFileDatasetSource._parse_inline`/`_read_csv`/
   `_build_series` to optionally carry a third `fetched_at` value per row — inline dict form gains an
   optional `"fetched_at"` key (list, same length as `timestamps`/`values`); inline list-of-rows form
   accepts an optional 3rd element per row; CSV form accepts an optional 3rd column. `LoadedSeries` gains
   a new field `fetched_at: pd.DatetimeIndex | None = None` (default `None`, same defensive-default
   precedent as `warnings`) — when the input has no third column/key, `fetched_at` stays `None`, and
   nothing about `series`/`warnings` changes for any existing 2-column caller (target-series loading is
   byte-unchanged). `ObjectStorageDatasetSource` reuses the same extended `_read_csv`/`_build_series` (no
   new parsing code, matching this file's existing DRY convention). `IngestionServiceDatasetSource` is
   **not** extended (the gap above) — its returned `LoadedSeries.fetched_at` stays `None` always, which is
   exactly what makes `feature_dataset.py`'s fail-closed check correct without any extra flag.
2. **`src/app/feature_dataset.py`** (new): `FeatureDatasetError(ValueError)` (subclasses `DatasetSourceError`
   is not appropriate since this module doesn't import from `dataset_source` circularly by class hierarchy —
   define as a sibling `ValueError` subclass, same shape/spirit). `MISSING_TIMESTAMP_POLICIES = {"drop_row",
   "forward_fill_exhausted_as_null_then_drop", "exclude_source"}`. `FEATURE_SOURCE_LAG_HOURS` dispatch table
   keyed by source-name prefix (`"blockchain_info_"` → 24, everything else including `"binance_price_"`/
   `"reddit_"` → 0 — sentiment's "no separate buffer" and price's "zero additional lag" both collapse to the
   same 0-hour constant per ADR-0008/0009, disclosed in the module docstring with the worked-example numbers
   cited). `ConnectorStatusChecker` protocol (`check(tenant_id: str, source: str) -> None`, raises
   `FeatureDatasetError` if not ready) + `IngestionServiceConnectorStatusChecker` implementation calling
   `GET /connectors/{source}/status` (reusing `IngestionServiceDatasetSource`'s client/header/base_url
   pattern) — treats any status other than `"completed"` (i.e. `"running"`/`"queued"`/`"failed"`) as
   fail-closed rejection, naming the concrete status in the error. `FeatureDatasetAssembler.assemble(
   target_index: pd.DatetimeIndex, feature_references: list[dict], missing_timestamp_policy: str,
   dataset_source: DatasetSource, connector_status_checker: ConnectorStatusChecker | None) -> AssembledFeatures`
   (`AssembledFeatures` = frozen dataclass: `index: pd.DatetimeIndex` (target index, minus any rows dropped
   by policy — never a superset of the original target index), `feature_dataframe: pd.DataFrame` (columns
   named `f"{source}.{field}"`, aligned to `index`), `lineage: list[dict]` (`{"source", "field", "lag_hours"}`
   per reference, persisted verbatim), `warnings: list[str]`). Per-reference: (a) if `"source"` key present,
   run the connector-status check first (before loading); (b) `loaded = dataset_source.load(reference)`; (c)
   if `loaded.fetched_at is None`, raise `FeatureDatasetError` naming the reference and stating fetched_at is
   required and unavailable (the disclosed ingestion-service gap surfaces here verbatim for that source type);
   (d) `pandas.merge_asof(direction="backward")` the feature series (sorted by `fetched_at`) onto
   `target_index - lag_hours`, producing one aligned column; (e) apply `missing_timestamp_policy`:
   `"exclude_source"` drops the whole column (not rows) if any alignment gap exists; the other two policies
   mark unaligned cells null, reconciled once across all columns at the end (rows still null after all
   columns are aligned are dropped from `index`/`feature_dataframe` together — target and features drop in
   lockstep, never independently, since the assembled table's index must always equal the (possibly
   trimmed) target index). `FeatureFoldScaler` (small `dataclasses.dataclass`: `fit(train_df: pd.DataFrame)
   -> FittedScaler` computing per-column mean/std **only** over the rows passed in — no global-DataFrame
   statistic is ever computed anywhere in this module; `FittedScaler.transform(df) -> pd.DataFrame`) — this
   is the per-fold-fit preprocessing surface CLAUDE.md's leakage rule requires and MDF-003's own AC names;
   it is not yet wired into any candidate-model inference call (no such consumer interface exists — that's
   MDF-004's explicit, deferred question), but the fit-per-split mechanism and its leakage-safety proof are
   in scope for this ticket and callable directly against `generate_splits`'s output.
3. **`src/app/routers/runs.py`** (edit): after the existing primary `dataset_source.load(request.dataset_reference)`
   call and *before* the existing RSS-004 split-count guardrail (`generate_splits` call), if
   `request.feature_references` is non-empty: validate `request.missing_timestamp_policy` is set (Pydantic
   model validator on `RunRequest` itself handles the `422`, see contracts change below — this is defense in
   depth, not the primary enforcement point) and call `FeatureDatasetAssembler.assemble(series.index, ...)`;
   reassign `series = series.loc[assembled.index]` (never a superset — see Design's ordering note) *before*
   the RSS-004/DH-005/MR-001 guardrails run, so their split-count/zero-split/price-level checks all see the
   post-alignment series, matching ADR-0009's binding ordering constraint exactly. `run_validation_protocol(
   series, config)`'s call site is **not** modified — it still receives only the (possibly trimmed) target
   `series`, never the feature DataFrame; `Naive0`/`NaiveLast` are unaffected by this ticket's changes beyond
   potentially seeing fewer rows if a policy dropped some. `_persist_new_run` gains a `feature_lineage`
   parameter (default `[]`), threaded from `assembled.lineage` when features were requested, `[]` otherwise.
4. **`src/app/dependencies/repositories.py`** (edit): new `FeatureDatasetAssemblerDep`/
   `ConnectorStatusCheckerDep` providers, same DI-seam convention as `DatasetSourceDep` (reuses the same
   `INGESTION_SERVICE_URL` env var `IngestionServiceDatasetSource`'s provider already reads — no new env var
   needed for the checker).
5. **`src/app/repositories/interfaces.py` + `sqlite_repository.py` + `postgres_repository.py`** (edit):
   `ValidationRunRepository.create_run` gains a `feature_lineage: list[dict] = []` parameter (mirrors
   `warnings`'s VS-002/DH-001 precedent exactly — same nullable-JSON-with-`[]`-default column shape);
   `RunRecord` gains a matching field. New Alembic migration `migrations/versions/0009_add_runs_feature_lineage_column.py`
   (sibling to `0008_add_runs_warnings_column.py`, same pattern: nullable JSON, `server_default='[]'`).
6. **`libs/common/src/naive_first_common/contracts.py`** (edit): `RunRequest` gains
   `feature_references: list[dict] | None = None` and `missing_timestamp_policy: str | None = None`, plus a
   Pydantic `model_validator(mode="after")` rejecting (`ValueError`, which FastAPI turns into `422`) any
   request where `feature_references` is non-empty and `missing_timestamp_policy` is `None` or not one of
   the three literal values — this is the primary enforcement point for the "no silent default" hard AC.
   `RunDetailResponse` gains `feature_lineage: list[dict] = Field(default_factory=list)` (same
   defensive-default style as `warnings`) and a derived `has_multimodal_features: bool` (computed in
   `runs.py::get_run`, `bool(run.feature_lineage)` — same one-source-of-truth precedent VS-029 established
   for `has_client_model`, not a second independent flag).

## Implementation acceptance criteria

- [x] AC1: `POST /runs` accepts `feature_references: list[{"source", "field"}]` and requires
  `missing_timestamp_policy` (one of the three literal values) whenever `feature_references` is non-empty —
  `422` with no default applied, verified by a request that supplies features but omits the policy field.
- [x] AC2: the target being validated remains exactly one return `pd.Series`; `run_validation_protocol` is
  called with that series alone (never the feature DataFrame), `Naive0`/`NaiveLast` behavior is unchanged
  except for row count if `missing_timestamp_policy` trimmed rows — `libs/naive_first_engine`'s `Baseline`
  protocol and `dm_test.py` are not imported/modified anywhere in this ticket's diff.
- [x] AC3: alignment is per-source-pair, keyed off each source's `fetched_at`, never a nominal timestamp,
  never a future-dated value (`merge_asof(direction="backward")` against `target_index - lag_hours`
  structurally cannot look forward).
- [x] AC4: alignment runs to completion — producing the final `index`/`feature_dataframe` — strictly before
  `generate_splits`/RSS-004's guardrail is invoked in `runs.py`; the reassigned `series` used for every
  downstream guardrail and for `run_validation_protocol` is the post-alignment series.
- [x] AC5: a feature reference resolving to `IngestionServiceDatasetSource` (no `fetched_at` available)
  fails closed with a clear, disclosed error — never silently approximated using the nominal timestamp.
- [x] AC6: a feature reference naming a connector still `"running"`/`"queued"`/`"failed"` (per
  `GET /connectors/{source}/status`) is rejected before any alignment is attempted.
- [x] AC7: the persisted run record stores `feature_lineage` (source/field/lag per feature), surfaced via
  `RunDetailResponse.feature_lineage`/`has_multimodal_features`, distinguishing a multimodal run from a
  single-series run in the API response.

Design decisions worth flagging for Tech Lead review:
- `"drop_row"` and `"forward_fill_exhausted_as_null_then_drop"` are implemented with genuinely different
  semantics (zero-tolerance exact-match `merge_asof` vs. unbounded backward-fill `merge_asof`) so the three
  `missing_timestamp_policy` values are provably distinguishable in output shape, per the Test acceptance
  criteria's explicit requirement. ADR-0009's own worked-example table's literal `fetched_at` numbers do not
  self-consistently satisfy its own stated alignment rule (documented in `test_feature_dataset.py`'s module
  docstring) — the synthetic fixture used instead is rule-consistent and reproduces the worked example's
  qualitative pattern (first row dropped, later rows forward-filled) under
  `"forward_fill_exhausted_as_null_then_drop"`.
- `ConnectorStatusChecker.check`'s `tenant_id` parameter is effectively unused by the real
  `IngestionServiceConnectorStatusChecker` (tenant is already bound at construction time, mirroring
  `IngestionServiceDatasetSource`'s own precedent) — `FeatureDatasetAssembler.assemble` has no `tenant_id`
  parameter per the ticket's own signature, so it passes an empty string; flagged for Tech Lead awareness, not
  hidden.
