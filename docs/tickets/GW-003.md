# GW-003 — Identity repository interfaces (`TenantRepository`, `UserRepository`, `ApiKeyRepository`)

**Status: done**

## Analysis
Story: GW-003 (Must), depends on GW-002. Constraining docs: implementation-plan.md section 7 (Repository + DI patterns), backlog AC (Protocol-based, `tenant_id`-first except tenant creation, plain frozen dataclass records, mechanically-checked no-`sqlalchemy`-import test). Direct precedent: `services/validation-service/src/app/repositories/interfaces.py` (VS-003) — same structure, same design decisions, applied to the identity schema instead of the validation schema.

## Design
Pattern: **Repository** (interfaces only — GW-004 implements) + **Dependency Injection** seam (`src/app/dependencies/repositories.py` provider stubs, GW-004/005/006 wire concrete providers). File: `src/app/repositories/interfaces.py` (new). DRY check: grep `src/app/repositories/` (only `__init__.py` from GW-001) and `src/app/models.py` (GW-002) before writing — record types mirror `Tenant`/`User`/`ApiKey` field-for-field as plain `@dataclass(frozen=True)` types local to this module (same reasoning as VS-003: reusing SQLAlchemy models directly would pull `sqlalchemy` into this module's import graph transitively).

Method set (binding, backlog AC2):
- `TenantRepository.create_tenant(name) -> TenantRecord` (the one exception to tenant_id-first — a tenant has no id yet), `get_tenant(tenant_id) -> TenantRecord | None`.
- `ApiKeyRepository.create_key(tenant_id, key_hash) -> ApiKeyRecord`, `get_by_hash(key_hash) -> ApiKeyRecord | None` (deliberately **not** tenant_id-first — GW-006's auth check must resolve a key to its tenant, not already know the tenant, so `key_hash` alone is the correct lookup key; document this exception explicitly, same spirit as `tenants` creation's own documented exception), `revoke_key(tenant_id, key_id) -> None`.
- `UserRepository.create_user(tenant_id, email, role) -> UserRecord`, `get_user_by_email(email) -> UserRecord | None` (same exception as `get_by_hash` — email lookup at login time doesn't yet know the tenant).

Both documented exceptions above are the *only* ones — every other method (`revoke_key`, `create_key`, `create_user`) keeps `tenant_id` first per AC2's "no exceptions" for methods where a tenant is already known.

`Protocol`, not ABC — matches VS-003's own precedent, no shared default method needed here either.
