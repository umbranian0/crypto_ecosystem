# RS-005 -- `GET /reports/{id}` retrieval endpoint

Status: done
Backlog: docs/product/backlog-reporting-service.md, RS-005 [Must]
Sprint: Sprint 12
Depends on: RS-002 (parallel-safe with RS-004)

## Analysis

Covers backlog RS-005: a previously generated report's content and metadata, tenant-isolated,
retrievable by id -- so a generated report can actually be retrieved, not just produced and
discarded.

## Design

- Files touched: `src/app/routers/report_retrieval.py` (new -- deliberately its own module,
  disjoint from RS-004's `report_generation.py`, so both tickets can run fully in parallel with zero
  file overlap, matching validation-service's VS-007/VS-008 `runs.py`/`splits.py` split), plus
  `tests/test_get_report_endpoint.py` (new). Both routers are mounted under the same `/reports`
  prefix in `src/app/main.py` -- whichever ticket lands second in `main.py` should append its
  `include_router` call, not remove the other's.
- **DRY check note**: reuses the same `Depends(naive_first_common.get_tenant_context)` seam RS-004
  uses -- no second tenant-resolution mechanism.
- Response on success (`200`): `id`, `run_id`, `report_kind`, `generated_at`, `status`, `content`
  (the rendered HTML).
- A report that does not exist, and a report that exists but belongs to a different tenant, both
  return the same `404` -- `ReportRepository.get_report` already returns `None` for both cases
  (RS-002's own AC), so the handler never distinguishes them, matching VS-007's established
  non-disclosure stance.

## Outcome

Implemented exactly as scoped in Design. Files created:
- `services/reporting-service/src/app/routers/report_retrieval.py` -- new `APIRouter` with a single
  `GET /{report_id}` handler (mounted under `/reports` prefix in `main.py`, so the full route is
  `GET /reports/{report_id}`). Resolves tenant via `Depends(naive_first_common.get_tenant_context)`;
  calls `ReportRepository.get_report(tenant.tenant_id, report_id)` and raises a bare `404` when it
  returns `None`, with no branch distinguishing "doesn't exist" from "wrong tenant" -- the repository
  (RS-002) already collapsed that distinction. Success path returns a local `ReportDetailResponse`
  Pydantic model (`id`, `run_id`, `report_kind`, `generated_at`, `status`, `content`) built from the
  fetched `ReportRecord`, no field renaming/recomputation.
- `services/reporting-service/tests/test_get_report_endpoint.py` -- new. Uses a `FakeReportRepository`
  dataclass (implements the `ReportRepository` Protocol) injected via `app.dependency_overrides`
  (GW-006/GW-007 fake-repository precedent per the ticket's own environment notes), not real
  Postgres. 5 tests: success shape, nonexistent-id 404, cross-tenant-vs-nonexistent 404
  byte-for-byte identity (`response.json() == response.json()`, the ticket's explicit
  non-tautology requirement), owning-tenant-can-see-cross-seeded-report positive control, and a
  missing-tenant-header 401 test (exercises `get_tenant_context`'s existing 401 behavior, not new
  logic added by this ticket).

Files modified:
- `services/reporting-service/src/app/main.py` -- mounts `report_retrieval.router` under the
  `/reports` prefix. RS-004's `report_generation` router did not exist yet at the time this ticket
  landed, so this is the first `include_router` call in the file; RS-004 is expected to append its
  own rather than replace this one (per both tickets' Design sections).
- `services/reporting-service/README.md` -- Status line and Contract paragraph updated to document
  `GET /reports/{id}` (path + method, response fields, 404 non-disclosure behavior); added a Design
  notes bullet documenting the router file split with RS-004.

Test results: `uv run pytest tests/` (run from a temp copy outside the OneDrive-synced tree per this
ticket's environment notes, `libs/common` kept at the same relative position) -- **17 passed, 0
failed** (5 new in `test_get_report_endpoint.py`; the other 12 are RS-001/RS-002/RS-003's
preexisting tests, including the real-Postgres RLS proof in `test_postgres_repository.py`, all still
passing unmodified). `uv.lock` did not change (no new dependency added).

Deviations from ticket text: none. The router's route path is declared as `/{report_id}` (relative)
rather than `/reports/{report_id}` (absolute) inside `report_retrieval.py` itself, with the
`/reports` prefix applied once in `main.py`'s `include_router` call -- this is the standard
FastAPI `APIRouter(prefix=...)` idiom for two routers sharing one prefix (RS-004's
`report_generation` router is expected to do the same), not a deviation from the ticket's
"mounted under the same `/reports` prefix" instruction, just its literal mechanism.

Review and Documentation-acceptance-criteria checkboxes for the Tech Lead's own personal-verification
step are left unchecked per this workflow's own rule -- they are not self-certifiable.
