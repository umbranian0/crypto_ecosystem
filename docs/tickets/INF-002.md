# INF-002 — Redis service in Docker Compose

Status: **done**
Backlog: docs/product/backlog-infra.md, INF-002 [Must]
Sprint: docs/sprints/sprint-06.md, Phase 1 / Track B
Depends on: none

## Analysis

`validation-service`'s `run.completed` publisher is currently an in-process log stand-in
(VS-009). VS-014 (Redis Streams-backed publisher) is blocked on a real, reachable Redis. Per
backlog-infra.md scope decision 3, VS-014 (publisher side only) is unblocked by this ticket alone
— it does not need `reporting-service` (trigger #7, the subscriber side) to exist.

## Design

- `infra/docker-compose.yml` defines a `redis` service (`redis` image per solution-design.md
  section 5), fixed host port mapping (e.g. `6379:6379`).
- **Binding decision (grooming, #10)**: connection env var is a single `REDIS_URL` (e.g.
  `redis://redis:6379/0`), mirroring the existing `DATABASE_URL` single-connection-string
  convention — not separate host/port/db env vars.
- `infra/README.md` states explicitly that this Redis instance unblocks VS-014's publisher-side
  work now, ahead of trigger #7's subscriber side, so a future contributor doesn't read "Redis
  exists" as "the full pub/sub loop is wired end-to-end" (backlog AC4, verbatim requirement).
- Pattern/DRY: same as INF-001 — infra-only, no application code.

## Outcome

Implemented in `infra/docker-compose.yml` (`redis` service, image `redis`, container name
`naive-first-redis`, fixed host port `6379:6379`, healthcheck via `redis-cli PING`), documented in
`infra/.env.example` (`REDIS_URL`, both local-dev and in-Compose forms) and `infra/README.md`
(Redis section, including the explicit VS-014-now/trigger-#7-later scope note).

Verified live: `docker compose -f infra/docker-compose.yml up -d redis` started the container
successfully; `docker exec naive-first-redis redis-cli PING` returned `PONG`; `docker compose ...
ps` shows the container `Up ... (healthy)` with port `0.0.0.0:6379->6379/tcp` published. Container
left running (not torn down) per instructions, since VS-014 and other tickets need it.

Note: `infra/docker-compose.yml` and `infra/.env.example` already existed with a `postgres`
service/vars (INF-001, running concurrently) when this ticket started; the `redis` service and
`REDIS_URL` block were added additively without touching the existing `postgres` content.
