# GW-031 — Proxy `GET /runs/{run_id}/splits/{split_index}/points` through gateway-api

**Module**: `services/gateway-api` only.
**Story**: RAV-007, `gateway-api` half.
**Depends on**: VS-033 (the real endpoint must exist to proxy).
**Blocks**: DASH-129.

## Analysis

Per CLAUDE.md's "no service imports another service's code" rule and this router's own existing
pattern (`services/gateway-api/src/app/routers/runs.py`'s module docstring: "adapt an authenticated
inbound request into exactly one outbound `httpx` call... No split/run/tenant-isolation business logic
is reimplemented here"), this is a pure pass-through addition — same shape as the existing
`GET /runs/{id}/splits` proxy immediately above it in the same file.

## Design

**Design pattern**: none new — this is the same GW-008/GW-016 pass-through pattern already
established in this exact file.

Files touched (scoped to `gateway-api` only):
- `src/app/routers/runs.py` — one new route, `GET /runs/{run_id}/splits/{split_index}/points`,
  forwarding `limit`/`offset` query params unmodified (same as GW-016's `list_runs` forwards
  `limit`/`offset` to `validation-service`'s `GET /runs`), using the same `_call_downstream`/
  `_raise_for_error` helpers every other route in this file already uses.
- Response envelope: a local `SplitPointsResponse` Pydantic model in this router (mirroring
  `RunListResponse`'s own "local envelope, shared item shape" precedent in this same file), with
  `items: list[SplitPointResponse]` importing `SplitPointResponse` from `naive_first_common.contracts`
  (VS-033's new shared model) — never a hand-duplicated field list.

**DRY check note**: grepped this router file before writing — `_call_downstream`/`_raise_for_error`
are the exact two helpers every existing proxy route reuses; this ticket adds no new transport-
handling code.
