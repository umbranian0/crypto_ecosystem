# VS-003 — Repository interfaces: `ValidationRunRepository`, `SplitResultRepository`

**Status: done**

## Analysis
Story: VS-003 (Must), depends on VS-002. Constraining docs: this service's own README ("Data access goes through a Repository layer... so schema-per-service can later become DB-per-service without touching call sites"), implementation-plan.md section 7 (Repository pattern + Dependency Injection pattern, named explicitly for this exact service), backlog decision 2.

## Design
Pattern: **Repository** (interfaces only, no implementation — that's VS-004) + this ticket sets up the **Dependency Injection** seam VS-006/007/008 will use. Files: `src/app/repositories/interfaces.py` (new — `ValidationRunRepository`, `SplitResultRepository` as `abc.ABC` or `typing.Protocol`; use `Protocol` for consistency with `naive_first_engine.baselines.Baseline`'s own `typing.Protocol` style, unless ABC is needed for a shared default method, in which case document why). DRY check: grep `src/app/repositories/` (only `__init__.py` exists from VS-001) and `src/app/models.py` (VS-002) before writing — reuse VS-002's `Run`/`SplitResult` types (or plain dataclasses mirroring their fields, if keeping the interface free of any SQLAlchemy import is preferred — see AC3) as the method return/input shapes, don't invent a third shape.

Method set (binding, from backlog AC1):
- `ValidationRunRepository`: `create_run(tenant_id, dataset_id, horizon, purge_gap_hours, split_config) -> RunRecord`, `get_run(tenant_id, run_id) -> RunRecord | None`, `update_run_status(tenant_id, run_id, status, *, completed_at=None, failure_reason=None) -> None`.
- `SplitResultRepository`: `add_splits(tenant_id, run_id, splits: list[SplitResultRecord]) -> None`, `get_splits(tenant_id, run_id) -> list[SplitResultRecord]` (ordered by `split_index`, per VS-008 AC3 — decide here whether ordering is the repository's job or the caller's, and document the choice; recommend: repository's job, so every caller gets it right by construction).

Every method's first parameter (after `self`) is `tenant_id` — no exceptions, per AC2.

## Implementation acceptance criteria
- [x] `ValidationRunRepository` and `SplitResultRepository` exist as ABCs/Protocols in `src/app/repositories/interfaces.py` with the method set above. (Implemented as `typing.Protocol`, per the Design section's stated preference for `Baseline`-style consistency — no shared default method needed, so ABC wasn't warranted.)
- [x] Every method signature requires `tenant_id` as an explicit parameter.
- [x] No import of a concrete storage driver (`sqlite3`, `sqlalchemy.engine`, `psycopg`, or even `sqlalchemy` itself if avoidable) appears in `interfaces.py` — decision taken: plain `@dataclass(frozen=True)` record types (`RunRecord`, `SplitResultRecord`), local to `interfaces.py`, field-for-field mirrors of VS-002's `Run`/`SplitResult`. `interfaces.py` imports only `typing`, `dataclasses`, `datetime` — no `sqlalchemy` anywhere in its import graph.
- [x] `src/app/dependencies/repositories.py` (new) declares FastAPI `Depends()` provider stubs typed against these interfaces (concrete wiring to VS-004's implementation happens in VS-004/VS-006, this ticket just establishes the DI seam per implementation-plan.md section 7).
