## Analysis

Covers backlog story AI-002 (`docs/product/backlog-ai-integration-ux.md`) in full: a completed
validation run's report gains an LLM-produced plain-language paragraph summarizing that run's own
MAE/RMSE/DA/DM-verdict numbers, fed only already-persisted data, fact-checked before it ships, and
gracefully degrading to today's table-only report on any failure.

Binding constraints (verify, don't relax):
- ADR-0011: hosted open-weights inference API over HTTPS only. No local Ollama/llama.cpp, no new
  container, no `infra/docker-compose.yml` service.
- ADR-0011: no `libs/ai_assist` — prompt-building/model-calling logic stays inline in
  `services/reporting-service/src/app/narrative/`.
- ADR-0011's "Safe vs unsafe extension points": the model call must be triggered from RS-006's
  existing `run.completed` Redis Streams subscriber only — **never** from `POST /reports/generate`'s
  synchronous HTTP handler. `POST /reports/generate` stays exactly as it behaves today (table-only,
  no narrative, no added latency) since it has no latency budget carved out for a model round-trip.
  This means `generate_validation_audit_report` (`app/generation.py`) must gain narrative generation
  as something the **subscriber opts into**, not something that fires for every caller.
- Backlog AI-002 acceptance criteria (all binding):
  1. Narrative step lives in `ValidationAuditRenderer` (Factory pattern already in place), fed only
     the run's own persisted `split_results`/aggregate metrics already fetched for the table — no new
     data source, no live call to any external prediction API.
  2. Prompt template is a versioned, checked-in artifact (a `.py` module is fine, matching this
     service's existing no-Jinja-for-logic convention) — not a hidden runtime string.
  3. A post-generation fact-check validator: a test must prove that if the generated paragraph
     asserts a directionally wrong claim (e.g. claims the model beat naive when the DM verdict says
     otherwise), the report either regenerates or falls back to a template-only report with a
     disclosed "narrative unavailable" note — never silently ships a false claim.
  4. A fixed banned-term test: "signal," "buy," "sell," "profit," "trade," directive
     "recommendation," and no future-price/return claims.
  5. The existing table/DM-verdict rendering is unchanged and remains authoritative; the narrative is
     visibly labeled "AI-generated summary of the results above" in the rendered HTML.
  6. Graceful degradation: if the model call fails/times out, report generation falls back to
     today's existing table-only report, proven by a test (not documented in prose only).

## Design

**Design pattern**: Adapter/Strategy for the model-calling client (this repo's established pattern —
see `DatasetSource` implementations in `ingestion-service`/`validation-service` for the precedent
ADR-0011 names explicitly). The real hosted-API HTTP call is one swappable implementation; tests use
a fake. This also keeps the seam testable without live network access/credentials, which this
environment doesn't have.

**DRY check (grep first)**: `app/renderers/base.py`'s `ReportRenderer.render(run, splits) -> str` is
the only existing rendering contract — do not duplicate it. `app/generation.py`'s
`generate_validation_audit_report` is the one fetch→render→persist sequence both `POST
/reports/generate` and RS-006's subscriber already share (DRY, per its own module docstring) — do not
create a second copy of that function; extend its signature instead. `app/subscriber.py`'s
`handle_event` is the one call site that should opt into narrative generation.

**Files touched** (all new except the two listed as "extend"):
- `services/reporting-service/src/app/narrative/__init__.py` — new package.
- `services/reporting-service/src/app/narrative/client.py` — `NarrativeClient` Protocol/ABC with one
  method, `generate(prompt: str) -> str`, matching the `generate(prompt, context) -> text` shape
  ADR-0011's forward-looking design note describes. `HostedApiNarrativeClient` implements it via
  `httpx` against an OpenAI-compatible HTTPS endpoint (env vars below); raises a narrow
  `NarrativeClientError` on any failure (connection, timeout, non-2xx) — never lets a raw `httpx`
  exception escape this module. A `get_narrative_client()` factory (mirrors
  `app/dependencies/http_client.py`'s existing provider shape) returns `None` if the required env
  vars aren't set, so an unconfigured deployment degrades cleanly rather than erroring.
- `services/reporting-service/src/app/narrative/prompt_template.py` — versioned template
  (`PROMPT_TEMPLATE_VERSION = "v1"` or similar) with a `build_prompt(run, splits) -> str` function.
  Must only reference `run`/`splits` fields already used by `validation_audit.html.jinja` (no new
  data). Docstring states plainly this must never ask the model to invent a claim not derivable from
  the given numbers, and must instruct it to avoid the banned-term list.
- `services/reporting-service/src/app/narrative/fact_check.py` — post-generation validator.
  `contains_banned_term(text: str) -> str | None` (returns the offending term or `None`).
  `is_directionally_consistent(text: str, run, splits) -> bool` — a deterministic, testable heuristic
  checking the generated paragraph's claims about "beat/outperform naive" against the real aggregate
  DM verdict(s); a positive "beat naive" claim when no split's DM verdict says the model was better
  is a contradiction. Document the heuristic's known scope/limits in the module docstring (this is a
  guardrail, not a full NLU fact-checker).
- `services/reporting-service/src/app/narrative/generation.py` — `generate_narrative_html(run,
  splits, client) -> str | None`: builds the prompt, calls the client, runs both fact-check gates
  (regenerate once on failure, then fall back to `None` — `None` means "no narrative", not an
  exception), catches `NarrativeClientError`. Never raises out to its caller.
- **Extend** `services/reporting-service/src/app/renderers/base.py`'s `ReportRenderer.render` and
  `services/reporting-service/src/app/renderers/validation_audit.py`'s
  `ValidationAuditRenderer.render` to accept an optional `narrative_html: str | None = None` keyword
  parameter; when provided, the Jinja template renders it in a clearly-labeled block ("AI-generated
  summary of the results above"), otherwise the template's output is byte-identical to today's.
  `services/reporting-service/src/app/templates/validation_audit.html.jinja` gains that conditional
  block only — no change to the existing table/verdict/disclaimer markup.
- **Extend** `services/reporting-service/src/app/generation.py`'s
  `generate_validation_audit_report` with an optional `narrative_client: NarrativeClient | None =
  None` parameter (default `None` — unchanged behavior for existing callers). When provided, after
  the run/splits are fetched, call `generate_narrative_html` and pass the result into the renderer's
  `narrative_html` argument. `app/routers/report_generation.py` (`POST /reports/generate`) must **not**
  pass a `narrative_client` — confirm this at review.
- **Extend** `services/reporting-service/src/app/subscriber.py`'s `handle_event`/`main` to construct a
  `narrative_client` via `get_narrative_client()` and pass it through to
  `generate_validation_audit_report`. If `get_narrative_client()` returns `None` (unconfigured), the
  call proceeds with `narrative_client=None`, i.e. today's table-only behavior — no error, no crash.

**New env vars** (disclose per constraint, don't wire a real key):
- `NARRATIVE_API_URL` — hosted OpenAI-compatible endpoint base URL.
- `NARRATIVE_API_KEY` — bearer credential for that endpoint.
- `NARRATIVE_API_TIMEOUT_SECONDS` (optional, sensible default e.g. `10`) — bounds the call so a hung
  provider can't hang the subscriber loop.

  live network call), `narrative/prompt_template.py`, `narrative/fact_check.py`

  generation.py` (success path, fact-check-failure → fallback path, client-error → fallback path,

- A banned-term test over the rendered narrative HTML output (not just the raw client response).
