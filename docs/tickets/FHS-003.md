## Analysis

Renders, per split, the same `SplitResultResponse` fields `run_detail`'s existing table already
shows (`model_*`/`naive0_*` `MetricSet` fields, `dm_statistic`/`dm_pvalue`/`dm_verdict`) as an
explicit **side-by-side validation-evidence summary panel**, above the existing per-split table and
RAV-002/003's existing charts — not a replacement for either. No new backend call: `run_detail`
(`services/dashboard-web/src/app/routers/runs.py`) already fetches `splits` via `GET
/runs/{id}/splits`. `dm_verdict`'s real values (confirmed via
`libs/naive_first_engine/src/naive_first_engine/dm_test.py`'s `Verdict` type, same as RAV-003
already confirmed) are `"better"`/`"worse"`/`"no significant difference"`, plus the documented
`dm_statistic`/`dm_pvalue` both-`None` case for a single-test-point split — that `None` case must
render as its own explicit category, never dropped or coerced, mirroring RAV-003's existing
`UNDEFINED_VERDICT_CATEGORY` precedent in `app/charting.py`.

## Implementation acceptance criteria (carried over from the backlog story)

- Renders, per split, `model_mae`/`naive0_mae` (and the run's other already-persisted metrics) next
  to each other, plus `dm_verdict` and `dm_pvalue`, using only `SplitResultResponse` fields already
  fetched by `run_detail` — no new backend call.
- A `dm_verdict` of `"no significant difference"` or a `None` DM value renders as its own explicit
  category — never dropped, never coerced into "better"/"worse" (reuses RAV-003's
  `UNDEFINED_VERDICT_CATEGORY` sentinel, per the DRY check above).

  vocabulary — the words "prediction," "forecast," "signal," "target," and "recommendation" do not
  appear anywhere in the panel or its template, grep-checked in this ticket's own test.
- No green/red bull/bear color pairing (existing `style.css` constraint, carried over unchanged —
  reuses RAV-003's four already-approved category colors).
- Zero-split runs render the existing "no results yet" state, not a broken/empty panel.
