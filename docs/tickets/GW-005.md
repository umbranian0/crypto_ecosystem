# GW-005 — Tenant + API-key provisioning (operator-facing)

**Status: done**

## Analysis
Story: GW-005 (Must), depends on GW-004. Constraining docs: backlog decision 1 (no real pilot client exists — this is a fixture-creation tool, not self-serve signup), backlog AC (raw key returned exactly once, never logged/persisted, implementer's choice between CLI script and gated operator endpoint), sprint-05.md's binding note (SHA-256 hashing).

## Design
Choice made (documented per AC): **CLI script**, not an operator endpoint. Rationale: an operator-only *endpoint* would need its own auth mechanism (who's allowed to call it?) before GW-006 (the service's actual auth mechanism) even exists yet — a chicken-and-egg problem an endpoint doesn't avoid but a local CLI script naturally does (whoever can run a script on the host already has operator-level access, no separate authn to invent for a step this ticket has no charter to design). This also matches "don't add unrequested abstractions" (dev-agent role instruction) — an endpoint is more surface than the ticket needs. File: `scripts/provision_tenant.py` (new, invoked `python scripts/provision_tenant.py --name "Acme Corp"`, imports `app.dependencies.repositories` providers directly — same pattern as any other script that needs the DI-wired repositories without going through FastAPI's request cycle).

Key generation: `secrets.token_urlsafe(32)` (stdlib `secrets`, cryptographically secure, high-entropy — the exact property sprint-05.md's binding note relies on to justify SHA-256 over a slow KDF). Hashing: `hashlib.sha256(raw_key.encode()).hexdigest()` — the sprint's binding, non-negotiable choice; store only the hex digest in `ApiKeyRepository.create_key`. Printed to stdout exactly once at creation, never written to any log statement, any file, or `key_hash`'s own column.

DRY check: grep `src/app/` and `scripts/` (empty) before writing — reuses GW-004's repository providers (`get_tenant_repository`, `get_api_key_repository` from `dependencies/repositories.py`) rather than opening a second raw DB connection.

## Implementation acceptance criteria
- [x] `scripts/provision_tenant.py` creates a `tenants` row (via `TenantRepository.create_tenant`) and one `api_keys` row (via `ApiKeyRepository.create_key`) for it, prints the raw key to stdout exactly once.
- [x] Raw key generated via `secrets.token_urlsafe(32)` or equivalent stdlib CSPRNG; hashed via `hashlib.sha256(...).hexdigest()` before being passed to `create_key`.
- [x] No `print`/`log`/file-write statement anywhere in the script (or anywhere it calls into) contains the raw key except the single, explicit "here is your key, shown once" stdout line.
- [x] Script usage and its operator/test-fixture-only nature (not a public sign-up flow) documented in `services/gateway-api/README.md`.
