# UAT-010 — Hour-based buckets on `/runs/horizon-summary`

**Module**: `services/dashboard-web`. **Depends on**: none — confirmed at ticket-breakdown time (below)
to have no file overlap with Track B.

## Analysis
Story: `docs/product/backlog-uat-findings.md` UAT-010. **Tech Lead verification (per sprint-39.md's
explicit flag)**: `/runs/horizon-summary` is rendered by its own dedicated template,
`services/dashboard-web/src/app/templates/horizon_summary.html` (confirmed via grep — distinct file from
`_forecast_horizon_summary_panel.html`, which is FHS-003's per-run panel embedded in `run_detail.html`
and is what UAT-004/UAT-013 touch). **No re-sequencing needed** — this story is safe to run fully in
parallel with Track B; sprint-39.md's conditional re-sequencing does not apply.
ADR-0007 stays authoritative for the day-based buckets — additive only.

## Design
Pattern: none new. Files touched:
- `services/dashboard-web/src/app/routers/runs.py` — `runs_horizon_summary`: new
  `HORIZON_SUMMARY_HOUR_OPTIONS = (1, 6, 24)` alongside the existing `HORIZON_SUMMARY_DAY_OPTIONS`; a
  new `unit` query param (`"days"`/`"hours"`, default `"days"` for backward compatibility) selects which
  option set + mapping applies. Hour buckets map directly to `horizon` (no `_horizon_for_days` conversion
  — ADR-0007 finding (a), already the dataset's native unit).
- `horizon_summary.html` — selector UI gains the three hour-based options alongside the existing
  7/15/30-day ones.
**DRY check note**: reuses the exact same `matching_runs = [run for run in all_runs if run.horizon == horizon and run.status == "completed"]`
filtering line already in `runs_horizon_summary` — only the bucket-to-`horizon` mapping table changes per
selected unit, not a second filtering implementation.
