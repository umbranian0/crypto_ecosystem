# INF-006 — Persistent volumes for Postgres and Redis

Status: **done**
Backlog: docs/product/backlog-infra.md, INF-006 [Must]
Sprint: docs/sprints/sprint-06.md, Phase 3
Depends on: INF-001, INF-002

## Analysis

INF-001/INF-002 already declare named volumes as part of their own AC (parity requirement with
SQLite's durability). This ticket's job is to confirm the round-trip explicitly and document the
Redis persistence choice (appendonly vs RDB), which INF-001/002 did not yet nail down.

## Design

- Confirm/finalize named Docker volumes for `postgres` (data dir, already declared in INF-001)
  and `redis` (declared here if not already in INF-002; enable `appendonly yes` for Redis so
  Streams data written by VS-014 survives a restart — a deliberate choice, documented rather than
  left to the image default).
- Round-trip test: write data (e.g. insert a test row via `psql`, or `redis-cli SET`), `docker
  compose down` (no `-v`), `docker compose up`, confirm data still present.

- [x] Named volume for Redis, with `appendonly yes` (or documented RDB snapshot policy) enabled so

## Outcome

Added `redis-data` named volume (mounted at `/data`) and `command: redis-server --appendonly yes`
to the `redis` service in `infra/docker-compose.yml`, declared alongside the existing
`postgres-data` volume. No other service blocks were touched.

Performed a real round-trip test:
1. `docker exec naive-first-postgres psql -U naive_first -d naive_first -c "CREATE TABLE IF NOT EXISTS inf006_probe(x int); INSERT INTO inf006_probe VALUES (1);"` → `CREATE TABLE` / `INSERT 0 1`
2. `docker exec naive-first-redis redis-cli SET inf006_probe hello` → `OK`
3. `docker exec naive-first-redis redis-cli BGSAVE` (force AOF/RDB flush)
4. `docker compose -f infra/docker-compose.yml down` (no `-v`) → containers stopped/removed, network removed, volumes untouched
5. `docker compose -f infra/docker-compose.yml up -d postgres redis` → both containers recreated and became healthy
6. `docker exec naive-first-postgres psql -U naive_first -d naive_first -c "SELECT * FROM inf006_probe;"` → row `x=1` still present
7. `docker exec naive-first-redis redis-cli GET inf006_probe` → `hello` still present
8. Verified `appendonly` config on the running container: `docker exec naive-first-redis redis-cli CONFIG GET appendonly` → `yes`
9. Cleaned up: dropped `inf006_probe` table, deleted `inf006_probe` key. Containers left running.

Documented the persistence choice in `infra/README.md` under a new "Persistence (INF-006)" section
(additive — no existing sections restructured).
