# INF-004 — gateway-api wired into Docker Compose

Status: **done**
Backlog: docs/product/backlog-infra.md, INF-004 [Must]
Sprint: docs/sprints/sprint-06.md, Phase 2
Depends on: INF-001, INF-003

## Analysis

Same shape as INF-003, for `gateway-api`, plus this is the story that proves the two real
services talk to each other inside the Compose network.

## Design

- `services/gateway-api/Dockerfile`: builds per existing `pyproject.toml`, starts the FastAPI app.
- `infra/docker-compose.yml` gains a `gateway-api` entry: `build: ../services/gateway-api`,
  started after `postgres`. `VALIDATION_SERVICE_URL=http://validation-service:8000` (internal
  Compose hostname — gateway-api's README already documents this env var with a `localhost`
  default for non-Compose dev). `DATABASE_URL` passed through the same pattern as INF-003,
  targeting the `identity` schema (schema-targeting itself is GW-012's job, this ticket just
  wires the env var through).
- No change to any file under `services/gateway-api/src/`.

## Outcome

Implemented per Design section, no deviations.

- `services/gateway-api/Dockerfile` added: same shape as `validation-service`'s Dockerfile
  (INF-003) -- `python:3.11-slim`, `uv sync --frozen --no-dev`, `uvicorn app.main:app` on port
  8000 -- adjusted for gateway-api depending only on `naive_first_common` (no
  `naive_first_engine` copy step). Also copies `scripts/` into the image so
  `scripts/provision_tenant.py` (GW-005) is runnable inside the running container via `docker
  compose exec`, which the smoke test below needed.
- `infra/docker-compose.yml` gained a `gateway-api` entry: `build.context:
  ../services/gateway-api` with `additional_contexts: {libs: ../libs}`, host port `8000`
  (`GATEWAY_API_PORT`, default `8000` -- `validation-service` already has `8001`), `depends_on:
  postgres: condition: service_healthy`. `VALIDATION_SERVICE_URL` defaults to
  `http://validation-service:8000` (internal Compose hostname); `DATABASE_URL` defaults to the
  same Postgres instance targeting the `identity` schema's parent database, wired through but not
  yet consumed by the app (GW-012's job), mirroring INF-003's precedent for `validation-service`.
  `validation-service` was deliberately *not* added as a `depends_on` of `gateway-api`: GW-009's
  existing 502/504 handling already covers it being unreachable, so no hard startup-ordering
  dependency is needed between the two application services.
- `infra/.env.example` and `infra/README.md` updated additively (new `gateway-api` env vars /
  section appended after the existing `validation-service` section, nothing existing removed or
  restructured).
- Zero files under `services/gateway-api/src/` touched by this work -- confirmed via `git status
  --porcelain -- services/gateway-api/src` before and after: the three files it shows modified
  (`dependencies/repositories.py`, `repositories/sqlite_repository.py`, `routers/runs.py`) were
  already modified/uncommitted before this ticket started (pre-existing in-progress ARCH-ticket
  work per this session's brief), not touched by this ticket's changes.
