## Analysis

Covers TRUST-005's reporting-service AC. Confirmed directly against
`validation_audit.html.jinja` (read in full, current state after `TRUST-001-02` lands): section 4
("Verdict") already computes `{% set better_count = ... %}` and already has an
`{% if better_count == 0 %}` branch (the "Overall" paragraph) whose current text is:

```jinja

```

This story is a pure, contained one-sentence template insertion inside this already-existing

## Design

**Pattern**: none of Strategy/Repository/Adapter/Factory/Observer applies — a one-line Jinja
template addition.

**Files touched** (scoped to `services/reporting-service` only):
- `services/reporting-service/src/app/renderers/validation_audit.py` — add a constant next to
  `TRUST-001-02`'s `METHODOLOGY_FACTS`, **textually identical (byte-for-byte) to `TRUST-005-01`'s
  dashboard-web sentence**:

  ```python
  NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE = (
      "Under rigorous, leakage-free validation, most models -- including sophisticated ones -- "
      "do not beat a strong naive baseline in a stable way; this platform's own published "
      "research found the same pattern, so this outcome is common and not evidence of a broken "
      "evaluation."
  )
  ```

  Pass it into the render context: `template.render(..., not_beating_naive_note=NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE)`.
- `services/reporting-service/src/app/templates/validation_audit.html.jinja` — inside the existing
  `{% if better_count == 0 %}` branch of section 4 (today's line 143–144), append one sentence
  after the existing, unchanged text:

  ```jinja
  {% if better_count == 0 %}
  the model did not beat naive on any split evaluated in this run. {{ not_beating_naive_note }}
  {% elif ...
  ```

  The existing "the model did not beat naive on any split evaluated in this run." sentence is not
  reworded, reordered, or removed — the new sentence is strictly additive, appended after it.

**DRY check** (performed before writing this ticket): `better_count`/the `{% if better_count == 0
%}` branch already exist and are computed exactly once, in section 4 — no second "is this a
zero-better-count run" check exists anywhere else in this template to duplicate or diverge from.

## Implementation acceptance criteria

- A run whose `better_count == 0` across its splits renders the existing "the model did not beat
  naive on any split evaluated in this run." sentence **unchanged**, immediately followed by
  `not_beating_naive_note` verbatim.
- A run whose `better_count > 0` (either "beat naive on every split" or "mixed") renders
  **byte-identical** output to today — the new sentence appears in no other branch of section 4's
  "Overall" paragraph.
- Positioning check: the added sentence never implies any model *should* beat naive, only that not
  beating it is expected and valid.

## Test acceptance criteria

- New test asserting a rendered report for a run with all-`"worse"`/all-`"no significant
  difference"` splits (`better_count == 0`) contains both the existing "did not beat naive on any
  split" sentence **and** `NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE` verbatim, in that order.
- New test asserting a rendered report for a run with `better_count > 0` does **not** contain
  `NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE` anywhere (proves the sentence is scoped to the
  `better_count == 0` branch only, not leaking into the "beat naive on every split"/"mixed"
  branches).
- Same-text test: `test_not_beating_naive_sentence_matches_shared_wording` asserts
  `NOT_BEATING_NAIVE_IS_EXPECTED_SENTENCE == (<the literal string above, hardcoded in this test
  file>)` — exact match, mirrors `TRUST-001-02`'s same-text-test mechanism. QA will independently
  verify this fails if this service's copy drifts from dashboard-web's.
- Full existing `services/reporting-service` suite still passes, including any existing test that
  asserts on section 4's exact "Overall" paragraph text for the `better_count == 0` case (update
  its literal string to include the appended sentence if such a test exists; do not leave it
  silently broken).
