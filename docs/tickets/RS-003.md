## Analysis

Covers backlog RS-003 in full: a Factory (`get_report_renderer(kind)`) with one real
implementation, `ValidationAuditRenderer`, turning a validation-service runs status + per-split
metrics + DM verdicts into a durable HTML report. Read
`.claude/skills/naive-first-audit/SKILL.md` directly before writing the template -- it defines the
report structure (Scope / Leakage check / Results table / Verdict / Disclaimer / Recommendations)
this renderer reproduces programmatically. Ties back to CLAUDE.md's core positioning constraint and
da-tese-ao-produto.md section 1.2/1.3's non-negotiable protocol: no recomputation/reinterpretation
of `dm_statistic`/`dm_pvalue`/`dm_verdict` (NFE-012's Harvey correction is already applied
upstream), no implication of trading signal/price prediction anywhere.

## Design

- **Pattern**: Factory (implementation-plan.md section 7, named explicitly for this service) --
  keeps `generate_report()` callers agnostic to which template renders; a future second report kind
  (certification seal, RS-105/Won't this backlog) becomes one new class, not a rewrite.
- Files touched (disjoint from RS-002's `repositories/`+`models.py`+`migrations/`):
  `src/app/renderers/base.py` (new), `src/app/renderers/factory.py` (new),
  `src/app/renderers/validation_audit.py` (new), `src/app/templates/validation_audit.html.jinja`
  (new), `tests/test_renderers.py` (new).
- **DRY check note**: grep `services/dashboard-web/src/app/templates/run_detail.html` and
  `services/dashboard-web/src/app/routers/runs.py` (DASH-004) before writing -- reuse the exact
  same field list (`id`/`status`/`dataset_id`/`horizon`/`purge_gap_hours`/`created_at`/
  `completed_at`/`failure_reason` for the run; boundaries + both baselines' full metric sets +
  `dm_statistic`/`dm_pvalue`/`dm_verdict` for each split) rather than inventing a second,
  independently-derived field list. Import `RunDetailResponse`/`SplitResultResponse` from
  `naive_first_common.contracts` (ARCH-003) -- no local redefinition of those fields, matching
  `dashboard-web`'s own DRY precedent for reusing the same shared contracts.
- `ReportRenderer` interface (`base.py`): `render(run: RunDetailResponse, splits:
  list[SplitResultResponse]) -> str`.
- `get_report_renderer(kind: str) -> ReportRenderer` (`factory.py`): returns
  `ValidationAuditRenderer()` for `kind == "validation_audit"`, raises a typed error
  (`UnknownReportKindError` or similar) for anything else -- no silent fallback.
- `ValidationAuditRenderer` renders via Jinja2 (`src/app/templates/validation_audit.html.jinja`),
  matching the skill's report structure: Scope, Leakage-check-adjacent framing (this renderer does
  not itself re-derive a leakage checklist -- it states what protocol parameters were used,
  `purge_gap_hours` etc., verbatim from the run, since re-deriving pass/fail leakage findings is
  outside this service's bounded context per "Does not own"), Results table (per split: both
  baselines' metrics + DM verdict), Verdict section stating plainly whether the model beat naive
  (per split and overall), and the mandatory Statistical-accuracy-vs-economic-value disclaimer
  (skill section 5, verbatim or near-verbatim).
- `status != "completed"` runs (e.g. `"failed"`, `"running"`) render a status-only report (no
  fabricated metrics table) -- mirrors DASH-004's "running-with-no-splits" handling.

## Outcome

Implemented exactly as scoped in Design, no scope creep:

- `src/app/renderers/base.py` (new) -- `ReportRenderer` ABC, `render(run: RunDetailResponse,
  splits: list[SplitResultResponse]) -> str`, importing both models from
  `naive_first_common.contracts`, no local field redefinition.
- `src/app/renderers/factory.py` (new) -- `get_report_renderer(kind: str) -> ReportRenderer`,
  returns `ValidationAuditRenderer()` for `"validation_audit"`, raises `UnknownReportKindError`
  (a `ValueError` subclass) for anything else.
- `src/app/renderers/validation_audit.py` (new) -- `ValidationAuditRenderer`, loads and renders
  `templates/validation_audit.html.jinja` via a module-level Jinja2 `Environment`
  (`FileSystemLoader` + `select_autoescape`), passing `run`/`splits` straight through.
- `src/app/templates/validation_audit.html.jinja` (new) -- Scope table (all `RunDetailResponse`
  fields), a status-only branch for `run.status != "completed"` (no fabricated table), Leakage-
  protocol-parameters section (states `horizon`/`purge_gap_hours` verbatim, explicitly does not
  re-derive a leakage pass/fail checklist per "Does not own"), Results table (every
  `model_*`/`naive0_*`/`dm_*` field rendered unmodified), Verdict section (per-split plain-language
  statement keyed only off the literal `dm_verdict` string -- "better" -> beat naive, "worse" ->
  "the model did not beat naive on this split", "no significant difference" -> stated as such; an
  overall statement using only counts of those same three literal strings, never a re-derived
  threshold on `dm_statistic`/`dm_pvalue`), the mandatory disclaimer paragraph (single unwrapped
  line, near-verbatim from skill section 5), and a Recommendations section (only rendered when
  `status == "completed"`).
- `tests/test_renderers.py` (new) -- 7 tests: Factory returns the renderer for `"validation_audit"`
  and raises `UnknownReportKindError` for an unknown kind; a completed run with mixed
  better/worse/no-significant-difference verdicts renders the table, per-verdict text, and the
  disclaimer; an all-"worse" run renders literal "did not beat naive" text plus the correct B/W
  count; a `"failed"` run (with `failure_reason`) and a `"running"` run (both zero splits) each
  render a status-only report with no results table and no exception, disclaimer still present.
- `services/reporting-service/README.md` -- Design notes section updated: documents the Factory,
  confirms `"validation_audit"` is the only real kind shipped this backlog, and lists the concrete
  file paths.
