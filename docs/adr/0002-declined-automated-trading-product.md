# We declined to build an automated trading product, even paper-traded, even as an MVP

A request came in to build an automated trading "robo" — buy/sell automation against a real exchange (Binance, crypto.com), risk-tiered users, "win in return" framing, with an explicit intent to switch from fictional to real trading later. This was declined outright, not narrowed or deferred, because building it — even paper-traded first — means designing user stories, risk tiers, and automation around a premise this platform's own research has already falsified: no model (OLS, Random Forest, ARIMA, LSTM) beats Naive0 in a stable, statistically significant way at any horizon, and best directional accuracy observed is 52.51%, barely above chance. CLAUDE.md's positioning rule ("never imply the system predicts prices or generates trading signals") exists precisely to prevent this category of product.

**Considered options**: (a) build it as requested; (b) build a narrower "MVP" version with fewer risk tiers; (c) decline the automated-trading premise entirely but offer a research-only backtest/simulation extension of `economic-service`'s existing gated posture. We chose (c). Option (b) was rejected because the harm this rule guards against — real people losing real money on a signal proven not to work — doesn't scale down with fewer features; a smaller robo is still a robo. Option (c) preserves the legitimate underlying interest (exploring cost/slippage modeling) while keeping every hard constraint `economic-service` already enforces: no real exchange integration ever, no automated/recurring execution, no risk-tiering or "invest and win" framing, and the backtest computation stays behind `ECON-005`'s existing eligibility gate (so it's equally inert today, for the same reason).

**Consequence for future readers**: if a future request resembles this one — automated decisions affecting real or simulated money against a real venue, framed as something a retail user signs up for — that is the line this repo has already drawn, not a case-by-case negotiation. `docs/product/backlog-economic-service.md`'s backtesting section records the explicit, narrower alternative that was authorized instead, including the Won't items (real exchange integration, automated execution, risk tiering, and — considered and declined — even a mocked-wallet bookkeeping structure) with the reasoning for each.
