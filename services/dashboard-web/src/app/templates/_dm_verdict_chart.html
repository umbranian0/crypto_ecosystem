{# RAV-003: DM-test verdict-by-split chart, server-rendered inline SVG per ADR-0006 (docs/adr/0006-dashboard-web-charting-server-rendered-svg.md) -- no client-side charting library, no Python plotting library. `dm_verdict_chart` is `app/charting.py`'s `build_dm_verdict_chart(splits)` output, computed by `run_detail`'s handler (charting.py has no Jinja2 import; this partial is the only place its geometry becomes markup). Each split's `dm_verdict` field is shown verbatim -- no recomputation of the verdict here, the Harvey et al. (1997)-corrected DM test already ran upstream in `naive_first_engine`/`validation-service`. "Better"/"worse" describe this split's own out-of-sample error relative to Naive0 under that test, never "the model recommends" or "predicts." A split whose `dm_statistic`/ `dm_pvalue` are both null (a single-test-point split's genuinely undefined DM statistic) is its own distinct "undefined for this split" category, never dropped or folded into "no significant difference." Colors are four named CSS variables only (`.verdict-bar-better`, `.verdict-bar-worse`, `.verdict-bar-no-sig-diff`, `.verdict-bar-undefined` -- style.css), chosen to be status-neutral and never a green="better"/red="worse" pairing. RAV-005: a second, distinguishable bar group (`dm_verdict_chart.client_bars`) renders below the platform's own verdict bars only when `dm_verdict_chart.has_client_baseline` is true (a run submitted with an optional client-supplied reference baseline, VS-017) -- reuses the same four category colors above (a second set of four bars, not a fifth color), since the categories themselves are identical, just counted separately for the client-supplied baseline. The common, no-client-baseline case renders byte-identical markup to before this ticket. `dm_verdict_chart.client_baseline_disclaimer` (verbatim, never paraphrased) is shown as visible copy adjacent to the chart whenever the series is shown. #}
